## Findings

### C1 — MINOR — the second clause of the ship criterion is not met for `[release.version_files]` — `open`

> *"Every documented key shows one example of its own shape, including the table-valued ones."*

That clause is in the criterion because the sister finding was `forbidden_literals` — a
table-valued key the README documented without ever showing the table. The README's `devkit.toml`
block (`README.md:145-205`) shows an example for every key it lists, including both table-valued
ones in `[tests]` (`budget = { unit = 20, integration = 130 }`, `cases = { … }`) and
`[release.commands]`. It ends:

```toml
[release.version_files]                       # every site `version-sync` reads
```

Header, comment, **no example row**. It is the one table-valued key in the block whose shape a
reader cannot see, and its shape is not obvious — this repo's own `devkit.toml:207-214` is
`"path" = 'regex-with-one-capture-group'`, a path-to-pattern mapping, not a list and not the
`{ k = v }` inline form the neighbouring `[tests]` keys use. Two lines lifted from `devkit.toml`
close it.

### C2 — NIT — a case in no criterion row — `open`

`2b40b0e` adds two functions. The story's proof table names one
(`test_a_gate_name_is_refused_by_namespace_naming_the_target_that_runs_it`);
`test_a_gate_name_refused_by_namespace_is_a_config_error_not_a_finding` is named in no criterion
row. The proof budget said `cases: 2-3` and the commit adds 2 new plus 2 amended, so the budget
holds — this is only the table being one row short of the commit. Same class as F9 of the
`a-milestone-declares-its-version` review, and raised for the same reason: §6's ordering is what
the table encodes.

### C3 — NIT — case sensitivity is correct and unstated — `open`

`Budget` passes. That is right — make targets are case-sensitive, so `Budget` genuinely is not the
`budget` gate — but the docstring's claim is an absolute ("exact-match, never a substring") and
SDLC §5 asks for hostile input against every such claim. The substring half has a case
(`budget-check`); the case half has none, and a future normalisation would silently start refusing
a legal target. One `parametrize` row on the existing case.
