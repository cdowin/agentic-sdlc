### Criterion 3 — and the `--force` question

The brief asks whether a `--force` on a checks-only belt can still print as recorded. It cannot —
the flag is refused at the parser, before any check runs:

```
adopt 0.2.0 --force        agentic-sdlc: adopt writes nothing, so there is nothing to force
                           — it is checks only                                     exit 2
```

Exit 2, not 1: usage, which is right — `--force` on `adopt` is a command that does not exist, not a
belt that failed. And the three belts that DO write still refuse, on the same consumer with the same
empty roadmap:

```
release 0.2.0              agentic-sdlc: release 0.2.0: no milestone directory
                           pm/roadmap/0.2.0-* — refused, and nothing was written     exit 1
close feature 0.2.0/thing  … close feature 0.2.0/thing: no milestone directory
                           pm/roadmap/0.2.0-* — refused, and nothing was written     exit 1
close story 0.2.0/thing/01-x  … same shape                                           exit 1
```

The regression guard is real: the entry condition was removed from exactly the belt that writes
nothing and from nowhere else.
