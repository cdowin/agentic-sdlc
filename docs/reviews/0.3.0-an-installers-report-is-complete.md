## Findings

### I1 — MAJOR — a DEFECT refuses the whole command and heads nothing — `open`

Measured twice on a consumer where `tools/dev/gdk_gate.sh` was byte-current:

```
Makefile.devkit is a DIRECTORY           exit 1   [install] lines: 0
tools/dev unwritable (chmod 555)         exit 1   [install] lines: 0
```

`main()`'s defect branch prints `_defect_refusal` to stderr and returns 1 **before** the report
loop runs, so neither the defective destination nor the healthy ones get a line. The criterion is
"whatever its disposition — added, modified, already current"; the brief's fourth disposition is
"not installed", and this is it. A consumer summarising with the grep the module's own docstring
names (`grep '^[install]'` — `install.py:13`, `:143`) gets an empty summary from the run that
failed, which reads exactly like a run that did nothing.

The named proof does not cover it: `test_a_defect_refuses_the_whole_command_and_writes_no_addition`
asserts on the disk and the refusal text and never calls `one_each`, the helper every other
disposition's case uses. `one_each` appears in `test_the_verb_writes_its_files_and_a_second_run_is_a_no_op`
and `test_a_collision_on_a_LATER_entry_withholds_that_file_and_nothing_else`; the defect case is
the one that omits it.

### I2 — MAJOR — the sixth installer is outside the feature — `open`

CLAUDE.md's self-hosting list names six installers; `pm install-skills` is the sixth, and
`install.PLANS` holds five. Measured on a fresh consumer:

```
pm install-skills                  [pm] installed .claude/rules/pm-execution.md
                                   [pm] installed .claude/skills/pm-operations/SKILL.md
  grep -c '^\[install\]'           0            <- both files invisible to the documented summary

pm install-skills --diff           [install] … already current   x2      (correct: print_diff is shared)

SKILL.md replaced with foreign content, real run:
  [pm] REFUSED — .claude/skills/pm-operations/SKILL.md exists and differs …   exit 1
  per-file lines printed: 1 of 2   <- pm-execution.md, which was already current, gets none
```

Three separate gaps, all of them the silence this feature exists to remove:

1. the real-run prefix is `[pm]`, not `REPORT_PREFIX`, so the grep the feature is built around
   returns 0 for this verb;
2. `skills.py:326-328` raises `Refused` on any collision **before** the report loop, so there is no
   `withheld` disposition at all and the non-colliding file is dropped — the exact defect
   `test_a_collision_on_a_LATER_entry_withholds_that_file_and_nothing_else` fixed for the other
   five;
3. no `_report_retirements` call, so criteria 2 and 3 do not reach it.

### I3 — MINOR — `skills.py`'s report loop drops every entry after a failed write — `open`

```python
for kind, target, body in actions:
    if kind == 'current':            _ok(f'{cfg.rel(target)} already current')
    elif cfg.rel(target) in landed:  _ok(f'installed {cfg.rel(target)}')
    else:                            break
```

The `break` is `skills.py:349`. `install.py` added `NOT_REACHED` for precisely this case, with a comment — *"Named, not dropped:
the entries a mid-plan failure never reached are the ones an operator has to re-run for."* The
sixth installer still `break`s. I could not force a mid-plan `apply` failure from the CLI (the
pre-plan defect scan catches every shape I could construct), so this one is read off the source
rather than measured; the reachable half of it is I2's collision path, which I did measure.

### I4 — MINOR — `--diff` calls a directory an addition, at exit 0 — `open`

```
Makefile.devkit is a directory        --diff: [install] Makefile.devkit does not exist —
                                              the whole file is an addition        exit 0
                                      real:   agentic-sdlc install-gates: Makefile.devkit
                                              is a directory                       exit 1
tools/dev unwritable                  --diff: [install] tools/dev/gdk_gate.sh does not exist —
                                              the whole file is an addition        exit 0
```

`print_diff` branches on `target.is_file()` and never calls `destination_defect`, which the real
run calls first. `--diff` is the flag whose whole job is "what would change", and here it asserts
a fact about the tree that is false and promises a write that will be refused. Rule 4's first
shape, on the surface a consumer reads before deciding.

### I5 — MINOR — an undecodable destination is reported as one that "differs" — `open`

`read_destination` returns `(None, '')` for a `UnicodeDecodeError` — text `None`, defect the
**empty string**. `main()` does `existing, unreadable = read_destination(target)` and branches on
`if unreadable:`, so that branch is dead for the decode case and the file falls through to the
collision list. Measured with `\x00\xff\xfe` at `Makefile.devkit`:

```
--diff     [install] Makefile.devkit is not text this can diff — --force would replace it whole
real run   [install] Makefile.devkit withheld — it exists and differs from what this would write
```

The `UNDECODABLE` disposition exists in the closed set and in `--diff`, and has no counterpart in
a real run: the run says the file *differs from* content it never decoded. Same class as F3 of the
`a-milestone-declares-its-version` review, one surface over.

### I6 — MINOR — the story record's close commit is wrong — `open`

`## Close` says `done: 1285784`. `git log --oneline 46f602e..HEAD -- src/agentic_sdlc/repo/install.py`
returns `48bf6d5` and nothing else. `1285784` is `the-plan-and-the-tree-agree`'s and touches no
installer file. The record's verification paragraph — "verified end-to-end by the orchestrator …
`install-gates --diff` headers both owned files" — is true, and I reproduced it; the commit
reference under it is not.

### Observation, not a finding

`PIN_FILE` is hard-coded to `'Makefile'` while `[adopt] pin_file` can move the pin. The docstring
says so and calls the consequence widening, and it is: a moved pin reads as no pin, and
`_span_phrase` then reports *"at or before v0.2.0 — this repo pins no readable DEVKIT_VERSION, so
the whole record is reported"*. Wrong in the safe direction, deliberately, and documented.
