### P1 — MAJOR — the ladder is the ship criterion and nothing gates it — `open`

Planted in `mirror/`, a copy of `src/` + `tests/`, after proving the copy is what runs (breaking
the asserted string `wrote the flow into` fails


The whole ladder can be removed and every test in every module that could plausibly hold it is
green. Grepped for the literals — `The flow this project now declares`, `never held`,
`A state you declare`, `against the tree it has`, `this tree uses` — and the suite contains none of
them; the single hit is a **comment** at `tests/test_pm_gate.py:1861`, in a `U1` case.

The story's own proof table is honest about this: criteria 1 and 2 carry `—` for their tier and
"measured on a scratch tree" for their case. SDLC §6 asks for a named case per criterion, and this
is the criterion the feature is named after — the sentence the adopting agent is supposed to read
at the moment of adoption. `U1` is the durable half and it is well covered; the half that fires
once, at the moment that matters, is the half with nothing holding it.

Cheapest fix in §6's own ordering: `test_init_stands_up_a_usable_tree_from_nothing` already runs
`init` on a tree with grains and captures `out`. Two assertions in that existing case — the
per-kind line for a kind in use, and `bug` — would close criteria 1, 2 and P3 together, without a
new function.

### P2 — MINOR — `D7` is not in `RETIRED_CHECKS`, and the code says it should be — `open`

`model.py:134`, written by this feature:

> *"`D7` was a real rule that RETIRED, and reusing a retired id would silently enable a different
> rule for any consumer whose config still names it, which is worse than the exit 2 they get today."*

The reasoning for taking a new letter is right. But `RETIRED_CHECKS` — whose own comment is *"A
rule id that WAS shipped and is not any more. Reported by name, never as 'unknown': a consumer
whose config still lists it is told where the rule went, rather than being silently ungated by a
typo-shaped message"* — carries only `D8`. Measured on a scratch consumer:

```
[pm] checks = [… "D7" …]
[check:pm] ERROR — [pm] checks names unknown rule(s) D7 — known rules are D1 … U1 … R6
exit 2
```

That is the typo-shaped message the table exists to prevent, for an id the same file asserts was
shipped and retired. One row in `RETIRED_CHECKS` fixes it. (Exit 2 is correct either way — nobody
is silently ungated. This is about the sentence, which is the whole point of the table.)

### P3 — MINOR — the ladder does to a grainless kind what `U1` refuses to do — `open`

`bug declares 3; this tree uses 0 / never held: open, fixed, closed` on a tree with no bugs.
Criterion 4 exists because "every declared state unused" means *the tree holds no grain of that
kind*, a different fact — and `_unused_states` skips it deliberately. `print_ladder` has no such
branch, so the two surfaces disagree, and the consumer meets the misleading one first: at adoption
a fresh tree has no bugs and often no features, so the ladder's most prominent rows are the ones
that mean nothing. One `if not in_use and not any(counts.values())` branch, or a `— no bugs in this
tree yet` suffix, and the two agree.

### P4 — MINOR — `state_usage` walks the whole PM tree once per kind — `open`

```python
for kind in model.FLOW_KINDS:
    counts = model.state_usage(cfg).get(kind)
```

`state_usage` is not cached and walks `milestone_dirs` → `bug_files` → `feature_files` →
`story_files`, reading `field_of` on every grain. Called inside the loop, that is four full walks
of the tree for one opt-in WARN — on this repo, 4 × (4 milestones + 31 features + 57 stories + 9
bugs). Hoisting the call above the loop is one line. Hard rule 10's *"a tier that got slower is a
finding"* is about tests, but the same argument holds for a gate consumers run daily.

### P5 — NIT — `print_ladder` ignores its argument and swallows its error — `open`

`print_ladder(cfg)` never reads `cfg`; it calls `model.reload()`, correctly, and the parameter is
dead. And:

```python
try:
    fresh = model.reload()
except model.ConfigError:
    return
```

A ladder that could not be computed is indistinguishable from one that was — `pm init` would print
`appended the flow to devkit.toml`, no ladder, and exit 0, which is the *reporting a write instead
of a meaning* failure this feature exists to end. I could not reach the branch from the CLI (the
section `install_flow` writes is well-formed and `cmd_init` has already loaded the config once), so
this is a shape objection, not a live defect.
