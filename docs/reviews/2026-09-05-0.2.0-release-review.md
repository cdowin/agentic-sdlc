# 0.2.0 pre-release review — NOT RELEASE-SAFE

Cross-cutting reviewer pass over `29bc4b7..HEAD` (15 commits), branch
`milestone/0.2.0-the-conveyor`, run 2026-09-05. Adversarial, by execution: every claim below
was produced by running the shipped code against a tree built for the purpose, in `tempfile`
scratch repos, through `PYTHONPATH=src python3 -m agentic_sdlc.cli` and
`uv run --python 3.11 --with pytest python -m pytest`. No repo-wide git command was run.

**Five blockers. Three of the five are the shape this package's reviews have caught every
minor bump: a gate that prints PASS over documents it did not measure.** The other two are a
red full gate at HEAD and a fail-open contract that fails open on outcome but not on time.

The conveyor itself — the milestone's headline deliverable — held up under every attack tried.
`pm ready-for tag`, `verdict.parse`, `verify`'s selector, the driver's cache-versus-tree
correction and the `--skip` ledger row are the strongest surfaces in the range, and none of the
findings below is against them.

---

## The blockers

### M1 — `check grain-shape` discards its census on the zero path and asserts a falsehood

`src/agentic_sdlc/repo/checks/grain_shape.py:271-297`. When the walk keeps nothing, `run()`
computes `census` at line 273, never uses it, and prints:

```
[check:grain-shape] PASS — pm/roadmap/ holds no grain document yet, so there is nothing to
measure; `check pm` is the gate that has an opinion about a PM tree being there
```

Measured, in a scratch repo whose `pm/roadmap/` held 12 markdown files with no frontmatter, one
dot-prefixed grain and one archived grain — 14 documents on disk:

```
[check:grain-shape] PASS — pm/roadmap/ holds no grain document yet …
EXIT=0
```

while the walk the gate had already built reads:

```
0 PM document(s), 12 note(s) skipped (no frontmatter — not a grain),
1 hidden (dot-prefixed — skipped, as D13 skips them), 1 path(s) excluded from scope
```

The gate has the disclosure in hand and throws it away, then makes a positive claim about the
tree that is not true. **The module says the opposite of what it does, twice.** Docstring,
lines 71-74: *"a roadmap holding markdown this gate did not measure fails loudly, while a
roadmap holding nothing at all is a fresh `pm init`."* In-branch comment, lines 277-281: *"A
roadmap that holds markdown this walk did not KEEP is a scope that lost files, and that is
rule 4's zero census — it fails … `found` carries both halves, so the two are told apart by
measurement rather than by inference."* Nothing in the code tells them apart; there is one
unconditional PASS.

`tests/test_grain_shape.py:292` and `:320` prove the disclosures render — both on the
NON-empty path, where a grain exists to print a census beside. The empty path is untested for
disclosure, and it is the path that lies.

`grain-shape` is `True` in `KNOWN_GATES`, so this ships to every consumer on the pin bump.

Minimum fix: print `census` in that branch, and FAIL when it carries a narrowing the gate did
not classify away.

### M2 — grains under a symlinked directory are invisible to the walk, and the gate PASSes

`src/agentic_sdlc/repo/checks/grain_shape.py:232`, through `src/agentic_sdlc/core/walk.py:243`
(`path.rglob(pattern)`). `Path.rglob` does not descend a symlinked directory, so such a subtree
lands in neither `Walk.kept` nor `Walk.skipped` — it is not a narrowing that went undisclosed,
it is a narrowing the disclosure mechanism cannot see.

Measured: `pm/roadmap/0.1.0` a symlink to a directory holding a 900-line `milestone.md` and a
900-line story, both well over their caps:

```
[check:grain-shape] PASS — pm/roadmap/ holds no grain document yet …
EXIT=0
```

**`check pm` on the same tree sees the milestone and fails.** Two gates over one directory give
contradictory answers about whether documents exist there, and grain-shape's is the false one.
That matters beyond the miss itself: the PASS at M1 is justified in-comment by delegation —
*"`check pm` is the gate that fails a PM tree it cannot find"* — and this is the case where the
delegate answers and grain-shape still prints PASS.

### M3 — an absolute `[pm] roadmap_dir` tracebacks out of `check grain-shape` at exit 1

`src/agentic_sdlc/repo/checks/grain_shape.py:302`, `rel = path.relative_to(root)`. With
`[pm] roadmap_dir = "/var/…/tmp.XXXX"`:

```
ValueError: '/var/…/tmp.0c8sLDDEv9/0.1.0/stories/s1.md' is not in the subpath of
'/private/var/…/tmp.xhIgAxemTn'
EXIT=1
```

Hard rule 6 reserves 1 for findings and 2 for usage/config. A config value produces an uncaught
traceback answering **1**, which a consumer's CI reads as drift. `check pm`, reading the same
key on the same tree, answers cleanly: `[check:pm] FAIL — no milestones found under /tmp/
(wrong [pm] roadmap_dir, or an empty tree?)`.

The relative form is the second half of the same defect and is a hard rule 8 problem rather than
a rule 6 one — `roadmap_dir = "../tmp.0c8sLDDEv9"` does not crash, it succeeds:

```
  OVER CAP   ../tmp.0c8sLDDEv9/0.1.0/stories/s1.md — 900 body line(s), story cap 200
[check:grain-shape] FAIL — 1 finding(s) across 1 PM document(s) under ../tmp.0c8sLDDEv9/
```

A gate in the stock roster reading a tree outside the checkout and reporting findings about it.
Rule 8: *"No file here … reads a path outside this checkout."*

### M4 — the full gate is RED at HEAD, on a new direct `rglob` in a check module

`src/agentic_sdlc/repo/checks/shell.py:35` — `str(p.relative_to(root)) for p in
sorted(base.rglob('*.sh'))`, introduced by `650dc45`, the last commit in the range.

```
uv run --python 3.11 --with pytest python -m pytest tests/test_boundaries.py -q
E  AssertionError: Lists differ: [] != ['repo/checks/shell.py:35: rglob()']
FAILED tests/test_boundaries.py::OneWalk::test_only_the_walk_module_enumerates
1 failed, 21 passed, 49 subtests
```

Two things, and the second is worse than the red:

1. `make milestone` cannot pass. The close protocol's ordering puts `gate` after this review; the
   tree it will answer for is already failing.
2. `core/walk.py`'s opening paragraph is a list of six defects with one shape — *"a
   `glob`/`rglob`/`iterdir`/`os.walk` returns ONE list, so a filter applied to it produces one
   list too, and the entries it removed have nowhere to go"* — and `test_boundaries.py` exists
   to make that shape unwritable. This helper reintroduces it in the one place it costs most:
   its whole job (per its own docstring, lines 24-27) is to tell a WRONG ROOT from an
   UNCOMMITTED tree *"when the census is already zero"*. `walk.descendants` compares `suffix`
   case-INSENSITIVELY, and says why: `glob('*.md')` never saw `<DOC>.MD`. This one is
   `rglob('*.sh')`, case-sensitive, with nowhere to put what it dropped.

### M5 — `gdk_gate.sh`'s recorder bound is defeated by a `GDK_LEDGER_CMD` that forks

`src/agentic_sdlc/repo/installables/gdk_gate.sh:329` —
`said="$(_gdk_ledger_run "${prefix[@]}" "${argv[@]}" 2>&1)" || rc=$?`.

`_gdk_ledger_run` bounds the recorder with `timeout`, which signals only the direct child. The
command substitution around it blocks until every process holding the inherited pipe exits, so a
recorder that backgrounds anything outlives its own deadline.

Twelve hostile `GDK_LEDGER_CMD` values, `GDK_LEDGER_TIMEOUT=3`, wall clock measured per probe:

| GDK_LEDGER_CMD | elapsed | verdict line | exit |
|---|---|---|---|
| (unset — baseline) | 0 s | `[PROBE] done — full log: …` | 3 |
| `true` / `/usr/bin/true` (returns 0, does nothing) | 0 s | unchanged | 3 |
| stderr forever | 3 s | unchanged, `recorder exited 124` note | 3 |
| stdout forever (`yes`) | 8 s | unchanged, `recorder exited 124` note | 3 |
| a directory | 0 s | unchanged, `exited 126` note | 3 |
| nonexistent binary | 0 s | unchanged, `exited 127` note | 3 |
| unparseable quoting | 0 s | unchanged, `not a command line this shell can parse` | 3 |
| exits 2 / kills its process group | 0 s | unchanged, `exited 2` / `exited 143` | 3 |
| **`sh -c 'sleep 120 & exit 0'`** | **120 s** | unchanged | 3 |
| **`sh -c 'sleep 120 & echo started'`** | **120 s** | unchanged | 3 |

**The verdict line and the exit code never moved — fail-open on OUTCOME is solid, and that half
of the contract is proven.** The bound is not. Lines 287-290 of the same file: *"A broken
recorder that hangs would otherwise hang every gate in a consumer's pre-push hook, which is the
one failure mode worse than a missing row."* A 40× overrun of a 3 s deadline is that failure
mode, on the path of every gate in every consumer, with the stock `GDK_LEDGER_CMD` being a
`uvx` invocation whose subprocess behaviour this package does not control.

## Also judged

- **Hard rule 1 — stdlib only.** Clean. AST walk over every `.py` under `src/`: zero imports
  outside `sys.stdlib_module_names` and `agentic_sdlc`.
- **Hard rule 8 — no consumer named, nothing read outside the checkout, no second repo.** Clean
  for `adopt`: every `subprocess.run` in `conveyor/steps.py` (:260, :280, :314, :614) passes
  `cwd=str(ctx.root)`, and `adopt 1.4.0` on a scratch consumer reached no second tree. The
  `reviewed:` pointer grammar refuses absolute, `~`, `..`, backslash, glob, scheme and symlink
  forms *by shape, before any stat*. **The one violation is M3**, which is `check grain-shape`
  rather than `adopt`.
- **Hard rule 6 — exit codes.** Clean except M3. `release` with no version, `--skip` without
  `--reason`, `--skip` of an unknown step, `pm ready-for tag` with no id, `pm ready-for wombat`,
  `check nosuchgate`, `[checks] all = []`, `[checks] all = "doc"`, `[checks] all` naming an
  unknown gate, and all six `[grain_shape] caps` refusals — every one exits **2**.
- **The deprecation window.** Closed and clean. `pm vocabulary` prints
  `planning ready building reviewing accepted packaging done` for all three grain kinds and
  `open fixed closed` for bugs. `pm milestone todo|wip|blocked|review` each exit **2** naming the
  set; `pm story todo` exits 2. `check pm` prints no NOTE line. `pm set <id> status wip` writes
  (it is a generic field setter, documented as such) and `check pm` D4 reports it as
  `DRIFT … status 'wip' not in (…)` at exit 1 — the documented split, not a hole.
- **`_check_module` (`cli.py`).** No import escape found. `KNOWN_GATES` membership is a literal
  dict checked before the module path is built, so no argv or config string reaches
  `import_module`; a roster entry with a missing module raises `ConfigError` rather than
  returning None. `all_roster()` refuses an unknown name in `[checks] all` at exit 2 and refuses
  an empty list.
- **`pm ready-for tag`.** The strongest surface in the range; nothing got past it. Thirteen
  hostile records — unknown severity, unknown verdict, two-cell row, free-text disposition,
  bare `landed`, unfenced block, empty file, a symlink out of the tree, a traversal pointer, a
  glob pointer, and a clean first block followed by a second block carrying `open` — every one
  BLOCKED at exit 1, each malformed case as `UNVERIFIABLE` naming the line number and the
  offending text. A milestone pointing at no record blocks. Only a genuinely clean parse passes.
- **`do()` never decides its own outcome.** Audited all 21 release and 8 adopt steps. No
  `check()` reads a flag its own `do()` set. `installables-diffed` is the one that reads an
  artifact its `do()` wrote, and it re-derives the census from the tree and compares digests, so
  a file edited after the diff makes the report stale and the step answers no — verified live.
  `push-branch` reads `rev-parse @{u}`; the four `_flip` status steps read the milestone file;
  `gate` and the three adopt gates run a command. The run state is corrected against the tree on
  resume, observed twice (`CORRECTED — the run state said 'tree-clean' was done` on this repo,
  and `'hooks-self-test'` on the scratch consumer).

## Non-blocking findings

- **L1** `tests/test_init_verb.py::test_a_second_run_writes_nothing` fails at HEAD on
  `assert 'wrote' not in done.stdout` — the guidance prose contains "that just wrote".
  Idempotence itself holds (`assert not changed` passes). Cosmetic, but it is a red in the gate.
- **L2** `tests/test_boundaries.py::OneApply::test_only_the_apply_module_writes` failed in the
  full-suite run and passes in isolation — order-dependent. It is the write-side structural
  guard, so a flaky one is worth pinning down rather than re-running.
- **L3** Nothing sets `GDK_GATE_CENSUS` (criterion 5's caveat, above).
- **L4** `pm/roadmap/0.2.0-the-conveyor/milestone.md:20-30` hand-maintains a feature table naming
  8 features; the tree holds 9 feature directories, with `the-inner-levels-are-belts-too` absent
  from the table. `.claude/rules/pm-execution.md` forbids exactly this shape: *"Do not
  hand-maintain … a feature list in a milestone file — that is a second scoreboard and it will
  lie."* It already does.
- **L5** `grain_shape._kind_of` (:167-186) hardcodes `'stories'` and `'bugs'` while its docstring
  claims the kinds come "from `repo/pm/model`'s own names and slots, never a second spelling of
  them". A document under `Stories/` classifies as `note` (cap 250) instead of `story` (cap 200).

## What was NOT verified

- **`make milestone` was never run**, and neither was the interpreter matrix. The full suite was
  run once on 3.11 (`1638 passed, 2 skipped, 676 subtests, 3 failed, 145.81 s`); `PY_MATRIX`,
  `make gates`, `make fuzz` and the seeded harnesses were not exercised on any other interpreter.
- **No `verify --story` run to completion.** The selection was computed and inspected; the seven
  commands it plans were not executed.
- **`install-ci` / `install-agents` / `install-gates` outputs were not diffed** beyond
  `install-sdlc --diff`, and no CI run was observed.
- **The `pr-open` / `ci-green` / `merge` steps were never reached** — the conveyor stops at step
  1 on a dirty tree — so their configured-command paths are read but unproven.
- **M2's blast radius outside grain-shape is unmeasured.** `walk.descendants` is the shared
  enumerator; whether the other gates that use it are equally blind through a symlink was not
  tested, and `walk.named` uses `os.walk`, which has different symlink behaviour.
- **`ready_for_tag` reads only the `reviewed:` pointers**, never a `[pm] review_dir` sweep — a
  documented ruling. A record with open findings that no grain points at is therefore invisible
  to it; `findings-resolved` (step 14) catches such a record by version string, but that is
  after `gate`. Not filed as a finding because it is deliberate and defended in the docstring,
  but it is a bypass an operator can walk into.
- **The tree was live during the review.** `changed()` reported 9 modified paths at one point and
  `git status` 6 at another, so builders were still editing; H2 in the scope audit applies.
  Every finding above was re-derived against a scratch tree or a file whose `git diff HEAD` was
  empty, but the suite numbers are a snapshot.
