reference onto it, and exits 0 (M1). `pm move` is gone from the router but was never added to
`RETIRED_COMMANDS`, so the one verb every consumer's muscle memory still types answers *"unknown

got the entry (M2). Story 01's criteria 3 and 4 say `pm set` refuses a binding that names no grain
or names the wrong kind; it does neither, and the proof row naming "two refusal rows, no write"
names cases that do not exist (M3). And 12.8% of the pm fuzz corpus is still spent driving `pm
move`, which criterion 5 forbids in so many words (M4).

## The three checks the brief asked for

**1. Does any guard read a PATH or an ID's SHAPE rather than the grain?** None left in scope.
`rename.py` never splits an id, never touches `KIND_PREFIX`, never reads a filename suffix; the
one layout question it asks is `model.is_pooled(cfg)` (`:163`), which is a fact about whether a
directory holds documents. `model.kind_of` (`model.py:1373`) goes through `grain_index` and its
docstring pins the rule; `cli.py:1998 _grain_kind` is now a one-line delegate to it with the
"it used to count slashes" history recorded. `cmd_set` and `cmd_rename` resolve every id through
`_grain_file`/`grain_index` — nothing is joined onto a path. Two shape reads survive and neither
bites: `model.id_defect` splits on `/` to reject empty and dot segments, which is a GRAMMAR guard
(and documented as such — it answers a hostile string without reading a document, it derives no
kind); and `model._is_shared_doc` matches a `-decisions.md`/`-handoff.md` filename suffix, which
`documents()` reaches through `pool_walk` — but it is ANDed with "and opens no frontmatter", so a
pooled grain whose slug ends that way is still swept, and a doc with no frontmatter has no ref to
sweep. One shape claim in the PROSE is stale: story 01 criterion 4 says the two kinds "come from
the ids themselves, since an id carries its kind as a prefix" (D4 says it too). The code does not
do that and is right not to; the sentence should be repaired with M3's criteria edit.

**2. Does `pm rename`'s ref-field list cover every field that holds an id?** Yes, and the census
is real rather than a restatement. Two independent tests, and I checked each reads something
outside `REF_FIELDS`. `test_every_template_key_is_swept_or_named_as_not_a_reference` loads the
four SHIPPED templates through `templates.load`, extracts the frontmatter keys, and asserts
`keys - NOT_REFS - REF_FIELDS == set()` behind a `len(keys) > 8` floor so a zero-census cannot pass
(rule 4). It reads 14 real keys. `test_every_id_a_reader_resolves_is_swept` builds its expectation
from `model.ORDER_KEY`, `validate.CAUSED_BY`, `validate._REF_KEYS` and
`{field for _, field in model.BINDS_TO.values()}` — the readers' own constants, not a list. Both
bite: dropping `caught_in`/`fix_milestone` reddens the first, dropping `order` + the bindings
reddens the second. I also ran an independent census over THIS repo's 127 real grains: the
frontmatter keys in `pm/roadmap/**` are the 14 the templates carry plus `labels`, `risk`,
`severity`, `size` and `version`, and none of those five holds a grain id. The root container
`releases.md` carries only `id`, `kind`, `order`, all covered. The residual gap is by design and
worth naming: `NOT_REFS` is hand-maintained, so a NEW template key that IS a ref could be waved
through by adding it there — the test's own comment says that is meant to be a decision, and it is
the honest place for one.

**3. Running the verb against a scratch tree — is `N` the true count?** Yes. Scratch pooled
`tree()` plus one document per ref kind: `pm rename 0.1/alpha ft-alpha` printed
`renamed 0.1/alpha -> ft-alpha in 5 file(s)` and named
`milestones/0.1.md order`, `features/alpha.md id`, `features/beta.md reviewed depends_on
consumed_by`, `stories/s0.md feature`, `bugs/crash.md caused_by`. I snapshotted every file under
`pm/` before and after: exactly those five files' bytes differ, zero files added, zero removed.
The near-misses held — `0.1/alphabet` and `0.1/alpha/s0` were untouched, and `features/alpha.md`'s
`reviewed: docs/reviews/alpha.md` was not mistaken for a ref. Byte fidelity checked separately on
a hand-built CRLF document with a trailing `# keep me` comment on an inline `depends_on` and a
block-style `consumed_by` with interior spacing: every `\r\n`, both comments, the interior spacing
and the body line `body 0.1/alpha in prose` came through unchanged, with only the two ref tokens
moved. The one place the count is honest about the wrong thing is M1.

## Not findings

- **A mixed tree — pools populated AND a leftover nested grain document — is swept only in the
  pools.** Probed: a pooled `tree()` with `pm/roadmap/0.1-demo/features/alpha/stories/legacy.md`
  holding `feature: 0.1/alpha` and `depends_on: ["0.1/alpha"]`; `pm rename` reports 2 files and
  leaves both stale. Not a finding, because nothing else reads that file either — `pm validate`
  exits 0 and `check pm` PASSes saying `1 story/ies`. `pm rename` is consistent with every other
  reader, and `tools/dev/pm_migrate.py` cannot produce the state (one `apply.Plan`, and it STOPS
  on collisions before writing a byte). The invisibility itself belongs to `the-pools-are-the-
  tables` / `check pm`, not here — flagging for the milestone reviewer, not against this feature.
- **`documents()` uses `pool_walk` (kept only) rather than `pool_census`, so the sweep never
  discloses what the walk narrowed away.** The narrowings are dotted names, shared docs and
  `.md` files that open no frontmatter — none can hold a frontmatter ref any reader honours, so
  there is nothing to disclose.
- **`apply(decide=False)` at `cli.py:1193`.** `sweep` already ran `plan.decide()` (`rename.py:187`)
  and `cmd_rename` refuses on its blockers, so the pre-flight is not skipped, only not repeated.
  The TOCTOU window between decide and apply is inherent and the `failed`/`landed` branch names
  exactly what did land.
- **D4's *"`add` must remain exactly `set` plus a list insert"*.** `cmd_add` also resolves both ids
  and refuses off `[pm.contains]`, which `cmd_set` does not. I read that as checks before the
  write rather than a second mechanism — `add` still writes the same one field and one list. The
  decision asks a reviewer to watch this line; it is not over it yet, but M3's repair puts the
  binding refusals permanently on one verb and not the other, which is the thing to state out loud
  when it lands.
- Hard rules 1 (stdlib only) and 2 (boots nothing) hold in `rename.py`: `re`, `dataclasses`,
  `pathlib`, `core.apply`, `repo.pm.model` only.
