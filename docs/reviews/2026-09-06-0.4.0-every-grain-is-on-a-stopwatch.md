number, and no write was added. What does not hold is the ship criterion itself. On the tree this

form, and it is not a hypothetical: it is what the verb prints in this checkout right now.

## Blockers

- **`C1` CRITICAL `src/agentic_sdlc/repo/pm/cli.py:922` + `src/agentic_sdlc/repo/pm/report.py:1198-1200`**
  — both surfaces report **nothing in flight over a tree with eight grains in flight**, and neither
  prints a line saying it could not measure. *Probed:* `pm/roadmap/ledgers/ms-0.4.0.jsonl` holds 52
  `status` rows, every one naming a legacy nested id (`0.4.0/every-grain-is-on-a-stopwatch`), while
  the pooled tree names the same grain `ft-every-grain-is-on-a-stopwatch`; zero pooled-id status
  rows exist anywhere under `pm/roadmap/`. `cli._open_for(cfg, 'ms-0.4.0')` returns 8 entries keyed
  `0.4.0/…`, and `cmd_status` then looks them up by `mid` (`cli.py:910`) and `view.fid`
  (`cli.py:928`) — pooled ids — so every lookup misses and the cell is omitted. `_in_flight_ages`
  filters `gid in kinds` (`report.py:1200`) where `kinds` is tree-derived (`report.py:922`), so all
  52 rows are discarded and the key is `[]`. Observed: `pm status ms-0.4.0` prints eight
  `[building ]` features with no age; `pm ledger report ms-0.4.0 --json` prints `in_flight: []`,
  which `tests/test_pm_ledger_report.py:353-355` defends in a comment as *"an answer"* — here that
  answer is false. The root cause (the migration left `grain:` values on nested ids) belongs to
  `ft-the-pools-are-the-tables`, but the **silence** is this feature's: `spend_data` one function
  above already has the disclosure pattern for exactly this class — a row naming a grain this
  milestone does not hold is counted as `stated_elsewhere` (`report.py:985`) and printed — and
  `_in_flight_ages` did not adopt it. Fix at the cheapest layer: count the status rows whose grain
  is not in `kinds` and emit them as UNMEASURED beside the distribution, and have `pm status` print
  the `-` its own docstring already promises (see `M1`), so a stopwatch that cannot see its tree
  says so instead of reading as a calm zero.

- **`M1` MAJOR `src/agentic_sdlc/repo/pm/cli.py:911-912, 927-929` (docstring `cli.py:854`)** —
  acceptance criterion 2 says the age prints *"`-` where it is `None`"*. It never does. Both prints
  are `+ (f'  open {…}' if <present> else '')`: an unmeasured grain gets **no cell at all**, which
  is indistinguishable from a `done` grain and from a grain the reader simply did not look at. The
  docstring at `cli.py:854` states the opposite — *"A grain with no status row is simply absent here
  and prints `-`"* — so the file itself documents the behaviour AC2 asked for and the code below it
  does not implement. This is what makes `C1` invisible: had `-` shipped, `pm status` on this
  checkout would print `open -` on all eight open features and the id mismatch would have been
  visible on the first run. Rule 11's own shape, in the feature written to satisfy rule 11. Fix:
  print `ledger.human_duration(None)` (`-`) for a grain whose category is not `done`, and keep the
  cell off only for grains that have finished.

- **`M2` MAJOR `src/agentic_sdlc/repo/pm/cli.py:2015-2022`, called at `cli.py:878`** — `_grain_kind`
  decides a grain's kind by **counting slashes**, which is the pre-0.4.0 nested-id shape. *Probed:*
  `_grain_kind('ms-0.4.0') == 'milestone'`, and so does `_grain_kind('ft-every-grain-is-on-a-stopwatch')`,
  `_grain_kind('st-foo')` and `_grain_kind('bug-foo')` — **every pooled id is classified as a
  milestone**, so `open_seconds` asks the milestone vocabulary about a feature, a story and a bug.
  It is invisible in this repo only because `[pm.states.feature]` and `[pm.states.milestone]`
  declare the same `done = ["done", "obe"]` (`devkit.toml:173-186`). It is not invisible for a bug:
  *probed* `model.category_of(cfg, 'milestone', 'closed')` is `None`, so once a `bug-…` status row
  exists, `open_seconds` returns a growing age for a **closed** bug. And for any consumer whose
  feature flow declares a done word its milestone flow does not — feature `done = ["shipped"]`,
  milestone `done = ["released"]` — `pm status` prints `open 47d` next to `[shipped]`. That is a
  write-shaped lie in a read verb: a number that looks legitimate and is not. Fix: resolve the kind
  from the grain's own `kind:` frontmatter (the 0.4.0 identity rule) rather than from the id's
  shape; `_open_for` already holds `cfg` and can ask the tree.

- **`M3` MAJOR `tests/test_pm_ledger_report.py:133, 355`** — **no case anywhere drives a non-empty
  `in_flight`.** The only two references are `SPEND_KEYS` and the exact-JSON case asserting
  `'in_flight': []` over a fixture in which everything is closed. So `report.py:1213-1214`
  (`median_s`, `worst_s`) and `report.py:1075-1078` (the printed line) never execute in the suite —
  acceptance criterion 3, *"`pm ledger report` gains median and worst open-duration per kind"*, is
  proven only to the depth of *the key exists*. Reverting the feature reddens those two asserts, so
  the row is not inert; computing the median wrongly, sorting wrongly, or crashing on the format
  string would all stay green. This is also the story's proof-table row for criteria 2 and 3 — *"one
  case over a fixture with an aged open grain and a closed one"* — and for criterion 3 that case
  does not exist. Fix: one case over the report with a `now=`-pinned aged open grain and a closed
  one, asserting the entry and the rendered line; it is the same fixture `test_pm_ledger.py:523`
  already builds.

- **`M4` MAJOR `tests/support/pm.py:193-218`** — the fixture every proof case for this feature runs
  on is **pooled in layout but keeps slash-shaped ids** (`0.1`, `0.1/alpha`, `0.1/alpha/s0`), by a
  deliberate choice its own comment defends for the migration's sake. The consequence for this
  feature is that `_grain_kind`'s slash-counting works in every test and cannot work in production,
  and that `test_pm_status_prints_the_age_and_nothing_gates_on_it` (`tests/test_pm_ledger.py:523`)
  — the one case standing behind AC2 — asserts `'open '` in the output over an id shape the shipped

## Findings

- **`m5` MINOR `src/agentic_sdlc/repo/pm/report.py:1213`** — `median_s` is `found[len(found) // 2]`,
  the upper of the two middles on an even-length list. With two features in flight at 1h and 3d it
  reports `median 3d, worst 3d`. Two in flight is the ordinary case for this tool, so the word
  `median` is wrong exactly where the report is most often read. Either average the two middles or
  call the field what it is.
- **`m6` MINOR `src/agentic_sdlc/repo/pm/report.py:1075-1078`** — the in-flight lines are appended
  after the `for kind in KIND_ORDER` loop (`report.py:1042`) with the same three-space indent the
  per-table notes use (`report.py:1068`, `report.py:1074`). `KIND_ORDER` ends with `bug`, so
  `2 feature(s) in flight — …` renders directly under the heading `bug (N)` and reads as one of that
  table's notes. AC3 says *"beside the spend table"*; this is beside the wrong one. Unobserved
  because of `C1` — no tree in the suite or in this checkout renders the line at all.
- **`m7` MINOR `src/agentic_sdlc/repo/pm/cli.py:927-929`** — AC2 says *"Column order and the existing
  cells do not move: consumers cut on them."* The new cell is inserted **before** the drift marker,
  not appended: a feature that is both open and drifting prints
  `… 1/2 done  open 3d  <DRIFT: …>` where it printed `… 1/2 done  <DRIFT: …>`, moving an existing
  trailing cell by two whitespace-separated fields. No test asserts `pm status`' drift marker at all
  (`grep -rn 'DRIFT:' tests/*.py` returns one hit, in `test_pm_gate.py:2019`, for the gate), so the
  claim in AC2 is unproven as well as untrue. Rule 6 makes this a minor-bump shape change, which
  0.4.0 is; the CHANGELOG entry does not mention it.
- **`m8` MINOR — `pm --help`** — the capability is named in no surface anyone stands in. `status`'s
  entry is the bare line `status [<milestone>]` with no description at all, and `ledger report`'s
  entry (`cli.py` USAGE, rendered at help lines 202-214) still enumerates the report as *"dispatches,
  tokens, tool calls, wall-clock and seconds in each CATEGORY … per story/feature/bug"* — the
  in-flight distribution is absent from both. Rule 11's read side and its own test: could someone
  hand-roll an open-age table off the ledger, and would anything have stopped them? Today, nothing
  would: the column does not render (`C1`) and the help does not mention it.
- **`n9` NIT `tests/test_pm_ledger.py:487`** — the story's proof table calls its first criterion-1
  row an **amend** of `test_pm_ledger.py`'s `total_seconds` cases. Those cases exist and were not

- **`n10` NIT `src/agentic_sdlc/repo/pm/ledger.py:515`** — one blank line between `total_seconds` and
