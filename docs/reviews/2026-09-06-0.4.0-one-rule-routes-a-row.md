## The four things worth attacking

**Is `_row_ledger_dir` one rule?** Yes as written — the `path is None` branch is the rule's own
second clause, not a second mechanism, and no status is read on either side. What is two is the
*decision* of which branch applies: it lives at the call sites and in `tests/conftest.py`, not in
the function, so D7's "its input is the row" overstates what shipped (W3), and the root address is
spelled five times over (W2).

**Did `only_row` going location-agnostic weaken anything?** Net stronger, and no case was left
uncovered. It used to read one path (`LEDGER_REL`), so every caller implicitly asserted placement;
it now asserts exactly one row *anywhere in the tree*, which catches a stray second write that a
single-path read could not. Eight callers (`:224 :238 :251 :346 :372 :394 :434 :464`) were content
assertions where placement was incidental — they lost a claim nothing needed. Placement is
re-asserted once per write form, deliberately: transcript at `:189` (`ledger_lines(root,
ROOT_LEDGER_REL)`) and `:569`, gate at `:966`, grain-routed at `:540-541` and `:553`. `refuses()`
was widened to the same whole-tree comparison, which closes the hole where a refusal wrote into the
*other* file.

**Is D7 sound?** The core argument is: `gate_row` has no field to bind by, so routing it by the
plan is the path being the schema one level down, and it keeps a refusal path D5 forbids. That
holds, and both rejected alternatives are argued fairly. What it does not admit to is M2: it
enumerates two readers, checks that both take the newest row per gate, and concludes nothing is
lost — but `pm ledger report`'s gate-cost section is a third reader that takes first-vs-last, and
its `runs`/`delta_ms` silently became tree-lifetime numbers under a milestone heading. Its own
escape hatch, `report <mid> --from <tag>`, does not answer the question either. Deleting 0.3.0's
answer three weeks after it shipped is defensible on the milestone's thesis; doing it without
scoping the report that consumed it is the part to land.

**Rule 11.** `pm --help` never names the grainless home (W4) and describes a route no transcript
row can take. The verb does say where it wrote at runtime, `verify --plan` names the file in its
`unknown` message, and `check budget` names it — so the fact is reachable, just not from `--help`.
Nothing here needs a new capability; every fix above is a word, a column, or a call.
