# Review — 0.4.0/telemetry-arrives-with-the-bump

One feature, one story, one commit: `c4685d1` (`feat(0.4.0/telemetry-arrives-with-the-bump): adopt
probes whether this tree records`), read at worktree state `318bac1` on
`milestone/0.4.0-authoring-is-separate-from-binding`. Reviewed cold against
`pm/roadmap/features/ft-telemetry-arrives-with-the-bump.md`, its one story
`st-adopt-probes-whether-this-tree-records` including the Close block, `CLAUDE.md` hard rules
2/4/6/10/11, `SDLC.md` §0, and the sibling record `2026-09-06-0.4.0-the-telemetry-surfaces.md`
(which reviewed `check pm` U2, the same argument one layer over) so nothing already dispositioned
is re-raised. Refs tool: raw `grep` plus direct execution of the courier corpus — this repo ships
no reference-aware search. Structural diff: `docs/sdlc-protocol.md` is generated by
`conveyor/sdlc_doc.py`, so it was read against its renderer rather than as prose.

**Verdict: HOLD.** The feature's thesis is right and its posture is right. What it shipped does
not do the one thing its ship criterion names. `telemetry-live` calls the courier's `--self-test`,
and that self-test is **hermetic**: it builds its own temp git repo and its own stub Makefile and
never reads the tree it was invoked in. So the "probe" measures nothing about the consumer, two of
the three named failure modes are undetectable, and on a consumer whose `pm` target is not
`.PHONY` the belt prints `ok: telemetry-live — telemetry is live: … their self-test passes against
this tree's vehicle` and exits 0 over a tree that records nothing. That is rule 4's first sin with
the lie spelled out in the PASS line. Strip the redundant spawn away — `hooks-self-test`, the step
immediately before it, already replayed that same corpus — and what is left is the settings.json
substring read, which is exactly the inspection AC2 rules out.

## The rule-2 question, answered

**`telemetry-live` is outside rule 2 as written, and it should be — but it is not disclosed, and
the spawn buys nothing.** Three parts:

1. **Outside the letter.** Rule 2 says "nothing starts a build, an import or a cache". This step
   forks `bash` → `python3`, `git init`, and `make` executing a real recipe in a temp repo
   (`cc-ledger-session.sh:124-141`, `:211-215`). A make recipe running is a build starting.
2. **`adopt` was already outside it before this feature.** `hooks-self-test` spawns every hook
   process, `checks-pass` spawns `agentic-sdlc check all`, `runner-targets-resolve` spawns
   `make -n`. The conveyor's whole `_make` / `run_command` / `_run` failure vocabulary exists
   because these belts spawn. `adopt` is the one belt whose job is to run the consumer's tooling,
   and rule 2's "every verb" has not described it for some time. This changeset did not break an
   intact line; it stepped one notch further, being the first adopt step whose child executes a
   recipe rather than dry-running one.
3. **It stays inside rule 2's purpose** — "safe anywhere, any time, in parallel". The recipe runs
   in a `mktemp -d` private to the process and is `rm -rf`'d (`cc-ledger-session.sh:124`, `:219`);
   nothing in the consumer's tree is touched and parallel runs cannot collide. Verified twice:
   `tests/test_conveyor_adopt.py:338` asserts the whole belt leaves the tree byte-identical, and
   my run from `/tmp/telemetry-probe-check` left that directory empty.

**So: acceptable in kind, and the defect is that it is not said out loud** — M1, where the
generated document a consumer reads to learn what `adopt` runs says this step "reads the tree".
The irony is the reviewable part: rule 2's cost is being paid for information the belt already
had one step earlier (B1), so today the honest fix is to delete the spawn, not to document it —
and the *correct* fix, driving the consumer's real `make -s pm`, is a bigger rule-2 step than the
one being taken now and needs the disclosure even more.
