## Blockers

- `M1` MAJOR `src/agentic_sdlc/repo/checks/pm.py:491` — **narrowing `[pm.contains]` silently turns
  off `check pm`'s DANGLING finding at the dropped level.** `_sequence_rows` derives its parents
  from `cfg.contains`, so the key that was introduced to gate one WRITE verb also decides which
  containers the GATE grades, and nothing says which those were. Probe, same tree, one planted
  dangling story entry on `ft-the-order-is-one-mechanism`: with the stock mapping,
  `[check:pm] FAIL — 1 status-drift / integrity violation(s)` naming `DANGLING`; after appending
  `[pm.contains]` `milestone = ["feature", "bug"]` — a narrowing that says nothing about stories —
  the identical tree prints `[check:pm] PASS — no PM-tree drift or integrity problems`. Cardinal
  sin 1, reachable from documented config. It is worse than theoretical because the table REPLACES
  rather than merges: the CHANGELOG's own consumer action (*"a project that files no bugs drops
  `"bug"`"*) written literally as `milestone = ["feature"]` also drops `roadmap` and `feature`, and
  `pm add roadmap <ms>` then refuses `a roadmap holds nothing`. Fix at the cheapest layer (rule
  11): merge the declared table over `DEFAULT_CONTAINS` rather than replacing it, and have
  `_sequence_rows` print the container kinds it graded so a level that stopped being measured is a
  named line.
- `M2` MAJOR `src/agentic_sdlc/repo/pm/validate.py:222` — **V5 has been grading an empty graph.**
  `graph[fid].extend(ref for ref in resolved if ref.count('/') == 1)` picks the feature-shaped refs
  by counting slashes in the ID. This milestone moved identity into frontmatter, so this repo's 44
  feature ids carry zero slashes: measured, `44 features, 0 ids with exactly one "/"`,
  `45 feature depends_on refs, 0 refs entering the V5 graph`. Probe: made
  `ft-binding-is-a-field` and `ft-the-order-is-one-mechanism` depend on each other — a real
  2-cycle — and `check pm` printed `PASS — no PM-tree drift or integrity problems` and
  `pm validate` printed `VALID`, with V5 enabled in `devkit.toml`. Line 209 has the same defect
  half-spelled: `graph[fid] = []` keys on the RAW `id:`, so a quoted one never matches a resolved
  ref. Inherited from `identity-lives-in-frontmatter`, surfaced by this feature's scope. Fix: key
  the graph on `model.unquote(fid)` and select refs by `grain_index()[ref].kind == 'feature'`,
  with a planted-cycle case that fails before it.
- `M3` MAJOR `src/agentic_sdlc/repo/pm/skills.py:288` — **`pm init` still advertises the key this
  feature retired.** `pm init` in a fresh repo prints, verbatim, under *"Declare any schema
  differences in devkit.toml"*: `# story_ordinal_prefix = true # if story FILES are NN-slug.md`.
  A consumer who uncomments the line the onboarding verb handed them gets `check pm` exit 2. The
  retirement swept `RETIRED_KEYS`, the seed, README, guidance and CHANGELOG and missed the one
  surface a new consumer stands in first. Raised to MAJOR rather than MINOR because it ships into
  first-run output and the fix is deleting one line. Fix: delete it, or replace it with the
  `[pm.contains]` row, which is the key that actually belongs in that list now.

  prints `already holds … at position 12 of 12 — nothing was written` at exit 0, and the SHA of
  every file under `pm/` is byte-identical across it.
- **Rule 3, a refusal writes nothing.** `pm add ms-0.4.0 st-order-sequences-every-container` →
  exit 1, `pm/` byte-identical. `test_a_place_that_cannot_be_honoured_refuses_and_writes_nothing`
  and `test_a_pair_off_the_mapping_refuses_naming_both_kinds` both compare whole-tree bytes.

  never does — correct per criterion 5. Neither can be *silently* empty at the top level:
  `checks/pm.py:99-105` FAILs at exit 1 with `no milestones found under <roadmap_dir>/` before any
  of this runs. Below that level it CAN be — `M1` and `N4`.
