## Blockers

- `M1` MAJOR `src/agentic_sdlc/repo/pm/cli.py:98,114,117` — the ship criterion says **every** read
  verb's `--help` names its columns in order; only `list` does. Probed bytes in a scratch tree:
  `pm next` emits `0.3.0<TAB>0.3.0<TAB>building` and its help names the entry and *"the milestone
  that claims it"* — the third cell is never named; `pm roadmap` and bare `pm order` each emit
  `<version><TAB><milestone><TAB><state>` and neither says the rows are tab-separated or names the
  cells as columns. This is the exact defect the feature exists to remove, one verb over. **The
  guard test blocks its own fix**: `tests/test_cli_surface.py:130` asserts `USAGE` splits on
  `columns IN ORDER:` into exactly 3 parts, so naming a third verb's columns reddens it. Fix: three
  help lines plus a parse that walks every occurrence instead of assuming two.
- `M2` MAJOR `src/agentic_sdlc/repo/pm/guidance/pm-operations.md:147-148` (installed copy
  `.claude/skills/pm-operations/SKILL.md:147-148`, `{version}`-templated and otherwise byte-equal)
  — **the second consumer the `agent-worktree.sh` fix missed.** It still states the row as
  ``one tab-separated `<story-id>  <status>  <owner>  <feature-id>` per story`` — a four-column
  roster that is now wrong, in the skill that auto-loads. Its sibling
  `guidance/pm-execution.md:136` names `pm list` with no columns, no `--json`, and — like
  `pm-operations.md` — never mentions `--kind milestone` at all, while `pm-execution.md:143`
  does advertise `pm vocabulary [--json]`. Rule 11's own test fails for the capability this
  feature added: an agent standing in the auto-loaded rule cannot learn that `pm list` speaks
  JSON, lists milestones, or carries a name. Fix: edit the two guidance sources and re-install
  with `--force`; a copy edited in place is the invisible fork `test_install.py` exists to catch.

- `W1` WARNING `src/agentic_sdlc/repo/pm/cli.py:842-849` vs `cli.py:57-59` — the help block this
  commit added to the STORY form claims ``` `-` for an empty cell, so a shell `read` gets a fixed
  count```, and `DASH`'s own comment (`cli.py:855-857`) says *"an empty field is never mistaken for
  a short row"*. Only `owner` and `name` go through `DASH`; `id` and `status` are emitted raw.
  Probed: a story file with neither field listed as `<TAB><TAB>claude<TAB>0.4.0/the-read-verbs-compose<TAB>pm list emits…`
  — two empty leading cells, and `--json` returns `{"id": "", "status": "", …}`. The milestone form
  guards all five. The field count does stay fixed (tabs are literal), so `read` does not misalign;
  what is false is the stated contract. Fix: `or DASH` on both, or drop the clause from the story
  block.
- `W2` WARNING story 01's `## How this is proven` — SDLC §5: `--json` is a new input surface on
  `list` and shipped **no refusal case**. Behaviour is correct, probed: `pm list --json=1` → exit 2
  `unknown flag '--json=1'`; `pm list --` → exit 2 `unknown flag '--'`; `pm list --json --json` →
  exit 0, one payload (idempotent); `pm list --status --json` → exit 2 `--status needs a value`
  (the flag is stripped before `_take_flags`, so it can never be swallowed as a value). The
  precedent is one file away and names the section:
  `tests/test_pm_ledger_report.py:405-411`, a `REFUSALS` table headed `# SDLC § 5's matrix` whose
  third entry is `(('--json=1',), 'unknown flag')` with the comment *"a verb that quietly accepted
  one would be inventing a grammar its own --help does not print"*. `list` already has a refusal
  cluster (`tests/test_pm_verbs.py:486,514`); the fix is one tuple in it.
- `W3` WARNING `src/agentic_sdlc/repo/pm/cli.py:877` — *"Here they cannot"* (the `_emit_rows`
  docstring) and *"cannot diverge"* (the commit message and the story close) are guaranteed by a
  test, not by the code. `dict(zip(columns, row))` truncates silently. Probed directly:
  `_emit_rows('milestone', [('a','b','c','d','e','SIXTH')], False)` prints six tab cells,
  `as_json=True` prints five keys and drops `SIXTH`. The claim is honest in effect — I patched
  `cmd_list` to append a sixth cell and `test_json_carries_exactly_the_fields_the_columns_carry`
  went red — but the guard is the case, not the construction. SDLC §5's second bullet asks hostile
  input against every "cannot". Fix: `zip(columns, row, strict=True)`, one word, and the docstring
  becomes true as written.
- `W4` WARNING `CHANGELOG.md:77-84` — the warning is otherwise the best kind (it names the shape,
  both rosters, the exact broken idiom with its code, the one-variable fix, and tells consumers to
  check theirs), but it names only the trailing-catch-all `read`. The **last-field** idiom is at
  least as common and now returns a different column: probed on this tree,
  `pm list --kind milestone | awk -F'\t' '{print $NF}'` returns `The agentic half, standing alone`
  where it returned `milestone/0.1.0-…` before, and the same holds for `rev | cut -f1`. Related and
  also unsaid: `name` is the first cell on either row that reliably contains SPACES (ids, statuses,
  owners and branches are token-like), so a default-IFS `awk '{print $4}'` or a `read` with fewer
  variables than columns now splits it. Fix: one sentence naming `$NF` and the space.

- `S1` SUGGESTION `src/agentic_sdlc/repo/pm/cli.py:881-885` — the substitution stops at `\t`.
  `\n` genuinely cannot occur (`model._split`, `model.py:707-708`, splits on `'\n'` only, so a
  frontmatter value is always one line), but `\r` survives `field_of`'s `.strip()` when it is
  interior and reaches stdout raw. Probed with
  `name: real<CR>9.9.9 done in_progress milestone/fake FORGED tail` — the byte stream forges no
  column (a shell `read` still gets five fields) but a terminal renders
  `9.9.9 done in_progress milestone/fake FORGED…` over the real row. The operator here is usually
  an LLM reading stdout, which is the reader this whole feature is about. Cheapest complete fix:
  substitute the ASCII control range rather than `\t` alone; `json.dumps` already escapes it on the
  other side.
- `S2` SUGGESTION `src/agentic_sdlc/repo/pm/cli.py:877-885` — a non-ASCII `name` on a row raises an
  uncaught `UnicodeEncodeError` under an ASCII stdout encoding and exits **1**, the code hard rule 6
  reserves for findings. Probed with an em dash in a milestone name:
  `LC_ALL=C LANG=C PYTHONCOERCECLOCALE=0 PYTHONUTF8=0 … pm list --kind milestone` → traceback at the
  `'\t'.join(...)` line, exit 1; the same with `--json` → traceback at `ensure_ascii=False`, exit 1.
  Plain `LC_ALL=C` is safe (PEP 538 coercion), and no name on a listed row is non-ASCII today —
  but two of this repo's own grain names already carry `U+2014`
  (`pm/roadmap/0.2.0-the-conveyor/bugs/the-deprecation-window-must-close.md:4`,
  `…/features/the-extraction-finishes/feature.md:4`), and `LC_ALL=C` is the hooks' declared vehicle
  (`tests/test_hooks_payloads.py:906`). `name` is the first free-prose cell either row has carried.
  Separately, `ensure_ascii=False` emits `U+2028` raw (probed: `\xe2\x80\xa8` in the payload) —
  valid JSON, not embeddable in pre-ES2019 JS.
- `S3` SUGGESTION `tests/test_cli_surface.py:139-143` and `feature.md` proof budget — the budget
  declared `cases: 2`; five new test functions shipped (three in `test_cli_surface.py`, two in
  `test_pm_verbs.py`) plus two amendments. Two of the five assert help PROSE, and
  `test_the_help_states_the_composition_rule`'s second assertion is
  `'is a column, not a verb' in said or 'a column' in said` — the first arm is true today, so the
  `or` arm can only ever mask a rewording. Nothing asserts `set(LIST_COLUMNS) == set(LIST_KINDS)`;
  a third kind in `LIST_KINDS` alone would `KeyError` inside `_emit_rows` at exit 1, and
  `pm list --unbound [--kind <k>]` is already planned in this same milestone
  (`0.4.0/the-unbound-census`). Drop the `or`, add the one-line parity assert.
- `S4` SUGGESTION `src/agentic_sdlc/repo/pm/cli.py:70-77` — the composition-rule paragraph sits
  INSIDE the verb roster, between `list --kind milestone` and `ready-for`, so `pm --help` reads as a
  list interrupted mid-way by an essay. Move it below the roster; nothing else in `USAGE` breaks the
  column of verb names.
