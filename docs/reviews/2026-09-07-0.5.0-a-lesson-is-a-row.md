**Verdict: HOLD.** The thesis holds and the work is real: nothing in the shipped code infers,
scores or ranks; the row is minted from six named keys and refuses every one of them empty; routing
goes through the same `ledger_of_grain` every other row uses and lands correctly at all four grain
levels; and the criterion's required test genuinely bites — I planted `confidence_derived` on the
minter and watched it go red. What holds the close is that **the row's one job is to point at its
source, and `--source` accepts a pointer that resolves on exactly one machine** — `../outside.md`
and `/var/folders/…/outside.md` both land verbatim in a committed, append-only ledger, and there is
no later gate to catch what `--review-record`'s equivalent gets caught by at close. Second, the
verb's `--help` states an ordering the verb does not hold.

## Blockers

- **`F1` MAJOR `repo/conveyor/lessons.py:307-311` (`_source_file`), `:317-322` (the refusal)** —
  **`--source` accepts a path outside the checkout, and the row is unretractable.** Probed on a
  live tree:

      SOURCE '../outside.md'                                   exit=0  → row lands
      SOURCE '/var/folders/…/tmpko4c0iz7/outside.md'           exit=0  → row lands
      ROWS: ('0.1/alpha', '../outside.md'),
            ('0.1/alpha', '/var/folders/…/tmpko4c0iz7/outside.md')

  `record_resolves` is `path.is_file()` and nothing else, so a pointer that resolves on the author's
  machine passes; the ledger is committed, and `append_to` is an append — **a bad row cannot be
  edited out.** The predicate that answers this already exists eight lines below the one being
  called: `model._pointer_escapes` (`model.py:2164`) returns `True` for both shapes above, and
  `conveyor/steps.py::_record_of` uses it to refuse an absolute `reviewed:` pointer *"(rule 8)"*.
  The lesson row has no equivalent second look, because nothing ever reads it again except to print
  it.

  The criterion's literal words — *"refusing a `--source` resolving to nothing exactly as
  `--review-record` already does"* — are satisfied; the parity is byte-for-byte, escape gap
  included. What is not satisfied is the grain's own sentence: *"The row points at its source; it
  never restates it."* A machine-local pointer points at nothing for every other reader of that
  ledger, which is the condition the refusal message itself names (*"a row pointing at nothing is
  the paraphrase this row exists not to be"*) — deferred to the next clone. That is why this is
  MAJOR and not a NIT: it is permanent, invisible after the fact, and rule 8 is explicit that no
  file here reads a path outside the checkout.

  Fix: one guard in `record()` before the `record_resolves` call —
  `if model._pointer_escapes(given[SOURCE_FLAG]): return _refused(…, 1)` — plus a third case in the
  existing `test_a_pointer_resolving_to_nothing_is_refused_and_nothing_is_written` parametrize,
  which already has the shape.

- **`F2` MAJOR `repo/conveyor/lessons.py:262-263` (the `--help` line), `:81-99` (`read`)** —
  **`lesson show` prints in ledger-file order and its `--help` says it prints in recorded order.**
  Probed with the oldest lesson in the later milestone's ledger:

      lesson show order  : ['NEWEST', 'OLDEST']
      claimed by --help  : "in the order they were recorded"
      read() docstring   : "Every `lesson` row, oldest first."

  `read()` walks `ledger.ledger_paths(cfg)` — grainless first, then `model.milestones(cfg)` order —
  and `list.extend`s per file. Within one ledger the claim holds; across two it is false, and the
  operator has no way to tell, because the `ts` column is last and nothing flags the boundary. This
  package already learned this exact lesson one file over: `pm/cli.py::ledger_show` sorts
  `rows.sort(key=lambda r: str(r.data.get('ts') or ''))` under the comment *"Two files, one
  timeline: rows read in file order would produce negative gaps."* The read side of the same row
  kind does not.

  MAJOR rather than MINOR on purpose: `--help` is a published surface (rule 6 — line shapes are
  grepped, and changing one is a minor bump at least), so a false guarantee is cheaper to correct
  before the tag than after it. The cheapest disposition is a two-word `--help` correction (*"in
  recorded order within each ledger"*), which is why this should not be an expensive hold; the
  honest fix is the `ts` sort — **and note that `F3`'s guard forbids the identifiers `sorted` and
  `sort` inside this module, so the honest fix reddens the guard as written.** That tension is the
  finding's real shape and should be resolved deliberately, not by whichever fix is typed first.

## Findings

- **`F3` MINOR `tests/test_conveyor_lessons.py:301-302, 310-321, 348-358`** — the `RANKING` AST
  guard is **meaningful, not theatre, and it does now cover the writer** — but it under-covers
  selection, and its assertion message over-claims. What is genuinely good: it catches D1's exact
  counter-example vocabulary (`frequency`, `confidence`, `rank`, `score`, `similarity`); it scans
  `lessons.py` whole, both halves; `lesson_sources()` adds every `ledger.py` function whose name
  contains `lessons.KIND`, which is `lesson_row`, i.e. the minter; and `assert len(found) > 1`
  reddens if the minter ever leaves that census — rule 4's census discipline, done right.

  What it misses, each probed against the guard's own predicate:

      CAUGHT  sorted(found)                      CAUGHT  found.sort()
      MISSED  max(found, key=lambda l: len(l.text))
      MISSED  min(found, key=lambda l: l.ts)
      MISSED  found[:3]           MISSED  found[-1]
      MISSED  heapq.nlargest(...)  MISSED  Counter(...).most_common(3)
      MISSED  found.reverse()      MISSED  a hand-rolled insertion order
      MISSED  weight = {...}; priority = [...]

  It is a whole-word identifier match, so it also missed `row['confidence_derived']` — the D1
  counter-example itself, one suffix away. (The *criterion's* field test caught that; see `F6` in
  the criteria table. The exact-dict assertion is the belt; this guard is the braces, and the
  braces are looser than the message says.) Net effect: the guard bans a benign chronological sort
  while permitting every form of selection. Nothing in the shipped code violates it —
  `grep 'min(\|max(\|\[:\|key=' lessons.py` returns one hit, the `_clip` truncation at `:145` —
  so this is a latent coverage gap, not a live defect. Fix: add `min`, `max`, `key`, `nlargest`,
  `nsmallest`, `most_common`, `reverse`, `weight`, `priority` to `RANKING`, add an `ast.Subscript`
  check over the lesson collection, and soften the message to name what it holds.

- **`F4` MINOR `README.md:112-114`, `CHANGELOG.md` `## Unreleased`** — **the new verb has no README
  row and no CHANGELOG line.** `CLAUDE.md` defines the unit: *"New verb = module + route + README
  row + CHANGELOG line."* The module and the route landed. The README's Verbs table says in its own

  (`tests/test_cli_surface.py:59-60`) reads `cli.__doc__`, never the README.

  Graded MINOR because `reviewer.md` item 7 is explicit that docs behind the code are never
  blockers — but it is rule 11's own test (*could someone hand-roll a thing this package already
  does, and would anything have stopped them?*), and a hand-written ledger row is exactly what a
  reader of the README would reach for.

- **`F5` MINOR `repo/conveyor/lessons.py:307-310`** — `_source_file` is a verbatim second copy of
  `repo/pm/cli.py::_resolve_record` (`Path(x) if x.startswith('/') else cfg.root / x`), and its
  docstring names the original: *"as `--review-record` resolves one."* This is the same finding

- **`F6` MINOR `repo/conveyor/lessons.py:281-306` (`flags_given`)** — **a lesson whose text starts
  with `-` cannot be recorded, and there is no `--` sentinel.** Probed:

      TEXT '-1 for the reviewer who blocks on a NIT'   exit=2  unknown flag '-1 for the reviewer…'
      TEXT '--force is the deviation, recorded'        exit=2  unknown flag '--force is the deviat…'
      with -- sentinel                                 exit=2  unknown flag '--'

  The second string is a sentence from this package's own `CLAUDE.md`. The refusal is clean and
  nothing lands, so rule 4 is intact and this is usability, not a sin — but the message
  misidentifies prose as a flag, which is the least useful thing it could say. Fix: treat the
  first non-flag word as the text and stop flag-scanning after it, or honour `--`.

- **`F7` MINOR `repo/conveyor/lessons.py:312-347`, `tests/test_conveyor_lessons.py` §6** — **no
  idempotence contract, written down or tested.** Two identical `lesson record` invocations append
  two rows (probed: `rows after two identical invocations: 2`). `CLAUDE.md` hard rule 3 states
  *"Writes are idempotent: the same command twice is a no-op the second time"* with no exception,
  and "Where things live" requires *"a verb that WRITES also needs a refusal path with a test, and
  an idempotence test."* The refusal path and its test exist and are good; the idempotence test
  does not. An append-only event log arguably cannot be idempotent — `pm decide` and
  `pm ledger record` have the same shape — but that is a **third contract**, and this repo already
  writes its contracts down: `tests/test_replay_migration.py:56-69` spells out FILL-GAPS and REFUSE
  precisely *"instead of being tidied away."* Fix is prose plus one case asserting the append is
  the intended semantics, not a five-line dedupe.

- **`N1` NIT `repo/conveyor/lessons.py:383-389`** — bare `agentic-sdlc lesson` prints `USAGE` to
  **stdout** and returns 2, while every other refusal in the module goes through `_refused` to
  stderr. A consumer piping stdout gets usage text where rows were expected.

- **`N2` NIT `repo/conveyor/lessons.py:241, 356-372`** — `lesson show` ships two new filter flags
  (`--grain`, `--rule`) for columns it already prints. Rule 11's read side says *"the rule governs
  the next one"* — the next filter is a column, never a flag — and the columns are named, ordered
  and tab-separated, so `lesson show | awk -F'\t' '$2=="tree-clean"'` already answers. The flags
  are defensible (they make `==` matching the only matching, which is the anti-nag property the
  feature file argues for) but the argument is nowhere in the code. Substance of rule 11 is met;
  this is the note, not a defect.

- **`N3` NIT `tests/test_cli_surface.py:414-423`** — `test_every_read_verb_names_its_columns`
  counts `columns IN ORDER:` occurrences in `pm_cli.USAGE` only, so a top-level read verb outside
  the `pm` family is outside that census. `lesson show` is held instead by its own
  `test_the_help_names_its_columns_in_order_and_the_reader_agrees`, which is stronger (it binds the
  prose to `COLUMNS` and `COLUMNS` to `ledger.LESSON_KEYS`), so nothing is unheld today. The census
