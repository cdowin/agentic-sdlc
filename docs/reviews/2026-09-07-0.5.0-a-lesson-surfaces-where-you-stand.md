## Blockers

- **`B1` BLOCKER `src/agentic_sdlc/repo/conveyor/driver.py:215-217`, `lessons.py:184-200`,
  `steps.py:644-656`** — **a lesson changes a verdict, an exit code and a write, on `release`, and
  the refusal is unrecoverable.** `surfacer.at_entry()` runs before the first check and calls
  `emit.emit`, whose default sink (`emit.py:49`, `SINK_LEDGER`, live with no `[emit]` section at
  all) appends the `lesson.enter` row to the milestone's **git-tracked** ledger. `tree-clean` is
  the FIRST release step (`steps.py:29-37`) and fails on any modified tracked path — it does not
  exclude the roadmap directory the way `check_committed` does at `steps.py:1231-1232`, which is
  why the two inner belts are immune and this one is not. Probed on a `git_tree()` scratch
  checkout, same tree, one committed clean, `steps.check_tree_clean` real:

  ```
  no lesson recorded   ->  exit 0, writes ['done'], "[release] ok: tree-clean — no modified paths"
  one lesson recorded  ->  exit 1, writes [],       "[release] error: tree-clean: 1 modified
                                                     path(s): pm/roadmap/ledgers/0.1.jsonl"
  ```

  It does not clear. Committing the emitted row and re-running emits another one, four attempts
  running, ledger 2 -> 3 -> 4 -> 5 rows, exit 1 every time: **`release` can never go green while
  any lesson names the milestone.** The only escape is `--force`, which files a `deviation` row —
  a recorded observation forcing a recorded deviation. This is the feature's own "A lesson is
  never a gate", the ship criterion's "It never changes an exit code", `CHANGELOG.md:206-207`'s
  "no verdict, no exit code and no existing line changes whether a lesson exists or not",
  `README.md:167-168`'s same sentence, and rule 4's second sin — a write that looks legitimate and
  is not — all at once.

  Three fix shapes, narrowest first, and the choice is the architect's: (a) have `Surfacer` build
  its lines at entry but hold every `emit` until after the last check and the write decision, so
  no check can observe the side effect of a surface (costs the "same instant" property between
  stdout and the stream, which is the feature's own words); (b) exclude `cfg.roadmap_dir` from
  `tree-clean` the way `check_committed` already does — larger blast radius, and it is arguably
  the right fix independently, because `_belt_written` at `steps.py:630-641` shows the belt
  already knew it dirties that file; (c) route lesson events away from the tracked ledger. Note
  that `pm ready-for`'s own `_emit_enter` (`ready_for.py:147,158`) has the same self-dirtying
  shape and runs in-process inside `features-done`/`findings-resolved` — it does not flip
  `tree-clean` on the same run only because those checks come after it, but it does leave the tree
  dirty for the next one. This feature is what moved an emission ahead of `tree-clean` and made it
  same-run and permanent; the class is older than the feature and worth fixing at (b).

- **`B2` CRITICAL `tests/test_conveyor_lessons.py:223-265`** —
  `test_a_lesson_changes_no_verdict_and_no_exit_code` is the case the feature "lives or dies on"
  by its own module docstring, and it **cannot fail on B1**, for a structural reason rather than

  proves is that `driver.run`'s line assembly and write decision are unaffected by the surfacer —
  true, worth having, and much weaker than what the docstring, `CHANGELOG.md:206` and
  `README.md:167` assert. It is rule 4's first sin wearing a test's clothes: PASS printed over
  something not measured. Fix, and it is under twenty lines: one case on `git_tree()` with the
  real `steps.check_tree_clean` in the registry, two freshly built trees, one with a lesson naming
  the milestone and one without, asserting identical exit codes and identical writes. It fails
  today.

- **`B3` MAJOR — the read side of the ship criterion is absent, and the criterion is not met
  without it.** `agentic-sdlc lesson show [--grain <id> | --rule <id>]` does not exist:
  `grep -rn lesson src/` returns the reader, two doc strings and nothing else — no verb module, no
  route in `cli.py`, no `--help` columns. Nor can anything in this package WRITE the row the
  reader reads: `ft-a-lesson-is-a-row-bound-to-a-grain`, which owns `lesson record`, is
  `status: planning` and sits immediately BEFORE this feature in the milestone's `order`. Measured
  on this repo's own tree: `lessons.read()` over 6 ledgers and 3,029 rows returns **0 lessons**.

  The author's argument — that `lesson show` belongs with `lesson record` in one verb module — is
  a good PLACEMENT argument and I do not dispute it. But placement decides which commit a thing
  lands in, not whether this feature's criterion is met, and the criterion is the grading
  instrument. The second half of it is not decoration on the first: it is rule 11's read side,
  spelled out with the columns-in-`--help` requirement, and D1's argument is precisely that a
  store you can write to and cannot enumerate is what `Learner` was. The belt surface is a
  read-back at three moments; it is not a way to ask *what have I recorded*. The sharpest case:
  `lessons.py:66,72` short-circuit an empty scope to `()`, correctly — so a lesson row carrying
  neither a `grain` nor a `rule` surfaces at no belt moment ever, and with no `show` verb it is
  unreachable for the life of the tree. That is the counter-example's exact shape.

  Two honest dispositions, and silence is not one of them: land `lesson show` here, or amend the
  criterion so the read verb belongs to the sibling feature and this feature's criterion stops
  naming it.

- **`M1` MAJOR `src/agentic_sdlc/repo/conveyor/lessons.py:106-115`** — reading blockers off
  `pm ready-for`'s printed line makes two contracts out of a line shape the verb never promised,
  and both fail SILENTLY, which is the failure mode this feature exists to forbid.
  `blockers_named` splits the flattened output on whitespace and takes **the first token after the
  `BLOCKED` marker** as a grain id. That requires (1) `BLOCKED` to stay a bare whitespace-delimited
  token — it is `'  BLOCKED  '` at `ready_for.py:71`, while every other `BLOCKED` string this
  repo ships is spelled `BLOCKED:` or `BLOCKED (…)` (`installables/pre-push:37,66`,
  `cc-write-confine.sh:91`, `cc-commit-pathspec.sh:183`, `cc-stop-gate.sh:100`), so one alignment
  edit returns `()` and the third surface goes dark with no line; and (2) the first word of
  `blocker.why` to BE a grain id, which for most shapes it is not. Census off `ready_for.py`'s own
  construction sites — leads with an id: `:400` (`held.names`), `:457`, `:471`, `:475`, `:479`,
  `:552`. Does not: `:340` yields `<check-name>:` or `UNVERIFIABLE`, `:517` yields `<owner>:`,
  `:528` yields `UNVERIFIABLE`, `:540` yields `E1,`, `:369` yields `nothing`, and `:152`'s
  over-cap line yields `...`. So the entire `findings-resolved` (tag rung) blocker family
  surfaces nothing, and blockers past `MAX_NAMED = 50` are never named to the surfacer at all.

  Exactness is preserved — `==` at `:64-74` means a junk token like `owner:` or `E1,` matches
  nothing — so this is a MISS risk, not a nag risk. That is the right direction to fail, but it
  fails quietly, which rule 11 does not allow, and exactly one of those eight shapes has a test
  (`test_conveyor_lessons.py:156-163`, the story-in-progress blocker). Fix at the cheapest layer:
  have `ready_for` carry the grain as DATA rather than as the first word of prose — `Blocker` is
  already a `NamedTuple` with a `check` field and could carry a `grain` one — so the coupling is
  on a field instead of a sentence. If the line must remain the contract, then every one of those

  quiet.

## Findings

- **`M2` MINOR `tests/test_conveyor_lessons.py:270-305`** — the AST check, assessed as asked. It
  is a cheap tripwire, not theatre, but it is worth less than its assertion message claims. It
  catches the single most likely regression — somebody reaching for `sorted`/`sort`/`rank`/`score`
  inside a 205-line module — and its false-negative surface is bounded by that small scope. It
  does NOT catch `min`, `max`, a `key=`/`reverse=` keyword (those are `ast.keyword` nodes, not
  `Name`/`Attribute`), `heapq.nlargest`, a `[:1]` slice, or an identifier named `weight`,
  `priority`, `relevance` or `match_quality`; and it scans `lessons.py` alone, while the ordering
  this feature actually depends on also lives at `driver.py:243` (`answer.names` order) and
  `steps.py:626` (`dict.fromkeys` order), neither of which is scanned. The claim "nothing ranks"
  is really carried by the four behavioural assertions immediately above it at `:286-296`, and
  those do bite. Separately, this repo already has one home for AST gates —
  `tests/test_boundaries.py`, which `emit.py:5-6` names as the thing holding the no-import rule
  shut — so this is a second AST-gate mechanism outside the module that owns them. Fix: move it
  into `test_boundaries.py` beside its peers and widen it to the three conveyor modules, or drop
  it and let the behavioural cases carry the claim alone.

- **`M3` MINOR `src/agentic_sdlc/repo/conveyor/lessons.py:77-82`** — `paths()` is a verbatim second
  copy of `checks/pm.py:395-400 _ledger_paths`, and its own docstring says so: *"THE HELPER THAT
  BELONGS IN `ledger.py`: `checks/pm.py` spells it privately, and a third is a third answer."* The
  author identified the nearest existing construct, named the right home, and then shipped the
  second copy anyway. Under checklist item 3 that is the finding, not an excuse for it. Fix is a
  five-line move into `ledger.py` with both callers importing it — cheaper now than after the
  third.

- **`N1` NIT `src/agentic_sdlc/repo/conveyor/lessons.py:184-200`** — `emit.emit` RETURNS a finding
  string on an unreachable sink (`emit.py:83-86`) rather than raising, and `_emit` at `:191`
  discards the return value. So the unreachable-sink path produces no line from the surfacer at
  all; the finding reaches stderr only, from `emit._finding`. Behaviour is acceptable — rule 11 is
  satisfied on stderr — but the docstring at `:186-188` claims the WARNING covers "if it could not
  be reached", which is true only for the exception path (a malformed `[emit]`), and the case at
  `:251-257` asserts the exit code and that the lesson still printed without ever asserting a line
  naming the unreachable sink. Make the docstring say what happens, or capture the returned
  finding as the line it claims to be.

- **`N2` NIT `tests/test_conveyor_lessons.py:235-247`** — the byte-identical claim is proven for
  the ledger sink alone. With `[emit] sink = "-"`, `emit._to_stdout` (`emit.py:90-98`) prints a
  JSON row into the belt's stdout during `run()`, before any verdict line is printed
  (`driver.main:690` prints `result.lines` after `run` returns) — and the belt emits nothing of

- **`N3` NIT `src/agentic_sdlc/repo/conveyor/lessons.py:85-103`** — `read()` parses every JSON row

- **`Q1` QUESTION `src/agentic_sdlc/repo/conveyor/lessons.py:30-33`** — the emitted kinds are
