**Verdict: HOLD.** Two MAJORs. The three claims I was told to attack hardest all survive, and two of

## Findings

- `C1` **MAJOR** `src/agentic_sdlc/repo/pm/cli.py:629` (same shape at `:657`, `:686`, `:770`, `:808`)
  — **a no-op mints a full arrival, so a recorded answer is silently replaced by `none`.**
  Every status verb calls `_arrived(...)` unconditionally, including the `cur == to` branch that has
  just printed `(no-op)`. Live, on a fixture tree:

      $ pm feature building 0.1/alpha --by agent reviewer
        -> disposition {state: building, answer: "--by", value: "agent reviewer"}
        -> census: "1 of 2 carries no disposition"
      $ pm feature building 0.1/alpha            # bare, no-op, nothing changed
        -> disposition {state: building, answer: "none"}       <-- shadows the answer
        -> status      {from: building, to: building}          <-- an arrival that did not happen
        -> census: "2 of 2 carry no disposition"
        -> and the answered fork PRINTS AGAIN

  `arrive._answered` takes the LAST disposition per `(grain, state)`, and so does `checks/pm.py` U5
  by construction — so the grain is now named by the gate as reaching its state with no disposition
  when it did, and the pressure line agrees with the gate about a fact that is false. The same
  shadowing hides a D6 `skipped` field: a `close feature --skip review-recorded "…"` row is followed
  by a bare re-run's row carrying no `skipped` key at all, verified. **This is rule 4's second sin —
  a write that looks legitimate and is not** — inside the one feature whose thesis is that the tree
  records what it did without asking anyone.
  Note the disposition row on the no-op path is **load-bearing and must stay**: re-running the move
  with the answer is how the fork is answered (`fork_lines`' own docstring), and that path works —
  bare then `--by me` correctly drops `unanswered` 2 -> 1. The fix is narrower than "skip
  `_arrived`": on `cur == to`, do not mint a `status` row (nothing transitioned), and do not mint a
  `none` disposition when this `(grain, state)` already carries an answered one. An answer already
  given is not un-given by re-running the command that shows it.

- `C2` **MAJOR** `conveyor/driver.py:603` (`_writer`, at `8f04468`) and `checks/pm.py` — **the census reaches one of the three
  surfaces its own ship criterion names.** The criterion: *"Every `pm` write, every belt write and
  every `check pm` run reports the tree's open work when there is any."*
  - `pm` write: **met**, properly — one line, on stderr, silent when nothing is open.
  - belt write: **degenerate.** `_writer` redirects the arrival's whole report into a buffer and
    flattens it — `said = ' '.join(buffer.getvalue().split())` — into one `[feature] write: …` line.
    Measured on a real `close feature --force`: **a single 555-character line** carrying the
    breadcrumb, the fork and the census run together. The fork's answers are no longer commands on
    their own lines, so *"both answers spelled, so the cheap answer costs one paste"* is exactly what
    the belt destroys — at `close feature`, which is where the question is raised. The feature's own
    "What it must not become" section says *"never noise… one line for the move, one question, two
    commands, one census line"*.
  - `check pm` run: **not met.** `check pm` uses `arrive.census` as U5's *guard* but never prints the
    `open:` line. Probed on a tree with two `in_progress` grains: the only line naming `in_progress`
    is an unrelated owner WARN.

  This is inherited plumbing made newly harmful — in 0.4.0 the squashed payload was one short
  breadcrumb. Cheapest fix: let the writer pass the arrival's lines through as lines rather than
  squashing (it already owns the buffer), and have `check pm` print the census it already computes.

- `m1` **MINOR**, cross-feature; the reading is owned by `ft-time-is-measured-per-state-and-rolls-up`
  — **the phantom `from == to` status row resets the clock.** Same root cause as C1.
  `report.arrival_state` reads a `status` row's `to` as an arrival mark, so a no-op inserts a second
  mark at the state the grain never left. Measured over synthetic rows, a grain in `building` since
  10:00 with a bare re-run at 13:00, read at 15:00:

      clean:            marks [(10:00, building)]                  open charge 5h
      after the no-op:  marks [(10:00, building), (13:00, building)] open charge 2h

  `state_seconds` also fabricates a *closed* stint of 3h for a state nobody left; the total is
  preserved but the shape is wrong. The row itself is inherited from 0.4.0 — `ledger.status_row`'s
  docstring says *"a no-op flip is a row like any other"* — and was harmless there because nothing
  computed per-state time. **8 such rows are already in this repo's own ledger** (of 330 status
  rows). The census `oldest` number is NOT affected: `ledger.open_seconds` keys on `status[0]`, the
  first row. Fixing C1's status-row half fixes this.

- `m2` **MINOR** `src/agentic_sdlc/repo/pm/cli.py:574` — **the D6 fold rests on two independent
  clock reads.** `_arrived` builds both rows in one expression, and each builder defaults its own
  `ts` to `ledger.utc_now()`, which is second-resolution. `report.arrivals` folds the status and
  disposition halves of one arrival only when `(stamp, state)` is *identical*, so a pair that
  straddles a second boundary is counted as two arrivals — a spurious stint and a reset open charge,
  from the same defect class D6 was decided to remove. The window is microseconds wide, so this is
  rare rather than theoretical. Both builders already accept `ts=`: read the stamp once and pass it
  to both.

- `m3` **MINOR** `src/agentic_sdlc/repo/pm/arrive.py:392-416` — **the report runs outside a reading
  scope, so the tree is walked four times per write.** `census` walks the grain index twice
  (`grain_index`, then `known_milestones` inside `_ledger_paths`) and `crossing` walks it twice more.
  Measured on this repo (167 grains, 6 ledger files, 3423 rows parsed per census):

      crossing + census, no scope           23.6 ms   4 index walks
      census alone,      no scope           17.2 ms   2 index walks
      census alone,      reading_tree()      9.6 ms   1 index walk

  Wrapping `report`'s body in `with model.reading_tree():` roughly halves it, for one line.
  **The `check pm` O(n²) shape does NOT repeat.** Synthetic trees, census warm:

      167 grains   16.1 ms   0.096 ms/grain
      367          25.5      0.070
      667          39.8      0.060
      1167         64.5      0.055
      2167        115.7      0.053

  Time grows ~x1.6 per x1.9 grains and ms/grain falls throughout — linear with a fixed ledger cost,
  not quadratic. At a 700-grain consumer tree the census is ~40 ms per write. Bounded and
  acceptable; recorded because it is paid on every `pm` write, every belt write and every `check pm`,
  and the 2x is free.

- `N1` **NIT** `devkit.toml`, `[pm.arrive.feature.reviewing]` — **one word, two shapes, reintroduced
  in the declaration.** This repo declares `answers = ["--review agent <type>", "--skip review
  \"<why>\""]`. On a `pm` move, `--skip` is an unvalidated free-text claim: probed, it records
  `{answer: "--skip", value: "review because reasons"}` with **no `skipped` field**. On
  `close feature`, `--skip` is a check name validated against `[<op>] skippable` that becomes the
  `skipped` field. Same word, two meanings, one validated and one not — the exact defect D6 was
  written to delete. The **tool** is right to treat answers as opaque declared flags; the fix is the
  declaration (`--skip-review "<why>"`), here and in any seeded example.

- `N2` **NIT** `src/agentic_sdlc/repo/pm/arrive.py:74-96` — **the answer must follow the grain id, and
  the wrong order gets a generic dump.** `take` joins everything after the flag into the value, so
  `pm feature building --by me 0.1/alpha` exits 2 with the whole `usage:` block rather than a line
  naming the ordering. `unknown_flag_hint` already does the rule-11 thing for an *undeclared* flag
  ("arriving at feature building accepts …"); the ordering refusal deserves the same sentence.

- `N3` **NIT** `tests/test_pm_verbs.py:508` `test_every_word_and_number_is_derived` — **the
  derived-only guard is real, and two of the line's numbers slip past it.** I tried to defeat it and
  could not on the parts it covers: the question is compared to `node.ask` verbatim, every answer
  line must *end* with a declared answer, and the open count is recomputed from `grain_index` plus
  the project's own `[pm.states.*]` categories. A hardcoded question or a hardcoded count does fail
  this test rather than a review. But the criterion says *every* number traces, and:
  the **age** is asserted only as `assertIn('oldest ', census)` — the duration itself is never
  compared to anything derived from the rows; the **`no_record`/`record_pool`** pair is asserted only
  in its absent form (`assertNotIn`), so the positive clause has no derivation test at all; and
  `assertIn(str(cfg.wip), census)` passes on any tree where that digit appears elsewhere in the line
  (the separate wip case does pin `f'wip of {wip}'` properly). Three rows on the existing case.

- `N4` **NIT** `src/agentic_sdlc/repo/pm/arrive.py:211-251, 296-333` — **`Census.unreadable`
  discloses damaged ledgers and not damaged grains.** An unreadable in_progress document silently
  drops out of the count: probed, `open: 4 in_progress` became `open: 3 in_progress` with
  `unreadable` still 0 and no clause. The class is one the code already recognises and discloses for
  the other input (*"the ages above are short by whatever is in them"*). **Not graded higher because
  nothing lies in a green tree**: `check pm` names the same document twice and exits 1
  (`DRIFT … declares no 'id:', so nothing can key on it — it was SKIPPED by this scan`), so the
  census only under-counts in a tree the gate already fails.

## Dispositions, 2026-09-07

- `C1` **landed in-place.** `cli._arrived` asks whether anything transitioned: `frm == to` mints no
  `status` row, and a bare re-run does not replace an ANSWERED `(grain, state)`'s disposition with
  `none`. An explicit answer still replaces an old one, and a bare move that IS a transition still
  writes both rows. The fork was suppressed the same way — asking again for a disposition the
  census already counts was the third half of the symptom — so the question, the row and the
  census now read one predicate. `tests/test_pm_ledger.py::test_a_no_op_mints_no_flip_and_never_shadows_an_answer`
  and the amended `test_a_declared_answer_is_recorded_as_it_was_typed` pin both halves.
- `C2` **landed in-place.** `driver._writer` hands the arrival's report back as LINES and `run`
  prints the first after `write:` and the rest verbatim, so the fork's commands are commands again;
  `check pm` prints the census it already computed as a counted `OPEN` line, off the same
  `arrive.census` U5 gates on, read ONCE and handed in. `[pm] pressure = false` silences all three.
  Cases: `test_conveyor_deviation.py::test_the_belt_hands_the_arrivals_report_on_as_LINES` and
  `test_pm_gate.py::…::test_every_run_reports_the_open_work_whatever_checks_are_on`.
- `m1` **landed in-place**, and wider than the status-row half. `report.arrivals` now folds
  consecutive arrivals at the SAME STATE rather than at the same stamp, so a re-arrival at a state
  nobody left cannot open a second stint whichever row kind carries it — which is what a no-op
  answering a fork now writes. **The eight `from == to` rows already in this repo's ledger need no
  migration: the reader tolerates them.** Recomputed on all three non-terminal carriers, the state
  totals are identical before and after (`0.4.0/the-read-verbs-compose` building 2078 / reviewing
  638; `0.2.0/the-extraction-finishes` 1432 / 46886), and the other five sit at a terminal state
  where nothing accrues. `ms-0.4.0` still reports 4069 and `ft-binding-is-a-field` 861.
- `m2` **landed in-place.** `_arrived` reads the clock once and passes `ts=` to both builders.
