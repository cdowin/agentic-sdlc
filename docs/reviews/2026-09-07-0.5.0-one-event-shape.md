## What holds, proven rather than read

**The absence really is the signal, and there is no fourth kind.** A `release` whose second check
answers `no` writes two `check.verdict` rows — `{verdict: "ok"}` and `{verdict: "error"}` — and no
`rung.leave`, exit 1. `adopt` emits its verdicts and never a leave, because the tap is the write's.
A run that never happened has no rows at all, so on the JSONL the three states are three shapes.
`test_a_belt_that_writes_nothing_emits_its_verdicts_and_no_leave_event` parametrises all three and
its last two lines assert `set(events) <= set(ledger.EVENT_KEYS)`, so a fourth kind fails a test.

**A skipped check mints nothing, and that is distinguishable from one that was asked.** `release
--skip b "…"` with `[release] skippable = ["b"]` leaves one `check.verdict` for `a` and a
`disposition` row carrying `skipped: [{check: "b", why: "…"}]` — D6's fold, live. A verdict for `b`
would be rule 4's sin, and there is none.

**A consumer that declares no sink gets today's run, byte for byte.** Same tree, same checks, with
and without `[emit]`: stdout identical (1027 bytes), stderr identical (empty), exit identical, and
the only ledger rows are the `status` and `disposition` rows that pre-date this feature. An
unreachable sink does not move the exit code either — `emit._finding` writes to stderr and the belt
carries on. `test_a_run_given_no_tap_behaves_exactly_as_it_did` pins the function-level half.

**U3 is noisy rather than blind.** Every kind that reaches `emit.emit` ends in a `TAPS` word:
`rung.enter`, `check.verdict`, `rung.leave`, and the lesson surfacer's `lesson.enter` /
`lesson.verdict`, which are built FROM `emit.TAP_*` and so cannot drift.
`test_every_tap_kind_spells_the_tap_check_pm_counts` pins the three, including their order.

**The rendered section is genuinely rendered.** `sdlc_doc.render() == docs/sdlc-protocol.md` on
disk, today. `_events()` holds no per-kind text.

## Blockers

- `E1` **CRITICAL** `tests/test_boundaries.py:1063-1090` — the derived-field guard grades
  `ledger.leave_row` **vacuously**, and `leave_row` is the row carrying `next_rung`, `next_checks`
  and `next_actions`. `_minted_strings` is applied only to `ast.Return` node VALUES; `leave_row`'s
  only return is `return row`, a bare `Name`, so it yields zero strings. Proven both ways: a literal
  planted directly in `leave_row`'s zipped value tuple is invisible, and so is
  `row['suggested_action'] = 'run a review'` placed immediately before the return — while the same
  literal in `_enter_row`'s returned dict and in `verdict_row`'s zipped tuple IS caught. The `seen`
  counter finds 4 of 4 minters and grades 3, so the test reports a clean census over a check it did
  not perform. The criterion's sentence — *"a hardcoded next-step fails a test rather than a
  review"* — is false for the one payload the sentence is about. **Fix:** grade the FunctionDef
  body, not the return expression: walk every `ast.Dict` value and every `dict(zip(...))` argument
  tuple in the function plus every `Subscript` assignment on a local, and exclude the `raise`
  f-strings explicitly (they are the only other string source, and `lesson_row` needs them). Then
  add `leave_row` to the reader's own probe, the way `MINTER_SPELLINGS` probes the other shapes, so
  the negative control exists.
- `E2` **MAJOR** `src/agentic_sdlc/repo/pm/ledger.py:92` — `rung` means two different things across
  the three kinds in ONE rendered table. `LEAVE_KEYS` puts `nxt.belt`, the **next** belt, in `rung`;
  `ENTER_KEYS` and `VERDICT_KEYS` put the rung that ran. Live, one `close story st-y` writes
  `check.verdict {rung: "story"}` and `rung.leave {rung: "feature"}` on the same grain in the same
  file, so a reader joining the two kinds on `(grain, rung)` joins nothing, or joins a story's leave
  to a feature's verdicts. The feature brief spells this field `next_rung`; the shipped key is
  `rung`, and the rendered table lists all three rows with a bare `rung` and nothing distinguishing.
  This is D6's *"one word, two shapes"* defect in the schema this feature exists to make
  authoritative, and after release renaming it is a major bump (rules 6 and 7). **Fix:** rename to
  `next_rung` — the brief's own word — in `LEAVE_KEYS` and `leave_row`; the rendered table and its
  test follow for free.
- `E3` **MAJOR** `tests/test_pm_ledger.py:679-694` — the schema-binding test does not prevent the
  document describing a stream that is not emitted, which is the whole reason the section is
  rendered. Both assertions filter to keys the row HAS (`[k for k in declared if k in row]`, and
  `set(row) <= set(declared)`), so a key added to `EVENT_KEYS` and minted by nothing passes — and
  because all three minters zip a fixed value tuple against the key tuple, `zip` drops the extra key
  silently rather than raising. Proven: appending `'suggested_action'` to `VERDICT_KEYS` leaves both
  assertions true and `sdlc_doc.render()` then publishes
  `| verdict | check.verdict | …, ran, suggested_action |` for a field no row ever carries. The test
  catches the opposite direction (a field added to a payload and not the schema) for `_enter_row`
  and for a subscript on `leave_row`, so it is half a binding. **Fix:** assert the other direction
  against a named allowlist — `set(declared) - set(row) <= OPTIONAL[kind]` with
  `OPTIONAL = {KIND_LEAVE: {'value'}}` — so the one designed-optional key is DECLARED and a phantom
  key fails by name.
- `E4` **MAJOR** `src/agentic_sdlc/repo/pm/cli.py:2300-2311` — the read verb the ship criterion names
  prints the three new kinds as a bare `ts` and `kind`. `cmd_ledger_show` branches on `status`,
  `disposition` and `lesson`; the three taps fall through to `f'{ts}  {kind:<8}'`. Live, a refused
  `release` (two verdicts, one `error`) and a passed one (one verdict, `ok`) render as identical
  `2026-…Z  check.verdict` lines — no check name, no verdict word, no `detail`, no `ran`;
  `rung.leave` shows no `state` and no `next_checks`; `rung.enter` would show neither `ready` nor
  its blockers. So *"the absence is the signal"* holds on the JSONL and fails at the shipped reader:
  there, refused and passed are the same eight characters. This is rule 11's read side verbatim, and
  `_disposition_cells`' own docstring states the rule — *"this verb printed the kind and stopped,
  which teaches a reader the tool does not hold the answer"* — because D5 recorded the identical
  defect for `disposition` one feature earlier and it was fixed there. **Fix:** three `_*_cells`
  helpers beside the two that exist, and see `E11` for the column width.
- `E5` **MAJOR** `src/agentic_sdlc/repo/conveyor/driver.py:274` — a malformed `[emit]` is swallowed
  at the belt instead of exit 2. `emit.settings()` raises `ConfigError` for a `kinds` entry this
  version cannot emit — *"a tap named and never emitted is a sink a consumer waits on forever"* —
  and `emit.py`'s own docstring commits to exit 2. `Verdicts.say` catches bare `Exception` and turns
  it into a mid-stream WARNING on **stdout**; live, `[emit] kinds = ["bogus"]` gives `release` exit
  **0** with `ok` printed and the consumer's sink silent forever. Hard rule 9 puts a malformed
  declaration at exit 2, and `driver.main` already resolves `ran_for` early for exactly this reason
  (*"a malformed `[<op>.commands]` is exit 2 before the first check, not a field this run then has
  to leave out of its events"*). Second half of the same defect: `Verdicts.say`'s docstring says it
  prints *"no lines unless the sink could not be reached"*, but a sink that cannot be reached
  produces no line from it at all — `emit.emit` handles `SINK_ERRORS` internally and returns the
  finding string, which `say` discards — so the branch fires only for the config error it should not
  be catching, and on the wrong stream (the other two taps warn on stderr). **Fix:** call
  `emit.settings()` in the same early `try` as `ran_for` when `emit.declared()`, then delete
  `Verdicts.say`'s try/except and `_defect` entirely. That makes *"emission is never load-bearing"*
  precise — the SINK never is, the DECLARATION is read like every other declaration.

  so a courier built off that table drops two kinds it will receive. The three-TAPS claim is intact;
  the KIND census is not. **Fix at the cheapest layer:** one sentence in the template saying the
  table is the BELT's own kinds and other kinds may ride the same taps with their own shape. The
  emitting code is `ft-a-lesson-surfaces-where-you-stand`'s; the incomplete table is this changeset's.
- `E8` **MINOR** `installables/sdlc-template.md:42` — *"the absence IS the signal"* holds only when

  about one left out. **Fix:** one sentence — a missing `rung.leave` reads as "refused" only against

- `E9` **MINOR** `src/agentic_sdlc/repo/pm/ledger.py:130-142` — `next_actions` is not what the brief

  the belt printed two `next:` lines from `steps.after_lines` and the row carried

  move. Cheapest at the brief.
- `E10` **NIT** `src/agentic_sdlc/repo/pm/ready_for.py:59` — `KIND_ENTER` is a second spelling of

- `E11` **NIT** `src/agentic_sdlc/repo/pm/cli.py:2299` — `{kind:<8}` no longer fits: `check.verdict`
