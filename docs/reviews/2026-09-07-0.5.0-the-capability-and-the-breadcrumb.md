# the capability line and the breadcrumb emission — review

Scope: `ft-a-move-names-the-capability-you-are-standing-in` and
`ft-a-move-emits-the-breadcrumb-it-prints` only. Four features shipped as one arrival mechanism and
were reviewed together; the full evidence is in `docs/reviews/2026-09-07-0.5.0-arrival.md`. This
record is split because that review's two MAJOR findings (C1, C2) belong to the spine and the pressure
line, and neither is about these two features.

**Splitting after the fact is the orchestrator's error, twice today** — U3/U4 first, now this. A
reviewer graded on N features writes ONE verdict block, and `findings-landed` reads a record rather
than a feature, so one feature's blocker holds another's close. The fix is one dispatch per feature,
not one dispatch per changeset.

## Both ship criteria — MET

**The capability line.** `have:` prints after `next:`, named only from the `[pm.arrive.*]`
declaration, a declared file that is absent is a named line rather than silence, a transition with no
binding prints nothing, and it rides `rung.leave` as `have` beside `next_actions`. It is a census, not
advice — the word is deliberately different from `next:`, which is the belt's binding check list.

**The breadcrumb emission.** One `derive_next`, two renderers. The printed line is byte-identical to
0.4.0 and its three existing tests pass untouched; `breadcrumbs = false` silences the prose only and
the row still carries every fact.

## What the reviewer attacked and could not break

**Stdout is byte-identical to 0.4.0** across nine verb cases including refusals — checked expecting a
regression and finding none, because 0.4.0's breadcrumb was already on stderr.

**D3 holds.** Nothing keys on `(from, to)`; `derive_next` asks only the destination's CATEGORY. There
is no transition table.

**D6's fold is real.** One row, `skipped` as a field, no discriminator, and a refused close returns
before the writer is called so it leaves nothing behind. `report.arrivals` folds the
status/disposition pair, so one arrival never double-counts.

**The O(n²) shape does NOT repeat.** Measured 167 → 2167 grains: ms per grain FALLS, 0.096 → 0.053.
Linear, ~40ms at a 700-grain consumer tree — the scale that cost 87 seconds earlier this milestone.

## Carried, not blocking

The reviewer notes the report runs outside a reading scope, so the tree is walked four times per
write; `model.reading_tree()` halves it (23.6ms → 10.9ms). Carried to the spine's fix pass, where the
call site lives.

it belongs to `ft-time-is-measured-per-state-and-rolls-up`.
