Commits `679c726` (checkpoint) and `a4545c2` (the feature), reviewed cold against
`pm/roadmap/features/ft-wiring-is-one-act-and-it-is-portable.md`, its sibling
`ft-telemetry-proves-the-path-not-the-config.md` (whose criterion duplicates one of this one's

reference-aware search. Every claim below was probed live in scratch trees under
`$TMPDIR`, never against this checkout.

**Verdict: HOLD.** The two mechanisms the feature exists for are right and they are proven the
honest way — the emitted commands are absolute, the settings write is refused by path with
`--force` included, `GDK_LEDGER_ROOT` never falls back to a cwd it was overridden away from, every
courier path fails open, and all five new guards (2 pyunit, 3 corpus rows per courier) go red when
their branch is removed. What holds the close is not the mechanism: **the emitted command is
unquoted**, so a checkout path containing a space produces a block the shell cannot run while
`--write-settings` writes it and reports *"these hooks are in force now"* (E1, E2); the one surface
that TELLS an operator the wiring is missing still instructs them to hand-paste and says this verb
*"never writes that file"* (E3); the entry point built for a brand-new consumer never reaches the
settings step at all (E4); this repo — the tree whose zero-row build IS issue #13 — still carries
the relative block, with no gate on it (E5); and the criterion's third paragraph
(`--tokens-total`) shipped nothing (E6). Every fix but E6 is one line or one clause.

Note for the belt: the block below says `HOLD`, not `PASS`. `PASS` is not in
`src/agentic_sdlc/repo/pm/verdict.py`'s closed `VERDICTS` set and would parse as
`MalformedVerdict` at exit 2.

## Blockers

- `E1` **MAJOR** `install.py:280` — `f'bash {root / rel}'` interpolates the absolute path
  **unquoted** into a string the harness hands to a shell. Probed end to end in a scratch repo at
  `…/scratchpad/my repo`: `install-hooks --write-settings` exits **0**, writes the file, prints
  `wrote .claude/settings.json — these hooks are in force now`, and the emitted command run through
  `sh -c` answers `bash: /private/tmp/…/my: No such file or directory`. Five hooks, none of them
  fire, nothing is red anywhere. The relative form had no space to break on, so absolutising
  introduced the class. **The new guard cannot see it**:
  `test_every_emitted_command_is_an_absolute_path_to_an_installed_file` extracts the path with
  `command.split(' ', 1)[1]`, which under a spaced root yields the whole remainder — `is_absolute()`
  and `is_file()` both stay true on a command that cannot run. Not CRITICAL only because it needs a
  space in the checkout path. Fix: `shlex.quote(str(root / rel))`, and one `repo()` case whose root
  carries a space.
- `E2` **MAJOR** `install.py:301` — `wrote {rel} — these hooks are in force now` asserts an outcome
  this package cannot observe, at the one surface this milestone exists to make honest. The same
  run's own block text (`install.py:293-298`) says the harness may read *"one above this repo"*;
  `check pm` U4 (`checks/pm.py:620-624`) and `telemetry-live` (`steps.py:1126-1130`) both spell out
  that whether a harness LOADS `<repo>/.claude/settings.json` depends on the session's project root.
  Issue #13 is a tree that had that exact file in place with nothing in force. What the verb knows
  is that it wrote the file; "in force" is the inference. Fix: one clause — `wrote {rel} — in force
  for a session rooted here`.
- `E3` **MAJOR** `conveyor/steps.py:1112-1115` — `telemetry-live`'s refusal, the one line a consumer
  reads at the moment they learn they are unwired, still says: *"`install-hooks` PRINTS the entries
  and never writes that file, because it is yours and has no merge; paste them and this goes
  green."* False as of this commit, and it is rule 11's own test verbatim — the operator standing in
  the surface that names the gap is told to hand-roll the thing the package now does, and never told
  `--write-settings` exists. It is also the ONLY surface a fresh consumer hits: `check pm` U2 returns
  early when nothing is wired (`checks/pm.py:547-548`, D5 — a tree that wires nothing opted out), so
  `adopt` is the whole channel. Same stale claim in the docstring at `steps.py:1054-1055` and the
  module comment at `steps.py:49`. **Nothing catches it**: this milestone's new
  `test_no_installable_names_a_retired_thing_except_as_a_migration_note` scans `installables/`,
  `guidance/` and `templates/` only — `steps.py` is code.
- `E4` **MAJOR** `init.py:258` + `install.py:869` — `init` calls `install.main(command, …,
  next_step=False)` and `_settings_step` is gated on `next_step`, so **the brand-new consumer this
  feature is for never sees the settings step at all**: no destination named, no block printed, no
  flag offered. Probed: `init`'s own seven-step "Next" list (`init.py:278-310`) mentions
  `.claude/settings.json`, `--write-settings`, the block and `GDK_LEDGER_ROOT` exactly zero times,
  while step 4 does tell them to edit the `project config` headers. The criterion condemns "a
  fragment with no destination"; through `init` the package emits neither fragment nor destination,
  which is strictly less. With E3, a fresh consumer's only route to the wiring is an `adopt` line
  that tells them to paste. Fix at the cheapest layer: `_settings_step(root, False)` once after
  `install-hooks` in `init.main`, or an eighth line in the Next list.
- `E5` **MAJOR** this repo's `.claude/settings.json` — still `bash tools/hooks/cc-ledger-session.sh`
  and four siblings, all relative. `CLAUDE.md:139` makes this a gate, not a nicety: *"`tools/hooks/`
  … (`install-hooks`, with `.claude/settings.json` carrying the entries it prints)"*. The entries it
  prints are now absolute; the file is stale, and it is **not** "legitimately absent" — it is present
  in the old form. The `tools/hooks/` copies ARE byte-current (E-none, see the table), so the drift
  is exactly the one file with no test behind it: `test_this_repo_carries_what_install_ci_produces`
  and its `install-agents` twin have no `install-hooks` settings counterpart, and `install-hooks
  --diff` prints `--write-settings writes nothing under --diff`, so the diff path cannot see it
  either. Consequence, not theory: this is the tree whose nine dispatches recorded zero rows, it
  stays that way, and `_wired_couriers` (`checks/pm.py:433`) matches the courier filename as a
  substring, so U2/U4/`telemetry-live` all keep answering "wired". `--write-settings` cannot fix it
  (E1's sibling problem: the file exists and differs, so it is correctly refused) — this one is a
  hand edit plus a self-hosting case.
- `E6` **MAJOR** feature file line 60 vs `pm/cli.py:262` — the criterion's third paragraph,
  *"`pm ledger record --grain` accepts `--tokens-total`, explicitly not a split"*, shipped nothing.

  paragraph with no code and no disposition.

- `E7` **MINOR** `install.py:346,354` vs `install.py:864` — a **successful** write returns

- `N1` **NIT** `tests/test_install.py:869,887` vs `:911` — the new `_block()` helper is the third

- `N2` **NIT** `install.py:349` + `core/apply.py:249-252` — a **dangling** symlink at
