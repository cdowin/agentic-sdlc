  * **P1 (MAJOR, REJECTED — and this is the honest half).** The ship criterion in the milestone brief
    reads *"No shipped file states what a verb does in prose that the verb does not generate."* Taken
    literally that is unachievable: grading an arbitrary sentence against a verb's behaviour is not a
    thing a static gate does. What landed is the **sharp, mechanisable slice** — a CLI call whose
    STATE the project never declared — which is the one of the five 0.5.0 sentences that this class
    of rule can actually catch. The other two are already covered elsewhere (`test_config_seed.py`
    for the seed-vs-default reversal; `test_install.py` for the `--force` cost claim). The grain file
    now says out loud which half is not covered, so the next reader does not assume it is.
  * **P2 (WARNING).** This gate had **no test module at all**, and the reason was structural:
    `REPO_ROOT` is captured at import, so `doc.relative_to(REPO_ROOT)` RAISES on a scratch tree and
    no case could build one. A `rel()` helper at the five reporting sites fixed it. Converting the
    constant itself belongs to `ft-the-vocabulary-is-constants-not-literals`, which owns that sweep.
  * **P3 (SUGGESTION).** The false-positive floor is a case, not a hope:
    `test_prose_that_is_not_an_invocation_is_not_read_as_one` puts four sentences that mention
    `story`, `reviewing`, `pm vocabulary` and `make unit` past the rule and asserts silence. A rule
    that fired on ordinary English gets switched off, and then it protects nothing.

## What bit

Pointed at this repo, the rule found **two** occurrences of `pm story reviewing <id>` — in
`.claude/agents/developer.md` and `.claude/rules/pm-execution.md`. Both read correctly TODAY: they
cite the call as an example of what exits 2. That is the milestone's own example, since corrected.
Both took the gate's existing `<!-- doc-scan:allow -->` escape at the SOURCE under `installables/`
and `pm/guidance/`, then re-installed — a copy edited in place is the invisible fork those verbs
exist to prevent.

**So the rule did not catch a live defect in this tree, and I am not claiming it did.** What it
catches is the shape, proven by planting it: `test_a_state_the_project_never_declared_is_a_FINDING`
is the sentence 0.5.0 shipped, and the gate reports it with the declared set named in the finding.

## Rule 9's edge, held

`test_a_project_that_declared_the_word_makes_it_legal` is the case that proves this READS rather than
DECIDES: declare `reviewing` in `[pm.states.story]` and the identical sentence stops being a finding.
Without it the rule would be a ban on one word wearing a vocabulary's clothes.
