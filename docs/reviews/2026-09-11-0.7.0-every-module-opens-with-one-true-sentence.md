# Audit — every module opens with one true sentence

`st-every-module-opens-with-one-true-sentence`, the last story of
`ft-the-module-says-what-it-does`. This is criterion 5's artifact: one row per module under
`src/agentic_sdlc/`, its opening sentence, whether the path says which layer it is in, and the
verdict. It is the AUDIT, not a gate — *is this sentence true of this module* is judgement, and a
test asserting it would be a second scoreboard. The cheap half is gated at
`tests/test_boundaries.py::EveryModuleSaysWhatItDoes`.

**50 modules, 47 with a docstring**; the three without are zero-length package markers, exempt by
name. Every number below was re-derived on 2026-09-11 and none was inherited from the brief.

## The two modules that made the same claim (criterion 5, graded hard)

At HEAD `repo/conveyor/__init__.py` opened *"conveyor — the belts: every check, then at most one
write (D12)"* and `repo/conveyor/driver.py` opened *"driver.py — the conveyor: every check, then
at most one write (D12)"*. Same claim, two spellings.

**`driver.py` is the wrong one.** A package docstring's job is to say what the package is and
assign each module its role, and `conveyor/__init__.py` does exactly that — it goes on to say
*"`driver` is the machine and the verb, `steps` the check lists"*. `driver.py` restated its
package's claim instead of taking the role the package had already given it, and it claimed to BE
the conveyor, which is the package's name, not a module's.

It now reads **`driver.py — the engine all four belts run on, and the verb that starts one.`** That
is the distinction that was missing: `driver.py` holds `Check`/`Result`/`Context`, `ask()`,
`run()`, `parse_flags()` and `main()`; `steps.py` holds the 50-odd check functions and the four
registries. The `(D12)` citation moved one sentence down, into the body paragraph that spells the
contract out, so nothing lost its pointer. This is not a reword of one claim into two claims — the
package still says *what the belts are*, and the module now says *what this module is*.

### A naming finding this story does NOT fix

**`verdict` names three different things.** `repo/pm/verdict.py` is the review-record block;
`driver.Verdicts` and `driver.verdict_row()` are a belt run's check results; `checks/pm._verdict()`
and `report._verdict` are a gate's PASS/FAIL line. All three are legitimate uses of the English
word and none is wrong on its own, but a reader who has met one meets the others expecting it.
Fixing it means renaming code, which this story may not do. Filed here rather than left unsaid
(rule 11); the cheapest fix is a word, not a module.

## The `print()` question (criterion 7), answered in writing

**Measured 2026-09-11 by AST** — `ast.Call` whose `func` is `Name('print')`, over all 50 modules:
**316 sites across 24 of 50 modules.** `grep -o 'print('` agrees exactly (316 / 24 files), so no
site is hiding in a docstring and none is an attribute call. The brief's 2026-09-10 reading was
307/23 and the dispatch's was 318/25; both are stale, and the number moved because `ledger.py` took
seven row renderers out of `cli.py` and `cite.py` arrived.

**The answer is NO RENDERER: printing at the edge is correct here.** A previous dispatch reached
the same answer in `st-the-pm-cli-helpers-find-a-home`'s close; this corroborates it from an
independent count and adds one argument it did not make.

1. **The distribution is not a missing abstraction, it is the shape of the tool.** 26 of the 50
   modules print NOTHING, and every one of those is a reader: all of `core/` bar one line, all of
   `pm/inventory`, `vocabulary`, `ledger`, `report`, `verdict`, `validate`, `rename`, `remote`,
   `templates`, all of `verify/cache` and `verify/rules`. The read/compute layer is already
   print-free. What prints is the CLI edge — a verb's `main()` and a gate's `run()` — which is
   where a command-line tool is supposed to print.
2. **A renderer would put a layer between the code and its contract.** Rule 6 makes every output
   line shape a published API, and those shapes are already pinned where they are produced:
   `tests/test_cli_surface.py` holds each read verb's declared columns, each gate's `--help` holds
   its own line grammar, and `check budget`'s docstring is asserted against by text. A renderer
   would move the line shape one hop away from the assertion that holds it, which makes it easier
   to change a consumer's `grep` by accident, not harder.
3. **The counts that look worst are not one thing.** `pm/cli.py`'s 71 sites are 24 sub-verbs, and
   `init.py`'s 39 are a step-by-step installation report whose whole value is that it prints as it
   goes. Neither is one renderable table; collapsing them would produce a `Renderer` with 24
   methods, which is the same code with a longer call path.
4. **The one argument this adds:** the counts are not stable enough to refactor from, and the
   package already has the read verb that answers the question. Three measurements four days apart
   gave 307, 316 and 318 because modules SPLIT, and every split moves prints without adding any.
   A renderer justified by "318 print sites" would be justified by a number that changes when
   nothing about the printing changes.

**What would change this answer:** a named defect a renderer would have prevented. There is none on
record. The nearest candidate is `check budget`'s docstring drifting from its behaviour
(`tests/test_check_budget.py:173`), and that was a DOCSTRING drifting, not a print — which is the
defect this story's gate now covers.

## Method and numbers

- **AST residual (criterion 8): ZERO.** Per module, `ast.parse` → delete the leading string
  expression of every `Module`/`ClassDef`/`FunctionDef`/`AsyncFunctionDef` → `ast.unparse` →
  compare character by character against the same transform over `git show HEAD:<path>`.
  **50 modules, 50 character-identical, 0 residual, 0 new.** The harness was probed both ways
  before it was believed: a docstring-only edit to `core/markdown.py` left it green, and changing
  `{0,3}` to `{0,4}` in one regex constant turned it red with the divergence printed at character
  72. No function body, constant or control-flow statement changed.
- **`src/` prose census, from `tests/test_prose_census.py` and never hand-rolled:**
  before `50 modules, 14,939 code, 4,839 prose, ratio 0.3239`;
  after `50 modules, 14,939 code, 4,838 prose, ratio 0.3239` (ceiling 0.3333).
  One prose line FEWER: three fragments joined onto one line, two split in two, and
  `changelog.py` lost the body sentence its new first line replaced.
- **The gate, shown failing on the unfixed code.** Its classifier over `git show HEAD:` sources
  reports 6 findings naming all six fragment modules by path, and 0 over the worktree. The
  collision half cannot fail on the real tree any more, so it was shown on a PLANTED one: a scratch
  copy of `src/` with `driver.py`'s first line replaced by its package's, run through the real test
  method with `SRC` patched, fails naming both paths. Two floors were probed too — a blinded
  `_opening_sentence` fails by name rather than passing, and a census of 27 modules that are all
  exempt fails on `MIN_SENTENCES` rather than passing over an empty population.
