## The findings

**R1 — MINOR — the release belt and the render verb disagree about the same field.**
`agentic-sdlc changelog ms-first` reports `1 unanswered` for a milestone whose own `changelog:` is
empty; `release 1.3.0` on the same tree reports
`ok: changelog-unreleased-nonempty — 1 entry/ies across 4 grain(s), 2 declined with none; every
closed grain answered`. Reproduce: in a scratch consumer give every child a `changelog:` and leave
the milestone's blank, then run both. Setting the milestone's sentence makes `changelog` print it as
a row and the tally go to `0 unanswered`, so the field is live and rendered — it is only the gating
reader that passes over it. The milestone is not yet in a `done` state when the check runs, so
*"every closed grain answered"* is literally true; the effect is that the one sentence a consumer
reads first can be silently absent from a release note the belt just blessed. On this tree, today,
that is exactly the state. Cheapest fix is the `pm set` in NEEDS YOU #1; the durable fix is for
`changelog-unreleased-nonempty` to ask the same question `changelog` asks.

**R2 — MINOR — the release note quotes a hand-written census that no longer re-derives.**
`pm/roadmap/features/ft-the-suite-is-measured-like-the-source.md:8` ships *"35 guards judged, 28
