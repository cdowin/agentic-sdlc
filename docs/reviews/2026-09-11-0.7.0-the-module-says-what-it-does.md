# Feature review — `ft-the-module-says-what-it-does`

Six stories, one changeset. Range `412301c..cc39494`, the feature's own commits being
`bb78a49 302ef1f 3267075 cdce244 2198600 f106d27`. Everything below was re-measured against
the tree at `cc39494`; nothing is inherited from a story's close.

## Verdict

**SHIP**, and it was SHIP-WITH-FIXES when this record was written. The three seams exist and each
one FAILS on a planted violation — 20 of 20 probes behaved. Rule 3 survives ten adversarial
encodings through both writers. One MAJOR: the by-id primitive's classifier graded five names while
the grain layer exposed three more that answer the same question, and eight live call sites in two
off-roster modules used them, so the ship criterion "no module outside the storage layer and that
roster passes a `Path` to ask what a grain says" was not true of the tree as shipped and the gate
was green over it.

**The MAJOR landed, and wider than this record asked for.** The fix is not three names added to a
tuple: `_document_addressed()` DERIVES the census — every module-level function in an owner that
hands a document read one of its own parameters, as a fixpoint, since `read_grain` reaches
`frontmatter.document` only through `doc_grain` — and asserts derived == graded ∪ excused in both
directions. The root cause was a hand-kept tuple beside a layer that grows, and the derivation
immediately found a SIXTH name this record missed (`inventory.header_of`, now excused by name: a
shared doc declares no `id:`, so there is nothing to ask it by).

`read_feature` is not graded because it no longer takes a path — `feature_view(cfg, feature:
Grain)` replaced it, which is strictly stronger than grading the signature. `Grain.section_defect`
closed the four `empty_section(view.path, …)` sites, `every_grain` closed the pool walk, and
`PATH_ADDRESSED_ROSTER` stayed at 3 with `ROSTER_OPENED_AT` unmoved. The dispositions below are
the current state of each finding, not the state at review time.

## Findings

### M1 — MAJOR — the by-id gate grades five names; the grain layer exposes eight

`tests/test_boundaries.py:193-201` grades `field_of`, `list_field_of`, `document`,
`sequence_defect` and `doc_grain`. Its own banner (`:196-199`) says grading `doc_grain` is what
stops *"every `field_of(p, k)` becomes `doc_grain(p).field(k)`, the gate goes green and nothing
changed."* The substitution works one name over. `inventory.read_grain` (`inventory.py:251-261`)
**is** `doc_grain(path, kind)` plus a `None` filter, three lines below it in the same module.

Reproduce — append to `src/agentic_sdlc/repo/dispatch.py`:

    def _status(cfg, p):
        return inventory.read_grain(cfg, p, 'story').field('status')

and run the 47 boundary cases: **0 failing.** Change `read_grain(cfg, p, 'story')` to
`doc_grain(p)` and `TheEngineAsksByIdNotByPath::test_no_module_off_the_roster_asks_a_path` fails
with `repo/dispatch.py:248: doc_grain(<path>) — the file-to-grain adapter…`. The same for
`inventory.empty_section(g.path, 'Close')`: 0 failing.

It is not only theoretical. Eight live off-roster sites pass a `Path` to ask what a grain says:

* `repo/checks/pm.py:304` — `read_grain(cfg, path, kind)` over a `pool_walk`. Legitimate (it
  really does hold the file it just enumerated) and **unregistered**: there is no `pool_grains`
  sibling, so this caller had nowhere else to go and the roster never learned about it.
* `repo/checks/pm.py:320,370` and `repo/pm/cli.py:1235,1325` — `read_feature(cfg, path)`.
* `repo/checks/pm.py:258,265,279,354` — `empty_section(view.path, …)` / `empty_section(story.path,
  …)`. These are the exact shape the primitive exists to kill: a `Grain`/view **in hand**, its
  `.path` handed to storage to ask what the document says, because `Grain` grew `field`,
  `list_field`, `declares` and `sequence_defect` but not `section`.

Cost of the fix is small — three names in a tuple, one `Grain.section(heading)`, one roster entry
or one `pool_grains(cfg, kind)` — which is why this is MAJOR and not CRITICAL. But the criterion
says the property holds and it does not, and the gate under it prints PASS: rule 4's first sin at
the gate, which this repo's own record says it has shipped four times.

### F2 — MINOR — both seams pin the owner's import ALIAS by convention, not by test

`FRONTMATTER_OWNER = 'frontmatter'` (`tests/test_boundaries.py:159`) and
`GRAIN_LAYER_OWNER = 'inventory'` (`:187`) are matched as receiver NAMES by
`_path_addressed_sites`. Rename the import and the gate is blind. Append to
`src/agentic_sdlc/repo/dispatch.py`:

    from agentic_sdlc.core import frontmatter as fm

    def s(p):
        return fm.field_of(p, 'status')

Every boundary case passes. The bare spelling (`from …frontmatter import field_of` then
`field_of(p, k)`) IS caught, because the reader accepts an empty receiver; only the aliased module
is not. One case — no module binds `agentic_sdlc.core.frontmatter` or
`agentic_sdlc.repo.pm.inventory` under a name other than the declared owner — closes it, and
`_import_bindings` already yields what it needs.

### F3 — MINOR — criterion 5's "forbids its internals being reached" is not what ships

`OneStorage` forbids re-BINDING one of the 8 names in `FRONTMATTER_INTERNALS`
(`tests/test_boundaries.py:166`) — that is a ban on a SECOND IMPLEMENTATION, and the file's own
comment says so. It does not forbid reaching them. 13 live sites do:
`repo/pm/rename.py:53,76,77,96,110,111,119`, `repo/checks/grain_shape.py:181,192`,
`repo/pm/inventory.py:801,977,982,1409,1475` — `_split`, `_fence_bounds`, `_LIST_ITEM`, `_FENCE`,
`_without_trailing_comment`.

Every one is byte-identical at `412301c`, so the feature introduced none of them, and because they
reach the OWNER they inherit its preservation rules — the rule-3 risk is low. The finding is that
the ship criterion claims a property the shipped gate does not hold, and the close record should
say which half landed. `rename.rewritten`/`reidentified` (`rename.py:72-127`) is the one that
matters: it assembles a document rewrite out of the owner's private parts, which is a fourth
frontmatter writer living outside the module that claims to be the only one.

### F4 — NIT — the rename write path never invalidates the document cache

`repo/pm/rename.py:232` stages through `out.plan.overwrite(path, swept, …)`, not
`frontmatter.write_raw`, and `forget_document` is called from `write_raw` alone
(`core/frontmatter.py:43`). A renamed document's parse stays in `_DOCUMENTS`; only
`_stamp`'s `(st_mtime_ns, st_size, st_ino, st_dev)` comparison saves it, and a rename between two
ids of the same length changes neither size nor inode. On a filesystem with coarse mtime
granularity a same-process read after the write serves bytes that moved on — rule 4's second sin
wearing a speedup, which is exactly what the cache's own banner (`core/frontmatter.py:79-82`)
warns about. Pre-existing and unchanged here. Cheapest fix is `apply.Plan` calling
`forget_document` per overwritten path.

### F5 — NIT — two one-line private aliases survived, recorded

`_plan_path` (`repo/pm/cli.py:2848`, 4 call sites) is `return inventory.releases_file(cfg)`;
`_ledger_of` (`:678`, 3 call sites) is `return ledger.ledger_of_grain(cfg, gid)`. The helpers
story identified both as re-exports by its own criterion 5 and deliberately left them, fixing the
deletion list at one. Recorded here so the next pass does not re-discover them.

### F6 — NIT — the `print()` answer's supporting sentence overstates its census

The conclusion (NO RENDERER) is right and I re-derived the number. But *"the compute layer is
already print-free and what prints is the CLI edge"* is stronger than the measurement: 8 of 50
modules both read the tree and print — `core/project.py:46` (a `core/` primitive, on stderr),
`repo/conveyor/steps.py:421`, plus `pm/cli.py`, `pm/skills.py`, `checks/grain_shape.py`,
`checks/doc.py`, `checks/shell.py`, `checks/hooks.py`. Every one is a single error or warning line
at an edge rather than a renderer, so nothing follows from it — but the sentence as written would
not survive the next person who runs the census.

### F7 — NIT — 15 cases against a declared budget of 4

`ft-the-module-says-what-it-does`'s `## Proof budget` says `cases: 4`. New test methods per
