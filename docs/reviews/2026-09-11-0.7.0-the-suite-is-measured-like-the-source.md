## Findings

**M1 (MAJOR, open) — `tests/test_prose_census.py:373` `test_a_new_module_at_this_repos_own_ratio_fits_under_the_ceiling`
is the main ceiling assertion plus rounding noise, and two committed claims about it are false.**

Adding a module documented at the root's OWN prose fraction leaves the ratio algebraically
unchanged: with `f = p/(p+c)`, `(p + tf) / (c + t(1-f)) = p/c` exactly. So the case cannot fail
while its sibling passes. Measured, three ways:

  * its threshold differs from the ceiling assertion by **one prose line out of 830** on `tests/`
    and by **zero** on `src/` (median module 217 lines; both red at +208);
  * a ceiling of `0.5131` — **2.6 prose lines of room in the whole suite**, no room for any new
    module — is GREEN on both cases. It only reddens once the ceiling is BELOW the measured ratio,
    where the main assertion reddens too;
  * the scenario its judgement names is green: plant a new module with 900 prose lines (both cases
    RED), then cut 80 comment lines from `test_boundaries.py`, a file that did not grow → **both
    cases GREEN** (ratio 0.55314 → 0.54957).

So two statements in the changeset are false, not merely stale:

  * `tests/test_prose_census.py:56` — *"874 prose lines of room … enough to write a new test module
    documented the way this suite documents, which `test_a_new_module…` asserts for both roots"*.
    The 874 (830 today) re-derives; the clause that the case asserts it does not.
  * `tests/test_guard_corpus.py:189` — *"Load-bearing INVERTED: it is the only thing that can fail
    when a ceiling is met by trimming a file that was not the one that grew"*, repeated as the
    single *"1 load-bearing inverted"* in `st-a-source-shaped-guard-names-what-it-protects`'s close.
    Disproved by the trim above.

Cheapest fix: document the number in LINES and assert it —
`assert root.ceiling * code - prose >= typical`, with `typical` the median module's PROSE — or plant
the new module at a rate above the average (the 75th-percentile module's prose fraction), not at it.
Either way the two prose claims come down to what the code does.

    commands: the three probes are recorded in this review's scratch harness; each is ~30 lines of
    `test_prose_census` calls against `replace(root, path=<scratch copy of tests/>)` — the same
    substitution `test_a_moved_or_empty_root_fails_instead_of_passing_over_nothing` already uses.
    Worth landing as a case in `test_prose_census.py`: *the headroom clause fails when the ceiling
    has no headroom.* Today nothing does.

**M2 (MINOR, open) — the partition desyncs from the tokenizer on U+2028 / form feed; `tests/` code
is overstated by 19 lines, in the fail-OPEN direction.** `prose_and_code` numbers lines with
`source.splitlines()`, which breaks on `\v \f \x1c-\x1e \x85 U+2028 U+2029`; `tokenize` and `ast`
break only on `\n \r\n \r`. After the first such character every later line number is shifted, so
blanks and docstring lines are misattributed for the rest of the file. Minimal repro: two modules
identical but for one `U+2028` inside a string literal report `code=3` and `code=4`. Live: 4 such
characters in 3 modules (`test_conveyor_deviation.py`, `test_pm_ledger_record.py`,
`test_pm_verbs.py` — they are fixtures for a line-separator bug) cost
`test_conveyor_deviation.py` 12 phantom code lines alone; tree-wide, shipped 22,412 vs
tokenizer-aligned 22,393, ratio 0.5130 vs 0.5134. One-line fix: `lines = source.split('\n')`
(dropping a trailing empty). The rest of the partition is exact — every line lands in exactly one
of prose/blank/code on all 112 modules, `code` never negative, the bug `b89a80c` fixed stays fixed
(`"""doc\n\nmore\n"""\nx = 1` → prose 4, code 1), the mixed line and the EOF docstring without a
trailing newline behave as documented.

**M4 (MINOR, open; OUTSIDE this changeset — file a bug) — two concurrent `make check` runs make one
verdict line lie, reproduced first try.** `GDK_SUM_CHECKS`
(`src/agentic_sdlc/repo/installables/Makefile.devkit:49`) greps the census out of the per-gate
transcript, whose slot is keyed by gate name only, so concurrent runs in one checkout share it:

    $ (make check &) ; (make check &) ; wait
    [CHECK] 5 check(s) PASS — full log: .gate-reports/check.log
    [CHECK] 10 check(s) PASS — full log: .gate-reports/check.log     # roster is 5

Both exit 0; only the census lies, and that census is what feeds `GDK_GATE_CENSUS` and the ledger
row. `gdk_gate.sh` already names the class for the sidecar (*"The transcript files collide the same
way … both want a per-run directory"*) and fixed only the sidecar by PID. This is rule 4's first sin
in a shipped installable and it contradicts hard rule 2's *"safe anywhere, any time, in parallel"*.
Introduced at 0.2.0 (`29c7620`), untouched here — so it does not block this feature.

**M5 (MINOR, open; OUTSIDE this changeset) — `test_how_long_never_has_been_true_is_read_off_the_oldest_row`
is clock-coupled, and its whole tolerance is `1 − frac(now)` seconds.** `hours_ago()`
(`tests/test_pm_gate.py:1079`) formats with `ledger.TS_FORMAT = '%Y-%m-%dT%H:%M:%SZ'`, which drops
the fraction, so the row is already `frac(now)` seconds older than the exact 40 d;
`_recording_span` floors the elapsed with `int()` and `human_duration` renders the leftover as a
second unit — `human_duration(3456001) == '40d 1s'` — while the case asserts the literal `40d`. The
case runs in-process (`run_gate` → `pm_check.run()`, 0.01 s), so it needs a stall of
`1 − frac(now)` s to fail: rare idle, routine on a machine running six agents. Not the shipped
renderer (which is correct) and not this changeset (the case and the helper date from 0.5.0). Fix:
assert the day component (`never in the 40d` as a regex allowing a trailing unit), or build the
fixture from a floored `now`.

**N7 (NIT, open) — a blank line inside a non-docstring string literal counts as BLANK, not code.**
222 such lines under `tests/`, 50 under `src/`; counting them as code (a `USAGE` string is code by
this module's own argument) reads 0.5080 / 0.3181 instead of 0.5130 / 0.3192 — i.e. the shipped
census is STRICTER. No line is double-counted, so it is a classification judgement, not a leak —
but the mixed code-and-comment line is documented and this one is not.

**N8 (NIT, open) — `cite` loses a tracked file whose name is not ASCII, into the "binary, or gone"
bucket.** `git ls-files` quotes such paths (`"caf\303\251.md"`), so `root / rel` does not exist and
the file is counted as UNREADABLE: disclosed, never silent, but mis-attributed and its citations
dropped. Inherited from `core.project.git_lines`; `cite` is a new caller. Fix: `ls-files -z` and
split on NUL, or `git -c core.quotePath=false`.

**Q9 (QUESTION, open) — what shape-only `PROTECTS` admits, probed.** Through the real roster reader,
a judgement naming the WRONG sin, one that is the exact opposite of the truth, one whose property is
nonsense, and a `second scoreboard` citing a real but unrelated case (or the guard itself) are all
ACCEPTED; only a missing `PROTECTS`, a non-pair, a verdict with neither opening word, a
`load-bearing` naming no sin, and a dangling id are refused. That is the declared limit (*"The SHAPE
is graded and the truth is not"*) and I am not asking for truth to be gated — M1 is the one
falsifiable judgement in the set and it is false. Worth noting beside it: **24 of 24 class
judgements open `load-bearing`, none opens `second scoreboard`**, while the story's own close says
two CASES are second scoreboards now. A verdict word nothing in the roster ever uses is a branch
only the planted corpus exercises.

`exit 0`, zero rows, `0 citation(s) … across 2 tracked text file(s)` (the census IS disclosed, so

a tree whose `.git` is a FILE (this review ran in one). `--rule 4` → exit 2 naming the grep.

function-call tier (no spawn) and cover the zero census, the skip, the help columns and the exit-2
