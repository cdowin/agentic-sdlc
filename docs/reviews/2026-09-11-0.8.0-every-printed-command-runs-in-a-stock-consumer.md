## Findings

**M1 (MAJOR) — `src/agentic_sdlc/repo/pm/arrive.py:417` `_subject_arg` makes a TREE value a bare
`Slot`, so a pasted `ready:` line runs arbitrary shell and make exits 0.** `crossing` (`:410-411`)
passes `inventory.milestone_version()`, the raw `version:` field with no validation, through
`_subject_arg`, which turns any value shaped `<…>` into `vehicle.Slot`. `Slot` is rendered unquoted
("Never a value", `vehicle.py:29`). Input: `make pm ARGS='set ms-first-light version '"'"'<x; touch
PWNED4 #>'"'"''`, then the move that makes the milestone ready. Output: `ready: make sdlc
ARGS='release <x; touch PWNED4 #>'`. Pasted as printed, `release` refuses, `touch PWNED4` runs, `#`
comments out the rest, and make exits **0**. That is both sins in one line. `answer_argv` (`:143`)
does the same with a bare `<…>` word from `[pm.arrive.*] answers` (config, so the risk is lower).
`test_vehicle.py` cannot see this: `_resolved` puts plain strings in every computed argument, never
a `Slot`. Fix: `_subject_of` returns `vehicle.Slot(noun[2])` for its placeholder fallback and a
plain string otherwise, and the `<…>` shape test goes. `answer_argv` makes a `Slot` only for
`^<[\w .-]+>$`. One unit case: a milestone whose version is `<x; touch p #>` renders a line where
`argv_of` returns `['release', '<x; touch p #>']`.

**M2 (MAJOR) — `src/agentic_sdlc/repo/pm/cli.py:1132, 1753, 1758, 1760, 2105, 3514` spell the
program as `{PROG}` (= `'agentic-sdlc pm'`), and the census is blind to it.** In the consumer:
`make pm ARGS='set st-s-one status done'` prints ``run `agentic-sdlc pm story done st-s-one` ``.
`set … order x` prints ``run `agentic-sdlc pm add <parent-id> <child-id> […]` (or `agentic-sdlc pm
remove`) ``. A flag-looking name prints ``agentic-sdlc pm new story <feature-id> <slug> <name...>``.
Every per-verb usage error ends ``"`agentic-sdlc pm --help` prints every verb"`` (7 times in the
sweep). Each is "run" plus a command that is `command not found` in a stock consumer, which is #36's
shape exactly. The census (`tests/test_install.py:2507, 2681`) reads source LINES for the literal
name. `PROGRAM_OUT` exempts only `PROG`'s assignment, so none of its uses is read. A planted
``f'run `agentic-sdlc '`` / ``f'close story {gid}`'`` split across two lines passes too (probe:
`citation_census` over a scratch corpus found only the assignment). So the gate prints PASS over
rendered lines no stock consumer can run. Fix: send the five sites through `vehicle.command('pm',
…)`. Have the census read string VALUES off the AST instead of lines: implicit concatenation comes
back joined, and a `FormattedValue` naming a module constant that starts with the program is
substituted with it. The two blind shapes then go into its planted corpus.

**M3 (MINOR) — `src/agentic_sdlc/repo/conveyor/steps.py:342, 1786-1797`: belt verdicts and the
installed protocol spell the program bare, under an OUT class the story did not name.**
`_own_verdict` prints "[story] unverifiable: story-verified: `agentic-sdlc verify --story` exited
2". The installed `docs/sdlc-protocol.md` puts 7 `agentic-sdlc …` commands under a column headed
**runs**. Someone reproducing a red check pastes that and gets `command not found`. The census
exempts them as `record` (`tests/test_install.py:2523-2533`), which is not among the M3 amendment's
OUT classes. Its stated reason, "the belt runs its own CLI in-process", is also wrong: `_own_cli`
spawns `python -m agentic_sdlc.cli`. Fix: render `spoken` and the protocol's `runs` cell through
`vehicle.command`, and keep the ledger's `ran` value as it is.

**M4 (MINOR) — `src/agentic_sdlc/repo/installables/Makefile.devkit:44` `unexport ARGS` applies to
every recipe, not just the verb's.** A consumer target `envargs: ; @echo "env=[$${ARGS-unset}]"`
run as `make envargs ARGS=hello` prints `env=[hello]` under the v0.7.0 include and `env=[unset]`
under this one. A script called from a consumer's recipe that reads `$ARGS` now gets nothing and
says nothing about it. Fix: drop the global `unexport`, and start the `pm` and `sdlc` recipes with
`unset ARGS;` (the leak case in `test_makefile_include.py` still holds). Or keep it, and name it in
the changelog.

**M5 (MINOR) — the free-text template the D12 hint (`checks/pm.py:1117`), the changelog refusal
(`steps.py:839`) and README.md:368 render: `'"'"'<sentence>'"'"'`.** Typing a sentence in place of
`<sentence>`, the obvious edit, loses PAIRED apostrophes at exit 0. `the 'costs' key` is written as
`the costs key`. One apostrophe fails loudly. An apostrophe followed by a backtick span unquotes
that span in the operator's shell, so it runs. This kit's own changelog sentences have both, e.g.
``"`agent-worktree.sh`'s `FALLBACK_BASE` …"``. Fix: a clause beside each template saying a `'` in the
sentence is typed `'"'"'`. That is words, not a new capability.

**M6 (MINOR) — `src/agentic_sdlc/repo/cite.py:178` renders `make sdlc ARGS='cite --sites' | grep
-P "^4\t"`.** BSD grep, the one on this machine, has no `-P`. Pasted, it gives grep's usage and exit
2, a `BrokenPipeError` traceback from the verb, and `make: *** [sdlc] Error 120`. The `grep -P`
predates this feature, but the feature re-rendered the line under a "runs as printed" criterion.
Fix: `| awk -F'\t' '$1 == 4'`.

**M7 (MINOR, outside the changeset: in v0.7.0 since `dbf6506`) — a pasted arrival-fork answer
records nothing.** In `pm/cli.py:769-772`, `answered = bool(said) or …` makes `not answered` false
exactly when an answer is given, so a no-op move with an answer writes no disposition row. The
docstring says "With an answer it still records: that is how a skipped fork is answered". Input:
arrive at `feature reviewing ft-delta`, then paste the rendered fork `make pm ARGS='feature
reviewing ft-delta --skip review '"'"'…'"'"''`. Output: "already reviewing (no-op)", exit 0, and
the last disposition row is still `"answer":"none"` (the direct `$DEVKIT pm …` call does the same).
Fix: `if moved or skipped or said or not answered:`. File it as a bug.

**N8 (NIT) — `src/agentic_sdlc/repo/vehicle.py:38`: a newline in an argument passes the `shlex`
round trip, but make splits the recipe at it.** `vehicle.command('pm','set','st-s-two','changelog',
'line one\nline two')` pasted gives `bash: -c: line 1: syntax error: unexpected end of file`, `Error
2`. It fails loudly, and no rendered value carries a newline today. `HOSTILE`
(`tests/test_vehicle.py:26`) has no `\n`. Fix: `command()` raises on a newline, and `\n` joins
`HOSTILE`.
