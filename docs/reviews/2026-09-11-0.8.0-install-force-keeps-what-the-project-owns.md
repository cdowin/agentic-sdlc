## Findings

**C1 (CRITICAL, open) — `install.py:534-546` `_markdown_block`: a project-config fence with no
closing ```` ``` ```` is closed by a LATER fence's close, past the end of its section.** Once the
fence opens, the scan stops at nothing but `^```[ \t]*$`; `^## ` is checked only before the fence
opens. `reviewer.md`, `milestone-reviewer.md` and `simplifier.md` each carry a second fence below
the section.

*Input:* `reviewer.md` with the fence edited, its close deleted, and one stale kit line in
`## Checklist`, then `install-agents --force .claude/agents/reviewer.md`.

*Output:* `wrote .claude/agents/reviewer.md — kept its project-config header byte for byte; the
rest is the packaged file`. The file is 198 lines against the packaged 127, holds `## Checklist`
twice, and keeps the stale line. The carried span was `(39, 119)`; the packaged span is
`(39, 48)`. From then on the second `--force` says `differs ONLY inside its project-config header,
which --force keeps — nothing to write`, and `installables-current` passes with
`27 installed file(s) are current with 0.7.0`. So the corrupting write reports itself as clean,
and every later reader calls the file current. `carry_config_block`'s docstring (`:604`) promises
the opposite ("a block with no closing marker … the file is replaced whole"); that only holds
when no later bare fence exists.

*Fix:* in `_markdown_block`, return None if a `^## ` or another ```` ```text ```` line comes
before the close. Add a HOSTILE row, "a markdown fence left open, a later fence closed". The
existing row `'a markdown fence left open'` (`tests/test_install.py:1906`) cannot catch this,
because `MD_STOCK` has no later fence.

**M2 (MAJOR, open) — `install.py:1070` compares a claim by exact string, and `ours_of`
(`steps.py:587`) accepts spellings that match nothing. The installer never names such a claim;
only the belt's `_claim_clause` does.** It holds the close because the Ship criterion's first
sentence fails for a claim the tool accepted without complaint, and the belt only names it after
`--force` has already written.

*Input:* `[adopt] ours = ["<spelling>"]` with an edited `architect.md`, then
`install-agents --force`, once for each of 8 spellings:

- `./.claude/agents/architect.md`
- `.claude/agents`
- `.claude/agents/`
- `.claude/agents/*.md`
- `.claude//agents/architect.md`
- `architect.md/`, the full path with a trailing slash
- ` .claude/…`, the full path with a leading space
- `claude/agents/architect.md`

*Output:* every run exits 0 and prints the plain `[install] wrote .claude/agents/architect.md`.
The file is overwritten, and no line anywhere mentions the claim. (A claim with `..` exits 2.) The
same spellings passed as ARGUMENTS exit 2 (`REFUSED_PATHS`), so the two path grammars disagree,
and the one that is silent is the claim.

*Fix:* the installer prints the belt's unplanned clause, i.e. the claims that match no destination
in any plan. It prints it on every run, `--diff` included, so it is visible before `--force`. Add
the spellings to `REFUSED_CLAIMS`' neighbour as a "named, not honoured" row.

**M3 (MAJOR, open) — `tests/test_conveyor_adopt.py:440-446`: `make test` is red at `90076b7`.**
`test_a_claimed_file_is_named_on_every_run_and_hides_no_other_drift` claims `Makefile.devkit`
before its first `install.main('install-gates', [])`. That run now leaves the absent claimed file
unwritten, which is the behaviour `test_force_leaves_a_claimed_file_alone…` pins on purpose. Then
`fork()` reads a missing file and raises `FileNotFoundError`. The module spawns, so it is in the
shell tier, and `make unit` is green without it. The builder ran the story rung, not the feature
rung.

*Fix:* amend the test. Either install before writing the claim, or name the paths:
`install.main('install-gates', [GATE_MK, GATE_LIB_REL])`.

**M4 (MINOR, open) — `install.py:523-531` `_shell_block`: the same class as C1, in the hook
grammar.** The header's close is the next `# -----` line anywhere in the file.

*Input:* `pre-push` with its closing rule deleted, a rule line added lower down, the header edited
and a stale line added, then `install-hooks --force tools/hooks/pre-push`.

*Output:* a file of 126 lines against the packaged 72, with `REPO_ROOT=` twice, and the line says
it kept the header. This is MINOR rather than CRITICAL because every stock hook carries exactly
one rule line, so it takes two edits to trigger.

*Fix:* treat a shell block as unterminated if its close does not come before the first line the
header grammar does not own. Or, cheaper, refuse the carry when the kept span is longer than the
packaged span plus the names it adds.

**M5 (MINOR, open) — `install.py:494` + `:662`: a CRLF file's carried block is written LF, and the
line still says "byte for byte".**

*Input:* `pm-operator.md` on disk as CRLF, fence edited, then `--force`.

*Output:* the block's bytes are no longer identical (CRLF before, LF after). The Ship criterion
says "byte-identical, or the story's decision says why not", and no decision says why. The root
cause predates this feature: `read_text` uses universal newlines, so a CRLF copy of the stock
file already reads `already current`. What this feature adds is the words "byte for byte".

*Fix:* say "line for line", or record the decision. Do not widen the read.

**M6 (MINOR, open) — `steps.py:960-962`: `installables-current` passes over a kept header that
lacks a stock name, although the install line names that as a fail-open hazard.**

*Input:* `cc-stop-gate.sh` without `GATE_STATIC=`, then `install-hooks --force`.

*Output:* the install line says `; the kept header LACKS \`GATE_STATIC=\`, which the packaged one
declares — copy it in from --diff`. The belt's verdict is `header-only`, and the check passes with
`27 installed file(s) are current`. The self-host test already refuses this for this repo
(`test_this_repo_carries_the_roles_it_runs_byte_current`). A consumer only hears it once, at the
write (rule 11).

*Fix:* append `install.kept_lacks(text, body)` to the HEADER_ONLY verdict's detail.

**M7 (MINOR, open) — `pm/skills.py:308`: `pm install-skills --force` overwrites a file that
`[adopt] ours` claims.**

*Input:* claim `.claude/rules/pm-execution.md` and edit it, then `pm install-skills --force`.

*Output:* `[install] wrote .claude/rules/pm-execution.md`, and the edit is gone. `_installable_drift`
grades all SIX installers and treats that file as claimable, so the belt and the sixth installer
disagree, which is exactly what story 1 criterion 4 exists to prevent. The feature scoped
`install-*`. Raise this to MAJOR if the milestone counts `install-skills` as an installer.

*Fix:* `cmd_install_skills` asks `ours_of` the same way `install.main` does.

**N8 (NIT, open)** — story 3 criterion 3 says "names changelog-writer.md as withdrawn in 0.6.0".
The line says `withdrawn between v0.4.0 and v0.7.0`, and the test pins the span. Either reword the
criterion or add the row's version to the line.

**N9 (NIT, open)** — `install.py:967-975`: `SINCE_MAX = 128` restates `driver.MAX_VERSION` (the
comment itself says it is "the one the belts put on a version"), and `shown()`/`SHOWN_MAX` restate
`driver._quote`/`QUOTE_LIMIT`. Import them rather than copy them.

**N10 (NIT, open)** — rule 6: `wrote {rel} — kept …` extends a line that used to be exact. The
suite's own idiom `line.split('wrote ', 1)[1]` (in `test_a_new_hook_lands…`) would read the tail
as the path. Also, the USAGE's "EVERY destination gets one `[install]` line" now means every NAMED
destination when paths are given. Neither is wrong; both are contract that a consumer greps.
