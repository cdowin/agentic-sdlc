# 0.8.0 spec review: ms-a-consumer-can-take-the-bump (scout pass)

**Verdict: HOLD.** Phase A can keep going, with one exception: the in-flight header story needs
Chris's decision on B2 before it lands. Phase B and phase C are not ready to execute yet. Two
blockers and two criticals each ask for a change to the grain text, not a redesign. Once those
edits are made, B and C become SHIP-WITH-FIXES.

Scope: the milestone, its decisions and handoff, 5 features, the stories for phases B and C, the 3
bound bugs, and the two feature decision files. Every file:line citation below was read at `HEAD`
(`1fcdabf`) with `git show`, so the builders' uncommitted edits did not affect it. I checked three
claims by running a scratch Makefile under GNU Make 3.81, the documented floor: the exit-code
collapse, the `$` expansion, and the ARGS leak.

## Blockers

**B1 BLOCKER, `st-a-roster-that-omits-a-stock-on-rule-says-so`, AC3 and AC4.** The story says to
refuse a retired field "at exit 2 as the 0.6.0 bug grain promised". 0.6.0 made the opposite
decision on purpose. `ms-the-rule-reaches-the-work-decisions.md` D2 says "a retired FIELD is drift,
not a config error… ships as a D11 DRIFT finding at exit 1", on the grounds of rule 9. D2 also
names the cost: exit 2 leaves the whole of `check pm` unrunnable. That is literal at HEAD, because
the config-error paths return 2 before any rule runs (`checks/pm.py:109`, `:122`). On the #19
consumer, 235 retired fields would hide the other findings entirely. **Fix:** move the
`RETIRED_FIELDS` loop (`checks/pm.py:1015-1021`) out of `_containment` so it runs ungated, next to
`stray_documents` (`:146-152`, "Never gated by `checks`"). It stays **exit 1**. AC4's probe should
expect exit 1 plus the omitted-rules line. The docstring's D11 line (`:12-13`) moves with the
loop. If exit 2 really is wanted, it needs a new `pm decide` that overrules D2.

**B2 BLOCKER, `st-the-project-config-header-survives-force` (in flight) against
`ft-every-printed-command-runs-in-a-stock-consumer`.** The markdown block grammar
(`install.py:486-487`, closed by `^## `) makes lines 15 to about 38 of every agent brief belong to
the project. That range holds more than config. It includes the kit's first instruction, "Run
`agentic-sdlc dispatch …`", in 10 briefs (line 16; line 33 in `reviewer.md`), plus
`doc-hygiene.md:23`, each brief's role intro paragraph, and the `<!-- BEGIN role-verbs -->` marker.
I measured the spans for all 17 installables. Under feature D1's carry, the phase-C rewrite of
those lines can never reach an existing consumer, whether or not they edited the block. That makes
the ship criterion's bullet 1 (never `command not found`, and #36's "sharpest case" is
`pm-operator.md:16`) contradict bullet 2 (the header stays byte-identical). **Fix (decision
needed):** pick one.
- **(a)** Narrow the markdown grammar to the ```` ```text ```` pointer fence, so the dispatch
  sentence and the intro become kit-owned. Record it with `pm decide`, because it widens the bytes
  `installables-current` grades.
- **(b)** Keep the span. When a carry leaves a block that differs from the packaged block, print one
  line saying so and pointing at `--diff`. Then reword the ship criterion so that a printed remedy
  counts.

## Criticals

**C1 CRITICAL, the vehicle's bootstrap order (both vehicle stories).** A consumer coming from 0.4
to 0.7 has a `Makefile.devkit` with no `sdlc` target until `install-gates --force` runs. Every
rendered `make sdlc ARGS="…"` fails with `No rule to make target 'sdlc'` until then. That includes
the `installables-current` remedy that `adopt` prints. There is a second failure in the same
window. `check doc`'s default scope includes `.claude/rules/*.md` and `.claude/agents/*.md`
(`doc.py:27`), and its make-target rule (`:132-141`) turns red on every swept citation if the rules
and agents were reinstalled before the gates. **Fix:** the commands that write `Makefile.devkit`
(`install-gates`, and `init`'s next steps) render in the pinned uvx form,
`uvx --from "git+…@v{__version__}" agentic-sdlc install-gates --force`, reading the tool's own
version with no inference. `adopt` names `install-gates` first. Add a probe: a scratch consumer with
a 0.7.0 `Makefile.devkit`.

**C2 CRITICAL, `check doc` goes silent after the sweep, and no story owns it.** `_STATUS_FORM`
(`doc.py:173-174`) matches only `(agentic-sdlc\s+)?pm\s+<kind>`. After phase C, the shipped spans
read `make pm ARGS="feature reviewing <id>"` or `make sdlc ARGS="pm feature …"`, and the regex
matches neither. So the #26 fix and the 0.6.0 status-form rule both stop seeing every shipped
citation, and the gate prints PASS over drift. **Fix:** add an AC to
`st-every-shipped-citation-resolves-through-the-stock-wiring` that makes `_STATUS_FORM` accept
both vehicle spellings. Probe: plant `make pm ARGS="feature reviewing x"` with no `reviewing` state
declared, and the gate must FAIL.

## Majors

**M1 MAJOR, the vehicle loses rule 6's exit codes (feature D1, ship criterion).** Make turns any
nonzero recipe exit into 2. I probed it: the verb exits 1 and make exits 2. The milestone's "exited
0 or 1" therefore cannot be measured through the vehicle. The 0/1 predicate on `pm ready-for` is
lost, and so is the dispatch preamble's own "EXIT CODES ARE CONTRACT" line (`dispatch.py:197-198`).
**Fix:** record this in D1 as a known cost. Have the `sdlc`/`pm` help and the preamble say that the
verb's code appears in make's `Error N` line. Reword the criterion to "the verb exited 0 or 1, and
make never said `No rule` or `command not found`".

**M2 MAJOR, `make sdlc` changes arguments without saying so (story 1).** I probed three cases:
- `ARGS='pm set x changelog "costs $5"'` writes `costs ` and exits 0. That is rule 4's second sin,
  a write that looks legitimate and is not.
- Command-line `ARGS` is exported, through both MAKEFLAGS and the environment, into every sub-make
  that `verify`/`close`/`release` spawn. A consumer target that uses `$(ARGS)` receives
  `close story X`.
- Nested double quotes in rendered hints break. The D12 hint carries `"<sentence>"`.

**Fix:** the recipe uses `$(value ARGS)`, adds `unexport ARGS`, and runs with `MAKEFLAGS=`. I
probed that combination and it stops the leak. Rendered free-text lines use outer single quotes,
following the precedent at `pm/cli.py:2074`. Add a unit case that round-trips every rendered
vehicle line through `shlex`.

**M3 MAJOR, the vehicle census scope is undefined.** At HEAD there are 142
`agentic-sdlc <verb>` strings across 19 `.py` files: 62 backticked hints, 49 in help bodies, 23
error prefixes and 8 `usage:` synopses. Story 1 hands the census to story 2, and story 2 says
"shipped text file". The shipped prose also has unbackticked commands:
`sdlc-template.md:10-13` (the first lines of the rendered protocol) and `doc-hygiene.md:23`. There
are 148 citations in total, 111 of them backticked, and the existing regex is backtick-bound
(`tests/test_install.py:1809`). Once the sweep lands, both existing role-verb tests match nothing,
so they need rewriting, not just amending. **Fix:** name which classes are in scope (hints,
`next:`, RECORDING, STATIC GATES, `init` next steps, fenced and indented blocks) and which are out
(`usage:`, `agentic-sdlc <verb>:` prefixes, GENERATED headers).

**M4 MAJOR, phase-B collisions the handoff does not serialize.** The gate-help bug edits the
docstring of `checks/pm.py`, which #19, #30 and the phase-C hints also touch. The release bug
(`steps.py:818-850`) and the bump bug (`steps.py:1319-1325`) both edit `steps.py`, which the
phase-A words builder is editing now. The handoff lists phase B as one parallel set. **Fix:** chain
`checks/pm.py` as #19 → #30 → gate-help. Chain `steps.py` as release → bump, after phase A's
`steps.py` slice commits.

**M5 MAJOR, the gate-help bug's premise is wrong.** The bug says the roster is correct and only the
opening line undersells it. In fact the "default:" roster on that page (`checks/pm.py:4-5`) is
false. It leaves out D12 and lists U2–U5, which are off by default: they are gated at `:488`,
`:713`, `:779` and `:841`, and `DEFAULT_CHECKS` at `vocabulary.py:206-207` lacks them. The seed
(`project-devkit.toml:150`) agrees with the code. The comment at `vocabulary.py:210-213` ("Both
are STOCK-ON") is also false for U2. The proposed test compares against `KNOWN_RULES`, which does
not exist. **Fix:** correct the default roster. Test the stated default against `DEFAULT_CHECKS`
and the enumerated rules against `KNOWN_CHECKS`. Have #19 AC2 define "stock-on" as
`DEFAULT_CHECKS` in so many words.

**M6 MAJOR, the bump-belt bug prices two options and misses the existing third.**
`[adopt.commands] checks-pass` already overrides the command (`steps.py:1321-1323`, with
`commands_for` at `:466`, documented at `README.md:275-279`). The cheapest rule-11 fix is for the
`ok:` detail to name what it did NOT run: the `[gates] extra` targets, which it already reads
(`steps.py:1052`), and the off `KNOWN_GATES`. It should also name the override. **Fix:** add this
as the option the bug recommends. Reject reading a make file (rule 9).

**M7 MAJOR, all three bound bugs carry `changelog: none`, and each one changes what a consumer
sees.** `release` would exit 1 on a tree it passed, a `--help` line changes shape, and the `adopt`
detail changes. The gate-help bug's own body calls `none` "the quiet kind of lie". The belt counts
`none` as answered (`changelog.py:92-97`), so the release note would say nothing about any of the
three. **Fix:** clear each with `pm set <bug> changelog ""`, and add an AC that the sentence is
written at close.

**M8 MAJOR, nothing owns the milestone's 0.4.0 → 0.8.0 walk.** Story 1's AC3 and AC5 would reach
the network through `uvx --from git+…@<pin>`. That runs the old, pinned code, and 0.8.0 is not
tagged yet. **Fix:** AC3 sets `DEVKIT=` to point at the checkout; `Makefile.devkit:17-23` already
supports that. The handoff assigns the full walk to the milestone review or to release.

## Minors and nits

- **m1** (#30 AC1): ledger `status` rows carry `grain`, not the kind. The kind has to be resolved
  through the grain index, and a row whose grain is absent should be skipped and counted. The
  sentence at `skills.py:252`, "a flow you are not running", goes too.
- **m2** (#26 AC1): "paragraph" is not defined. `non_fenced_lines` drops fences, so a naive join
  crosses fence gaps, headings, list items and table rows. Break on each of those, and on
  non-consecutive line numbers.
- **m3** (#19): no `pm` verb removes a field, and the check is for presence
  (`checks/pm.py:1016-1018`). The finding's hint should therefore say "delete the line by hand".
  Consider a counted line instead of a WARN that can never be silenced for a deliberate omission.
- **m4** (story 1 AC4): `_roster()` returns `()` when `[checks] all` is not declared
  (`dispatch.py:202-214`), so a stock consumer gets no STATIC GATES line at all. The stock default
  lives in `cli.py` `KNOWN_GATES`, and `repo/` cannot import it. The AC has to cover this case.
- **m5**: `sdlc` needs to be added to `.PHONY` (`Makefile.devkit:74-75`).
- **m6**: story 1 has `depends_on: []`, but it rewrites strings in every file phase B touches.
  Encode that dependency.
- **n1**: `st-check-doc…` swaps two citations. At HEAD the make-target rule is `doc.py:132-141` and
  the path rule is `:145-160`.
- **n2**: there is no `tests/test_check_pm*.py`. The check pm tests are `tests/test_pm_gate.py`.
  The process case for the vehicle should amend `tests/test_makefile_gates.py`.
