## Findings

**M1 (MAJOR) — `pm/cli.py:1174` + `:1178-1184`: a flag-shaped argument to the backfill write is
taken as data, so `--dry-run` there files a real row.** `_take_flags` takes the next word as the
flag's value, whatever it is. `version_defect` accepts `--dry-run`, and a summary word is anything
left over. Three inputs:
- `pm retire gone --version --dry-run --name X` exits 0 and appends
  `{"version":"--dry-run","name":"X","backfilled":true}`.
- `--version 1 --name --dry-run` exits 0 and writes name `--dry-run`.
- `--version 2 --name Y --dryrun`, a typo, exits 0 and writes summary `--dryrun`.

The operator asked for a dry run and got a permanent row in an append-only ledger. A correction
can supersede that row but cannot remove it. **Fix:** in `cmd_retire`, after `_take_flags`,
refuse at exit 2 and write nothing when any pair value, or any word other than `--dry-run`,
starts with `-`. Name the three flags the verb takes. This is `cmd_decide`'s guard. Add the three
argvs above as rows in `Retire.BACKFILL_REFUSED`. The shared loop also closes Q17. If you would
rather not change the normal path in this range, guard `_backfill_retire` alone.

**M2 (MAJOR) — `pm/cli.py:2108`: `pm new bug 0.1 x --name 'The Title'` exits 0 and writes
`name: --name The Title`.** `--name=The Title` writes `name: --name=The Title`. At `d62daed` the
same argv exited 2 and wrote nothing. #24 names this spelling as the one three consumer docs
carried, so the feature has turned a dead end into a wrong write with exit 0. **Fix:** refuse at
exit 2 when `rest[2]` starts with `-`, naming the positional form
`pm new bug <milestone> <slug> <name...>` (the `:2230` guard). Add a row to
`test_a_flag_that_carries_no_id_refuses_and_never_eats_the_slug`. `new feature … --name T` has
the same hole, predating the range. It belongs to Q16's bug.

**M3 (MINOR) — `pm/cli.py:1084`: the in-tree guard matches the id exactly, so a near-miss of an
in-tree id is backfilled at exit 0.** With `ms-foo` in the tree, each of `MS-FOO`, `Ms-Foo`,
`foo`, `ms-foo.md` and `ms-foo`+U+200B prints `[dry-run] would backfill a retire row for …`. The
line does say "on no plan", and `pm roadmap` cannot be fooled, because it reads the grain first.
But a typo leaves an orphan row that can never be removed. **Fix:** also refuse, naming the
in-tree id, when the argument matches one after casefolding, stripping a `.md` suffix and
dropping format (Cf) characters, or when adding a kind prefix (`<prefix>-<mid>`) makes it one.

**M4 (MINOR) — `pm/cli.py:3409`, comment `:3343-3345`: a help flag anywhere now drops a write at
exit 0.** At `d62daed`, `pm decide 0.1/alpha drop the -h alias` recorded D1 at exit 0, and
`pm new feature 0.1 hflag make --help answer` created the feature. Now both print usage, exit 0
and write nothing. A script that checks the exit code reads success. The comment says a
flag-shaped title "is already refused", but `cmd_decide` refuses only a title whose first word
starts with `--`. **Fix:** exit 0 only when the flag is `argv[1]`. Later in argv, print the
verb's block to stderr and exit 2 with "read as a help flag, nothing was written; quote the words
to use it as text". The write is still never reached. This amends criterion 1's "anywhere … exits
0" to "anywhere … never writes", which is the orchestrator's call. Either way, correct the comment.

**M5 (MINOR) — `tests/test_pm_verbs.py:1863-1881`: the backfill re-enumerates the version
grammar's refusal matrix.** `MALFORMED` and its two generator rows re-prove `driver.version_defect`
with 26 subtests. `tests/test_conveyor_driver.py:310-316` already enumerates that grammar. SDLC
§5 (amended 2026-09-05): *a surface that REUSES a grammar proves that it reuses it with one case.
Inventing one is a finding.* **Fix:** keep one malformed id (`a/b`) and one malformed version
(`a b`), and drop `MALFORMED`.

**M6 (MINOR) — `pm/cli.py:2130-2131` + `:2142`: with a template that has a `{name}` slot and no
name given, the literal `{name}` is left in and the `next:` line says the opposite.** Probe
template line `name: "{name}"`. `pm new bug 0.1 slotq0` writes `name: "{name}"` and `# {name}`,
then prints ``next: `pm set bg-slotq0 name '<name>'` — `name:` is empty``. `validate` exits 0.
**Fix:** always set `values[FIELD_NAME] = name`, empty or not, so the slot renders to what the
line says.

**N7 (NIT) — `pm/cli.py:2108`: the bug name's whitespace is not collapsed.** A name of `'   '`
stamps `name:    ` with trailing spaces and prints no `next:`. A tab is stamped raw into a field
that `pm list` prints as a column. Collapse it as `_backfill_retire` does:
`' '.join(' '.join(rest[2:]).split())`.

**N8 (NIT) — `pm/cli.py:1081`: the backfill ID is checked against the VERSION grammar.**
- `pm retire a:b --version 0.0.9 --name Colon` exits 0, and `pm roadmap` prints the row. But
  `pm add roadmap a:b` then says the id "carries a character no id may hold".
- A 150-character id, which is legal (`ID_MAX` 200), is refused as "the version is too long".

Use `inventory.id_defect(mid)` plus a refusal of `/`. That also removes the deferred import from
`pm` into `conveyor.driver`.

**N9 (NIT) — `pm/cli.py:1085-1092`: an in-tree id of another kind is told to use a command that
refuses.** `retire roadmap --version 9.9.9 --name P` exits 2 and advises
`agentic-sdlc pm retire roadmap [<summary...>]`, which then says "'roadmap' is not a milestone".
Branch on `held.kind`.

**N10 (NIT) — the same defect gets two exit codes.** A multi-line `--name` on the backfill is
`Usage`, exit 2 (`:1111`). A multi-line `<name...>` on `new bug` is `Refused`, exit 1 (`:2112`),
which matches `pm set` and `decide`. Pick one.

**N11 (NIT) — `tests/test_pm_verbs.py:1432`: the help case's per-verb oracle is weak.** The plant
where `_help_for` returns all of `USAGE` passes all 72 subtests. Only the `new bug` narrowing
assertion went red. Add `assertLess(len(out.splitlines()), len(cli.USAGE.splitlines()))` to each
subtest.

**N12 (NIT) — SDLC §6: `EveryVerbAnswersItsOwnHelp` is a new class.** It does not say why
`tests/test_cli_surface.py:297` `help_surfaces()` could not take the `pm <verb> --help` rows. That
census was "widened rather than duplicated" for this exact claim.

**N13 (NIT) — `conveyor/driver.py:450`: the writing belts' help lost "(or nothing to write)".**
It now says `0 written`. But `close story` on a story that is already done exits 0 through
`pm story done`'s `(no-op)`. Restore the parenthetical.

**N14 (NIT) — the roster dump survives on the arity path.** `pm set` with no arguments, and
`pm retire --version 3 --name Zed` with no id, still print `ERROR — usage:` plus 509 lines at
exit 2. `pm help set` prints the whole roster. `_help_for(verb, ())` now exists to answer all
three.

**N15 (NIT, DELTA) — the docs are behind the code.** `README.md:124` (the `pm retire` row) and
`pm/guidance/pm-operations.md:198-213`, the skill a consumer's LLM reads, name neither the
backfill form nor `new bug <name...>`. A consumer with 27 pruned milestones would never learn of
`--version/--name` (rule 11). `changelog:` is empty on the feature and on all three stories, and
this is a minor bump.

**Q16 (QUESTION) — do you want this filed as its own bug on 0.8.0?** It predates the range (it
reproduces at `d62daed`), so it does not hold this close, but it is a rule-4 sin.
`pm new feature|story|milestone … $'x\nstatus: done'` injects a frontmatter line, and `pm get
ft-inj status` then answers `done` for a grain created a second earlier. The new bug branch fixed
this for bugs only (`:2110-2113`). The same one-line guard, plus M2's flag guard, belongs on the
three other scaffolds.

**Q17 (QUESTION) — do you want this filed as its own bug?** It predates the range.
`pm retire 0.1 --dryrun`, a typo, is read as a summary word and REALLY retires: "3 file(s)
removed". M1's shared-loop fix closes it. If you want the normal path left alone in this range,
it needs its own bug.
