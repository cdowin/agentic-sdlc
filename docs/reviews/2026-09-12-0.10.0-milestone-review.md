# 0.10.0 — milestone review: the ledger is a stamp

Range `6b33acf..0399197`. This record covers the seams between the seven lanes. The findings on
single features are in `2026-09-12-0.10.0-features.md` (F1 and F2, both MAJOR, count against
release here as well). Probes ran in a scratch `git archive` copy.

**Verdict: RELEASE-WITH-FIXES.** The milestone criterion holds except where two lanes meet: the
twin join (features F2), and gate cost. Gate rows that one lane claimed for the milestone are
printed by no table after another lane removed the milestone's gate table.

## Blockers

- **R1 MAJOR** `src/agentic_sdlc/repo/pm/report.py:1262-1273` + `:1108-1152`: after ft-a-milestone-
  reports-only-its-own-rows, a gate row stamped with a milestone's `branch:` belongs to that
  milestone. After ft-the-report-is-the-stamp-table, the milestone report prints no gate table and
  `--tree` excludes owned rows. So **gate cost for every run on a milestone branch, which under
  SDLC.md is nearly every run, appears in no table.** The only trace is a `gate N` count. Probe: the
  scratch 0.10.0 report says `gate 7, test 35` owned. `report --tree` by branch reads
  `- 5332, main 1`, and none of the 42 appears in its gate table. The `--tree` heading ("N gate
  row(s)") reads as the whole corpus. CLAUDE.md rule 11 now sends operators to "`--tree` for gate
  cost", so this is rule 11's absence shape. **Fix, cheapest first:** a counted line under the tree
  gate table (`N gate row(s) on a milestone's branch — in no gate table`). Better: make `--tree`'s
  gate table read every gate row, since ft-the-report already scopes gate cost to the tree and not
  to a milestone. Either way, add a planted case.

## Also recorded

- **R2 MINOR** `src/agentic_sdlc/repo/pm/ledger.py:482` vs `report.py:954`: the two lanes each
  wrote a `stamp_units`, and they disagree. `show` closes the LATEST open start (LIFO) and prints a
  lone stop as a unit. `report` closes the EARLIEST (FIFO) and counts a lone stop as unpaired. The
  CLI refuses a second open start, so only a `merge=union` of two worktrees reaches this, and that
  is the flow 0.10.0 introduced. `report.py:82-89` also redeclares `branch`, `stamp`, `issue` and
  `outcome` instead of importing `ledger`'s constants. `row_names` (`ledger.py:894`) re-implements
  the one-story rule from `named_grains`. By reading, not probed. **Fix:** one pairing, in `ledger`.
- **R3 MINOR** `src/agentic_sdlc/repo/dispatch.py:306-321`: the `GDK-STAMP` line takes its issues
  from an `issue:` frontmatter field. That field is in no template, README row or guidance, and no
  0.10.0 grain declares it, so every unit in the milestone's own report prints issue `-`. Rule 11:
  name the field in the README's `dispatch` row and in the grain templates.
- **R4 MINOR** `src/agentic_sdlc/repo/dispatch.py:332-333` (the parallel preamble renders it too):
  every dispatch still tells the leader to `export GDK_LEDGER_GRAIN=<gid>`. In the courier
  (`cc-ledger-subagent.sh:329`), the env var outranks the transcript's stamp line. So a leader
  session started with it exported would file every concurrent builder under one grain, and
  ft-a-concurrent's criterion is "with no environment variable exported". It is latent today
  because of R5. **Fix:** on SubagentStop, rank the transcript's own stamp above the session
  env, and drop the export line when a stamp is rendered.
- **R5 WARNING** (pre-existing since 0.8.0 `188c831`, outside this range)
  `tools/hooks/cc-ledger-subagent.sh:55-58` with `Makefile.devkit:100`: `env_arg` passes
  `"$$GDK_LEDGER_GRAIN"` through `ARGS`, and the `pm` target inserts it with `$(value ARGS)`, so
  the shell sees `$$` (its PID). Probe: `GDK_LEDGER_GRAIN=ms-the-ledger-is-a-stamp` plus a
  SubagentStop payload gives `ERROR — no grain resolves from id '20530GDK_LEDGER_GRAIN'`, exit 2,
  no row. When the variable is exported, the courier writes nothing, yet the courier header
  (edited in this range) and install's next-step tell consumers to export it. `GDK_LEDGER_ROOT`
  goes through the same `env_arg` (not probed). **File as a bug**; its fix makes R4 live.
- **R6 NIT** `src/agentic_sdlc/repo/installables/cc-stop-gate.sh:88-107`: the trunk session's every
  Stop now spawns `make -s sdlc ARGS="check pm"`. That is correct, but it is a per-stop cost that no
  `verify --plan` row shows. It has no `--self-test` corpus like the other guards (it prints "payload
  is not JSON"). Its cases live in `test_hooks_payloads.py:179-230`.
