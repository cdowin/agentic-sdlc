## Blockers

- **M1 MAJOR** `src/agentic_sdlc/repo/installables/project-devkit.toml:211`. The consumer seed still
  says the dispatch is attributed by the export: `"this dispatch's spend, when GDK_LEDGER_GRAIN=<id> is
  exported before it"`. That is pattern 11, verbatim, in an installable. **Fix:**
  `"this dispatch's spend, attributed by its \`dispatch --grain\` GDK-STAMP line"`. No test pins the
  old text.
- **M2 MAJOR** `README.md:131` (the `pm ledger` row). It gives the grain resolution order as
  `--grain (the couriers pass GDK_LEDGER_GRAIN … — you export it; nothing here does), else from the one
  story in progress, else not at all`. The stamp is missing, so the export reads as the way to
  attribute, in the row an operator reads to learn attribution. **Fix:** `… from --grain (a session's
  GDK_LEDGER_GRAIN, which you export), else the prompt's GDK-STAMP line, else the one story in
  progress, else not at all`. That order is the same one `cc-ledger-subagent.sh:17-21` states.

  "A dispatch names the narrow command as the loop; the wide one is the orchestrator's, at the close,
  and a builder never runs it."
