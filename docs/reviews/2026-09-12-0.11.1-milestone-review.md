# 0.11.1 milestone review: the host stays a checkout (bb81f46)

**Verdict: RELEASE-WITH-FIXES.** Three false ALLOWs are MAJOR and hold the close. All three
were BLOCKED by the pre-fix hooks (`bb81f46^`) and are ALLOWED after the fix. One of them sets
`core.bare = true`, which is the bug itself.

Method: 60 hostile payloads piped through `tools/hooks/cc-git-allowlist.sh` and
`cc-commit-pathspec.sh` under `/bin/bash` 3.2. Each regression was replayed against the
`bb81f46^` copies. Real git effects were checked on a scratch repo with a linked worktree, driven
only by `git -C <scratch>`. `--self-test`: 48 blocked, 51 allowed, OK.

## Blockers

- **M1 MAJOR** `tools/hooks/cc-git-allowlist.sh` `checkouts(cwd)` and `cc-commit-pathspec.sh`
  `outside_repo`: "this repository" is taken from the payload `cwd`, and a `cd` in an earlier
  call moves it. With the session sitting in a scratch repo, `git -C /Users/cdowin/workspace/agentic-sdlc reset --hard`
  is ALLOWED, and so are `stash`, `init` and `commit -am sweep`. With cwd `/tmp`,
  `git -C <repo>/.claude/worktrees/x init` is ALLOWED, because of `or not checkouts(cwd)` in
  `init()`. Fix: anchor on the hook's own checkout (`$0`/`CLAUDE_PROJECT_DIR`) as well as the
  cwd's, and never allow because no roots were found.
- **M2 MAJOR** `git_call`/`outside()`: the `-C` exemption skips `--git-dir`, `--work-tree` and
  `GIT_DIR=`/`GIT_WORK_TREE=` without reading them. Both `GIT_DIR=<repo>/.git/worktrees/x git init -q /tmp/zz`
  and `git -C /tmp --git-dir=<repo>/.git --work-tree=<repo> reset --hard` (or `commit -am`) are
  ALLOWED. On scratch, `GIT_DIR=S/.git/worktrees/W git init -q /elsewhere` set
  `core.bare = true` in S's shared config. Fix: any of these, as a flag or an assignment, removes
  the exemption.
- **M3 MAJOR** `outside()` joins a relative `-C` onto the payload cwd and ignores a `cd` or
  `pushd` in the same command. `cd src && git -C .. reset --hard` is ALLOWED, and so are
  `cd .claude && git -C .. init` and `cd src && git -C .. commit -am sweep` (pathspec hook). Fix:
  only an absolute or `~` `-C` path, or init target, can earn the exemption. The scratch recipe
  already uses absolute paths.
- m4 MINOR: a symlink created in the same command, as in `ln -s <repo> /tmp/l && git -C /tmp/l reset --hard`,
  resolves at hook time to a path that does not exist yet, so it counts as outside. This takes
  deliberate evasion rather than a mistake.
- m5 MINOR: `archive` is allowed in every form, so `git archive -o <repo>/.git/config HEAD`
  writes into the repo. A shell redirect can do the same thing and the guard never read
  redirects. Still, `-o/--output` could require an outside path.

These held, and were BLOCKED: a pre-existing symlink into the repo, `~` and `~user`, `$HOME`
(unknowable), `-C <repo>/.. -C agentic-sdlc`, `-C /tmp -C <abs repo>`, `init <inside path>` after
an outside `-C`, and every targetless or inside `init` from a real linked worktree (including
`-C S/.git`, `--git-dir=S/.git init` and `init --bare S/.git`). `/tmp/..` chains resolve
physically, the same way chdir does, so they do not reach the repo.
