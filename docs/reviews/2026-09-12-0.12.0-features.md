## ft-the-guard-lets-the-leader-keep-house

**Blockers**
- M1 MAJOR `src/agentic_sdlc/repo/installables/cc-git-allowlist.sh:658` (same in `tools/hooks/`):
  `branch()` compares long options by exact string, but git accepts any unique prefix. So
  `git branch -d --forc feat/x` gets through the hook with exit 0, and in the scratch clone it
  deleted a branch whose commit was merged nowhere (`Deleted branch feat/x`, rc 0). At `10249c7` the
  same payload was blocked, because every `-d` was refused. The same class hits
  `git symbolic-ref --del refs/remotes/origin/HEAD` (`:697`), which was blocked before and now
  passes and deletes the ref. **Fix:** expand each long option to its unique prefix against the
  verb's table before judging, or refuse any long option that is not on an allowlist, as `switch()`
  already does with `SWITCH_LONG`. Add corpus rows for `-d --forc` and `--del`.
- M2 MAJOR `tools/hooks/cc-git-allowlist.sh:32`: this repo's header still has `switch` in
  `ALLOW_SUBCOMMANDS`, and that skips the new judge. With the armed guard,
  `git switch --discard-changes main`, `-f`, `-C feat/x`, `--orphan x`,
  `GIT_DIR=/r/.git git -C /tmp/x switch -f main` and `git -C ../agentic-sdlc switch -f main` all
  exit 0. The stock hook gives 2 for each. The widening existed for the leader's `switch main`
  (0.11.1), which stock now allows. It was raised from MINOR because this is the tree where
  parallel lanes run, and discarding a peer's edits is exactly the loss this guard exists to stop.
  **Fix:** drop `switch` from the header, and reverse the feature's "The header keeps `switch`"
  with `pm decide`.

**Below the line**
- m3 MINOR `cc-git-allowlist.sh:626`: `merge --ff-only --autostash origin/main` passes, but `pull`
  refuses `--autostash`. An autostash sweeps every uncommitted edit, a peer's included, into the
  shared `refs/stash`. Add `--autostash` to the `ff_only` exclusions.
- m4 MINOR `agent-worktree.sh:329-351`: `branch -D` runs after `worktree remove`, so the merge
  proof is stale by the time the branch is deleted. A commit landing in that window would be
  dropped. `git update-ref -d refs/heads/<branch> <proven-sha>` deletes only if the branch has not
  moved. Nothing else found: with `$base` or `$FALLBACK_BASE` unknown, `is-ancestor` fails and the
  branch is kept.
- S5 SUGGESTION: these holes predate this range and are the same class as M1.
  `git commit --am` amends (verified in scratch), `git push --force-w` passes the hook, and
  `fetch` is allowed wholesale, so `pull --ff-only --refmap=+refs/heads/*:refs/heads/*` can
  force-move a local branch. One option normalizer closes all of them.
- N6 NIT: `git branch -d main` and `git branch -d milestone/<x>` pass. git's own merged check keeps
  the work, so there is no loss.
