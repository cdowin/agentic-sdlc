## Findings

- **m1 MINOR** `src/agentic_sdlc/repo/pm/report.py:724-739` — `join_twins` folds EVERY hand row naming an
  `agent_id` into the one courier row. So two hand records for one agent (for example a retried
  `ledger record`) print `2 courier/hand pair(s) joined` for one pair, and the earlier hand row's grain is
  silently replaced by the later one's. Probe: `join_twins([courier A, hand A st-x, hand A st-y])` returned
  1 row, `joined 2`, grain `st-y`. Fix: join at most one hand row per courier. A second hand row naming the
  same id stays unjoined and counted, which is the rule-9-safe answer.
- **N1 NIT** `src/agentic_sdlc/repo/pm/cli.py:342` — the flag list in the `ledger record` synopsis does not
  include `[--agent-id X]`. Only the parenthetical note names it (rule 11).
- **N2 NIT** `tests/test_dispatch.py:179` — this asserts a string inside `pm/guidance/pm-execution.md`
  prose. A doc-content check sitting in the dispatch test module.
- **Q1 QUESTION** — the join assumes that "the id the Agent tool returned" is byte-equal to the courier
  row's `agent_id` (the SubagentStop payload or the transcript's `agentId`). The test builds both sides by
  hand, and no fixture pairs a real Agent-tool return with a real courier row. Not verified.
