## Findings

- **M1 MAJOR** `src/agentic_sdlc/repo/install.py:218-231`. Stdout holds two `# why` + `gh api … --input -` + JSON
  blocks. You cannot pipe it, and you cannot paste it. The probe `install-ci --ruleset | python3 -c 'json.load(sys.stdin)'` gives
  JSONDecodeError. If you paste it, gh reads the rest of the paste as stdin, and that includes the second block. The test
  itself hand-splits on the gh line (`tests/test_install.py:454`), which proves the point. Rule 11: "composition is the
  shell's job". Fix, preferred: `--ruleset branch|tag`, where each call prints ONE bare JSON document, so
  `agentic-sdlc install-ci --ruleset branch | gh api -X POST repos/O/R/rulesets --input -` works. Move the why and the
  gh line into `--help`. Cheaper alternative: keep one stdout, but emit `gh api … --input - <<'JSON'` … `JSON` so the whole
  output is a runnable script. This is MAJOR, not MINOR, because the shape freezes when 0.16.0 ships.
- **S1 SUGGESTION** `src/agentic_sdlc/repo/installables/ci-verify.yml:16-19`. With `push: main` dropped and
  `strict_required_status_checks_policy: false`, nothing verifies the merge commit that auto-tag tags. This matters when main
  moved after the PR's run. This is by design (#82); say it in the header or in SDLC.md.
- **N1 NIT** `install.py:185-191`. The live `protected-main` also has `require_extra_approval_for_unattributed_changes: true` and
  `required_reviewers: []`. The payload omits both. They are probably server defaults. This pass did not verify that by a POST.
- **N2 NIT** `install.py:141,1474`. `RULESET_COMMANDS` is a one-element tuple and it has one reader. Inline `command == 'install-ci'`.

Push-trigger readers: none. `ci-auto-tag.yml` has its own `push:` and no `workflow_run` on verify. There is no README badge.
Nothing in `tests/` reads verify's `push` (grep). The installed `.github/workflows/verify.yml` is byte-equal to the template from `name:` down.
