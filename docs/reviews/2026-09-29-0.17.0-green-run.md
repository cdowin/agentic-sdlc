# Lane review — ft-a-green-run-is-bought-once (0.17.0), range fbf64bb..1e73656

**Verdict: SHIP.** Nothing at MAJOR or above. The story-rung digest leaves out only frontmatter `status:` lines under the roadmap and five move-kind ledger rows. It says so on every reuse line (`State.where`). A `src/` edit and a `changelog:` edit between two closes both re-run the rung (test run).

## Findings
- **F1 SHOULD-FIX** `verify/main.py::rung_state`: an unscoped story rung ALWAYS leaves out statuses, and a project cannot turn this off. If a project's `[verify] story` target reads statuses (for example a `make check` or a `check pm` inside `unit`), it reuses a PASS after a status flip, and a hand `pm status` flip counts too. The reuse line discloses this, so the tool does not lie, but the verdict is stale. `[verify.inputs]` is the only way out, and it must list every top-level prefix, which then misses new top-level paths. Fix (small): add one seed/`--help` sentence saying "a story target that reads statuses must be scoped". Or treat an explicit `[verify.inputs] story = ["."]`-style whole-tree value as the opt-out.
- **F2 WARNING** `conveyor/driver.py::_close_stories` `if code == 2: return code`: when a ConfigError hits at id k of n, the run exits 2. Ids 1..k-1 are already written, no tally prints, and ids after k are never tried. Fix: print the tally before the return.
- **F3 NIT** `driver.py::run` line ~381 `verdicts.say`: a shared answer still files one `check.verdict` per id. The ledger then shows N asks of `story-verified` for one run, which inflates `pm ledger report` gate counts.
- **F4 NIT** `installables/pre-push`: `--remotes=<name>` trusts the local remote-tracking refs. Suppose a ref was deleted or force-rewritten on the remote and never pruned here. Its commits then count as pushed and Stage 2 is skipped. A fetch that is stale the other way gates, which is the safe direction.
- **F5 NIT** `verify/cache.py::_without_status` drops EVERY `status:` line inside the frontmatter. A duplicated status key, which `check pm` would flag, therefore does not move the state.
- **S6 SUGGESTION** (lens zero): with the cache fix, `story-verified` already reuses across ids, and `committed` is one `git status`. `GRAIN_BLIND`/`asked_once`/`Shared` (about 60 lines) save one tree hash per id. A plain per-id loop meets the criterion, but the brief mandated asked-once, so this is only recorded.
- **D7 DELTA** the feature's `changelog:` is empty. It needs the consumer-visible sentence: many-id `close story`, pre-push skips pushed commits, and the state tag v4 re-runs every cached rung once after upgrade.

Checked and clean: `required-lines` is not in `GRAIN_BLIND`, so it is asked per id (correct, because it reads the grain). `forward-reconciled` is a release step and is not touched. CRLF keeps its `\r` in the hash (`split_lines` splits on `\n`). A grain outside roadmap_dir, or a failed `vocabulary.load`, is hashed whole (re-runs). Submodules are hashed whole. `--force`/`--skip` apply per id through `run`, and each id files its own deviation row. A refused id does not stop the others. Exit is 1 when any id is refused. `tools/hooks/pre-push` equals its source. The guidance copy differs only in its header.
