# Lane review — 0.18.0 / ft-ci-runs-each-suite-once (4a9b6ea..2de0885)

**Verdict: SHIP-WITH-FIXES.** On this repo each suite runs once and the aggregate check is sound for failure. The stock workflow ships a false green to consumers.

## Findings

- **F1 MAJOR** `installables/ci-verify.yml::python` (step "the story rung on python …"). A leg sets `UV_PYTHON` and runs the consumer's `[verify] story` rung, but nothing proves that the rung ran on that interpreter. A rung that does not go through `uv run` (`python3 -m pytest`, a non-Python toolchain) passes on the runner's default interpreter. The leg is still named `python 3.13`, and the required `matrix` check reports success over interpreters it did not measure (rule 4). In the same run, `verify` skips the consumer's own `matrix` tier, because the skip keys on a tracked pyproject.toml and not on whether the legs replace that tier. Replay: `printf 'unit:\n\t@python3 -c "import sys;print(sys.version_info[:2])"\n' > S/Makefile; UV_PYTHON=3.13 make -C S unit` prints `(3, 14)`. Fix (small): a leg runs the target that it skips, `make matrix PY_MATRIX=${{ matrix.python }}`, where the project's own target carries `--python`. A consumer with no `matrix` target then gets a red "no rule" and not a green leg. Or the leg first asserts `uv run python -c 'import sys; assert sys.version.startswith(...)'`. That is weaker, because it proves uv and not the rung.
- **W2 WARNING** `ci-verify.yml::matrix` `if: ${{ !cancelled() }}`. In a cancelled run the aggregate job is skipped, and GitHub reports a skipped required job as success. If `verify` finished green before the cancel, the PR can merge with its legs not run. Fix (one word): `if: always()`. The `result = success` test then fails on `cancelled`. Not verified on a runner.
- **W3 WARNING** `ci-verify.yml::python` gets none of the toolchain steps that a consumer adds to `verify`, which is where the file says to add them. A consumer with a pyproject.toml whose story rung needs that toolchain gets a red required `matrix` after `install-ci --force`. This is loud, not a lie. Name it in `install.py::_NEXT_STEP` next to the leg-list sentence.
- **M4 MINOR** `installables/Makefile.devkit::gdk-tiers-skipped-milestone`. The skip line goes to the console only. `milestone.log` and its verdict `PASS (check test budget)` name what ran, not what was skipped. A reader of the transcript sees an absent tier with no reason.
- **N5 NIT** `Makefile.tiers::matrix`. Each parallel leg runs `-n auto`, so 3 legs start 3×cores workers. Consider `PYTEST_N` per leg = cores/legs.
- **N6 NIT** `Makefile.tiers` `export UV_PYTHON ?= $(PY_FLOOR)` also pins the developer's `.venv` for `make pm`/`sdlc`. A `.venv` on another interpreter is rebuilt once. This is intended; say so in the comment.
- **N7 NIT** `gdk_gate.sh::gdk_gate_capture`. The claim that `head -c` stdio-buffers holds for GNU/BSD `head` writing to a pipe. Whether this was the 82 s cause is for the first CI run to confirm. The verdict-line shape did not change: `gdk_gate_verdict` is outside the capture (rule 6 held).
