# Lane review — ft-every-rung-reuses-a-green-run (0.18.0), 4a9b6ea..6d629bb

**Verdict: SHIP-WITH-FIXES.** One MAJOR. `release` keeps #87 through the static rung. A bare `verify --milestone` does not keep it.

## Findings
- **F1 MAJOR** `src/agentic_sdlc/repo/verify/main.py::rung_state`. The stock milestone rung is `make milestone`, which is `check` plus the tiers (`Makefile.devkit:207`). `check pm` grades statuses, so by the brief's own opt-out test the stock rung "reads statuses". But the stock key is `true`, so the rung's state leaves out every `status:` line. `release` protects itself with `steps.py::_static_at_done`. A bare `verify --milestone` does not: after a status flip that makes `make check` exit 1, it reuses the old PASS (rule 4, first sin). Replay in a scratch copy, root absolute: flipping `ft-a-bare-host-is-named-at-session-start.md` from `done` to `todo` changes `check pm` from exit 0 to exit 1 (2 violations). `cache.tree_state(root, (), moves_out=True)` is equal before and after the flip. Fix (about 20 lines): move the static ask into verify's milestone reuse path, so a moves-out reuse of the milestone rung runs `make check` now. `release` then inherits the ask, and `_static_at_done` is deleted. Other fix: key the milestone rung whole, with release alone asking the state at `building`.
- **F2 MINOR** `steps.py::commands_for` STATIC branch, `_static_at_done`. No test covers the `[release.commands] static` override or its refusal. Probe: `static = "echo …; exit 3"` resolves. `commands_for('release', names=('version-sync',))` refuses with the right text. Add one case of each to the existing release test.
- **F3 MINOR** `steps.py::_static_at_done`. `DEFAULT_STATIC = 'make check'` assumes that the consumer has a `check` target. A consumer with a custom gate Makefile and no `check` target gets a `release` refusal on reuse only ("No rule to make target"). The same gate passes when it runs fresh. The fix is a sentence in the seed comment, or `verify --check` could hold the target to existing.
- **F4 NIT** `cache.py::_is_grain_doc`. The predicate matches every `.md` under the roadmap, not only grains. It removes a frontmatter `status:` from a shared doc too (for example, `pm/roadmap/releases.md` has frontmatter). The docstring says "grain documents". A `status:` line in a body still counts, as the probe showed.
- **F5 NIT** `cache.py::tree_state` with a relative `root` never matches the roadmap, so the exclusion is silently off. This fails safe (it re-runs). All callers pass an absolute root.
