# Lane review — ft-the-static-gate-takes-seconds (#98), e09a65b e9e6b70

**Verdict: HOLD** — two MAJOR. One is rule 4's first sin, proved by replay: a reused `check doc` PASS over a claim that now FAILs.

## Blockers
- **F1 MAJOR** `repo/checks/doc.py::inputs` vs `::resolve_path`. The key holds the NAMES from `git ls-files --exclude-standard`, but `resolve_path` asks `.exists()`, and `.exists()` also sees gitignored files. So a doc can cite an ignored `.md/.py/.sh` outside the doc scope. When that file is deleted, nothing in the key moves. `../` paths that resolve from the doc's parent to a place outside the tree have the same gap. Replay (scratch clone of HEAD): `echo tools/dev/local-probe.sh >> .git/info/exclude; echo x > tools/dev/local-probe.sh`; add ``See `tools/dev/local-probe.sh`.`` to CLAUDE.md; run `check all` (PASS recorded); `rm tools/dev/local-probe.sh`. Then `check all` prints `[check:doc] PASS … reused — green at …`, and `check doc` prints `FAIL — CLAUDE.md:195 dead path`. Fix (~15 lines + 1 case in `tests/test_check_reuse.py`): salt `facts` with the existence bit of every path claim, or key names on `--ignored` too. MAJOR, not CRITICAL: the trigger is narrow (the doc must cite an ignored file, and the file must then be deleted).
- **F2 MAJOR** `repo/verify/gates.py::Session.gate`. A reuse prints only `found.said`, which is the PASS line, so it drops every WARN line. In the scratch clone, run 1 printed 10 WARN lines and run 2 printed 0. This breaks rule 11: the `check pm` WARN family (a courier that writes nothing, U2/U4, ledger ignore) goes silent on every `make check` that follows. The ledger rows those WARNs read are SELF_FILED kinds, and those kinds are dropped from the key. Fix (~10 lines): do not record a PASS that printed a WARN, or record the WARN lines and print them again.

## Other findings
- **F3 MINOR** `installables/gdk_gate.sh::_gdk_ledger_close` skips the row whenever the mark exists, and `Session.close` creates the mark whenever anything was reused, so the verdict is not checked. A `make check` that reuses 4 gates and FAILs 1 files no `gate` row. That FAIL disappears from `pm ledger report`. Fix: mark only when worst == 0.
- **F4 MINOR** `repo/checks/hooks.py::inputs` and `gates.py::Session.replay`: the facts hold the bash PATH only. They do not hold the bash version or the `python3` that the corpus parses payloads with. `check shell` does key the shellcheck version. Not probed.
- **F5 NIT** `check pm` age text uses `datetime.now()`, but only in WARN text. No FAIL depends on the clock (grep of pm.py). Under F2 that text is dropped anyway.
