# Lane review — ft-the-kit-ships-as-a-locked-wheel (#101, 1.0.0), d8c7bfd + ff42d73 @ 2b7bcb0

**Verdict: SHIP-WITH-FIXES.** No MAJOR or higher. F1-F3 are one-line workflow edits. Land them before the first real tag publishes.

## Findings
- **F1 MINOR** `.github/workflows/release.yml` job `publish`: the first `actions/checkout` persists the `contents: write` token in `.git/config`. `uv build` then runs an unpinned `hatchling` from PyPI with that token on disk. Fix: set `persist-credentials: false` on the tag checkout (the push uses the `site` checkout), or split the build and publish jobs.
- **F2 MINOR** `release.yml` step `actions/checkout ref: gh-pages`: when the branch is absent (the first tag), the step fails with "couldn't find remote ref". The header does not name this case. Loud, not a lie. But 1.0.0's Makefile.devkit refuses every target until the index resolves. Fix: create an orphan `gh-pages` before tagging v1.0.0 and name that in the header, or add a bootstrap step (`git ls-remote --exit-code origin gh-pages` or an orphan init).
- **F3 MINOR** `release.yml` `env.TAG` / `ref: ${{ env.TAG }}`: nothing checks that a dispatched `tag` input is a tag. `ref:` also resolves a branch with that name. A write-access dispatch with `tag=v1.2.3`, run against a branch `v1.2.3` whose pyproject says 1.2.3, passes the `ls` check and publishes an untagged commit as immutable 1.2.3. I did not run this; I reasoned it from the workflow. Fix: `ref: refs/tags/${{ env.TAG }}`.
- **F4 WARNING** grain `changelog:` is empty. These output shapes changed (rule 6): the `init` "Next:" list is renumbered 1-9 with a new step 1; `_span_phrase` gets a new "pins no readable version (...)" text; `pin-bumped` has new lines; remedies change from `uvx --from ...` to `uv run agentic-sdlc ...`. The 1.0.0 line must name the BREAKING move and these shapes.
- **F5 NIT** Two readers decide "the lock names the kit": `Makefile.devkit` uses `grep -x 'name = "agentic-sdlc"'`, and `vehicle.locked_version` uses tomllib. The index URL is spelled in 5 places: `Makefile.devkit`, `vehicle.INDEX_URL`, `project-pyproject.toml`, README and the release.yml header. I did not verify that a test holds them equal.
- **F6 NIT** `steps.migration_steps` step 1 says "no pyproject.toml yet? `uv init --bare` first". That writes `version = "0.1.0"`, which `[pm] version_file`/auto-tag then read by default. `project-pyproject.toml` omits the version line to avoid exactly this. Point to the init seed instead.
- **F7 NIT** `tests/test_makefile_include.py::test_a_consumer_locked_from_a_built_index_runs_the_venv_kit_and_no_uvx` runs `uv build`, which needs `hatchling` from PyPI. With no network and no uv cache, `make test` fails instead of skipping.
- **F8 NIT** `Makefile.devkit` runs `uv sync --frozen` at parse time when the kit is stale, so `make help` and `make -n` also write `.venv`. The file documents this. It is accepted as the cost of "a bumped lock never runs the old kit".
