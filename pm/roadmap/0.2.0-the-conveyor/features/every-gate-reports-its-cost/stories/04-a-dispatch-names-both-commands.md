# The stock agents name the narrow command and the wide one

<!-- What is observable when this ships. A story is an observation, not a task. -->

A consumer runs `agentic-sdlc install-agents` and the roster it gets already carries the rule
that cost 31 minutes to learn: **name the narrow command for the loop and the wide one for
the close**. An agent given one command uses it as its inner loop, because nothing told it
there was another.

Ship criterion 4 of this feature, and the only one whose deliverable is prose. It is
independent of stories 01-03 and can run in parallel with all of them.

## What the rule says, where it goes

The wording is one short block, identical in every file that carries it, stating: the
dispatch names BOTH commands with their measured costs; the narrow one is the inner loop and
the wide one runs once at the close; and where the repo declares `[verify]`, `agentic-sdlc
verify --plan` is what answers *which* narrow command — asked of the repo rather than guessed
by the author.

**Cross-feature coupling, flagged for the orchestrator:** `verify --plan` is
`0.2.0/the-story-belt-knows-what-verifies-this-edit`, same phase. The wording must read
correctly in a repo that has no `[verify]` section — "where the repo declares `[verify]`" —
so this story does not block on that feature landing. Do not invent flags for it beyond
`--plan`, and do not claim it exists unconditionally.

Which files carry it: the roster agents that WRITE or EXECUTE a dispatch — `architect.md`,
`po.md`, `developer.md`, `verification-builder.md`, `test-writer.md`. Not
`changelog-writer.md` / `doc-hygiene.md` / `tech-writer.md` / `pm-operator.md`, whose work is
prose sync against a known diff and has no verification inner loop; a rule pasted where it
does not apply is the noise that gets the whole block deleted.

## Files it must stay out of

`SDLC.md` and `README.md` — SDLC.md §2 puts shared-doc wording in the report as **PROPOSED**
text for the orchestrator to apply, and §4 of it already says builders run scoped slices;
whether that section grows a pointer is the orchestrator's edit, not this story's.
`CHANGELOG.md` likewise. Also out: everything under `src/agentic_sdlc/repo/pm/`,
`src/agentic_sdlc/repo/installables/*.sh`, `Makefile.devkit`, `pm/roadmap/`.

## Acceptance criteria

1. Each of the five named installables carries the block, and the five copies are
   byte-identical to one another. Proven by an assertion in `tests/test_install.py` that
   extracts the block from each and compares — five hand-maintained near-copies drift, and a
   test comparing them is what keeps the wording one wording.
2. `.claude/agents/verification-builder.md` and `verification-reviewer.md` are byte-current
   with their installable sources. Proven by the existing byte-current test in
   `tests/test_install.py`, unmodified.
3. The edited files pass `check doc` **in a fresh consumer**, not just here. Proven by the
   existing `tests/test_install.py` case that installs into a temp repo and runs the gate.
   CLAUDE.md: *"a contract that reddens the gates it arrives beside gets deleted by the first
   person who runs them."*
4. `agentic-sdlc check doc` over this repo's own tree exits 0 — the installables are scanned
   here too. Verify with `PYTHONPATH=src python3 -m agentic_sdlc.cli check doc`.
5. **Hard rule 8.** No file names a consuming project, a repo, a tag, or a path outside this
   checkout. The measured numbers (154 s / 0.9 s / 170x / 31 minutes) are quoted as a
   worked example of a SHAPE, with no repo attached. Proven by
   `tests/test_consumer_independence.py` passing unmodified.
6. Slice command for the loop: `python3 -m pytest tests/test_install.py -q`.

## Out of scope

- Any Python. This story ships prose in five markdown files and a re-install.
- `model:` / `effort:` frontmatter changes — SDLC.md §3 owns that table and flags `effort:`
  as UNVERIFIED; nothing here touches it.
- Adding a new agent to the roster.
- Editing `project-CLAUDE.md`, which is the consumer's own file rather than an agent
  definition.
